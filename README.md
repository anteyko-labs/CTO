# Avtodom

Учётная система для пункта замены масла и магазина автомасел: касса, склад, расчёт сотрудников и ежедневная прибыль в одном месте.

## Какую боль решаем

Владелец точки сегодня не видит в конце дня честной картины: сколько продано, сколько это стоило в закупке, сколько ушло мастерам и на расходы, сколько осталось в кассе и кто сколько должен. Масло продаётся и канистрами, и на розлив, из-за чего остатки расходятся. Долги ведутся в тетради.

## Что делает система

- **Склад** — приём товара по штрихкоду, печать своих этикеток, остатки масла в литрах и канистрах, себестоимость по средней, сигналы «заканчивается» и «залежалось».
- **Касса** — продажа на вынос или с заменой в сервисе, выбор кассира и мастера, оплата наличными, картой, переводом или в долг.
- **Сотрудники** — начисление за каждую замену, ежедневный расчёт и выдача из кассы.
- **Деньги** — операционные расходы, сдача кассы, чистая прибыль за день и по категориям.
- **Клиенты** — контакты, долги с документами, электронная масляная книжка автомобиля.

## Для кого

| Роль | Что делает |
| --- | --- |
| Владелец | Видит всё: прибыль, себестоимость, зарплаты, долги. Управляет ценами, сотрудниками, переливом масла. Работает в том числе с телефона. |
| Администратор | Ведёт кассу и склад: продажи, приём товара, клиенты, долги, сдача кассы. Прибыль и доходы магазина не видит. |

Мастера и кассиры как пользователи в систему не входят: они заведены в справочнике сотрудников и выбираются в чеке.

## Разработка

Нужны: Rust stable, Node.js 22, PostgreSQL 16.

После клонирования включить проверки репозитория:

```sh
git config core.hooksPath .githooks
```

Хуки проверяют сообщения коммитов, не пропускают файлы окружения и секреты, а для Rust-кода запускают `cargo fmt --check` и `cargo clippy`.

### Сервер

```sh
cd server
echo "DATABASE_URL=postgres://postgres:ПАРОЛЬ@localhost:5432/avtodom" > .env
createdb avtodom
BOOTSTRAP_OWNER_LOGIN=owner BOOTSTRAP_OWNER_PASSWORD=пароль-владельца cargo run
```

Миграции применяются при старте. Владелец создаётся, только если в базе нет пользователей. API — `http://127.0.0.1:8080/api/v1`.

Тесты (каждый тест создаёт временную базу): `cargo test`. После изменения SQL-запросов обновить данные для сборки без базы: `cargo sqlx prepare -- --all-targets`.

### Клиент

```sh
cd web
npm install
npm run dev      # http://localhost:5173, запросы /api проксируются на сервер
npm test
npm run build    # сборка в web/dist, её раздаёт сервер
```

Сквозные тесты в браузере: собрать клиент, запустить сервер с владельцем `owner` / `owner-pass-1` и выполнить `npm run e2e` (с установленным Edge вместо скачанного Chromium — `E2E_CHANNEL=msedge npm run e2e`). Тесты создают свои данные с уникальными именами, поэтому их можно запускать на рабочей базе разработчика, но не на базе точки.

На каждый push GitHub Actions запускает все проверки сервера, клиента и сквозные тесты (`.github/workflows/ci.yml`).

## Развёртывание

```sh
cd deploy
cp .env.example .env   # заполнить домен, пароль базы, первого владельца
docker compose up -d --build
```

Поднимаются PostgreSQL, приложение, Caddy (HTTPS) и ежедневная резервная копия в `deploy/backups/`. Копии нужно регулярно переносить за пределы сервера.
