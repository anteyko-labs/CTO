# SPEC-34. Следующая замена — по каждой услуге в чеке

Решение заказчика 26.10.2026 — ADR-109: «если там услуги — для каждой услуги чтобы спрашивала у кассира след. замену: ниже, после «Пробег сейчас», выбрал из списка услуг, которые он оплачивает, например замену масла, и написал след. пробег, например 225 000; дальше замену антифриза — 250 000 и т. д.». Лимит долга клиента — общий на все филиалы (как сделано в SPEC-33).

## 1. Услуга и строка книжки

- У услуги в справочнике — «Строка книжки»: что она меняет (масло двигателя, масло в коробке, антифриз, тормозная жидкость, масляный / воздушный / салонный / топливный фильтр, прочее) и интервал по умолчанию в км (или милях — по машине) и днях. Добавляются строки книжки «Антифриз» и «Тормозная жидкость» (интервалы по умолчанию — в настройках книжки, владелец правит). Миграция ставит строку услугам по названию (масл+мотор/двигат → масло двигателя; коробк/АКПП/МКПП/трансмис → коробка; антифриз/охлажд → антифриз; тормоз → тормозная жидкость; фильтр + воздуш/салон/топлив/масл → соответствующий фильтр); остальное — «прочее» без напоминания, пока владелец не выберет.

## 2. Касса

- В чеке «В сервис» под полем «Пробег сейчас» — блок «Следующая замена»: по строке на каждую услугу чека со строкой книжки (не «прочее», не доливка на вынос) — «Замена масла в моторе — следующая на пробеге [225 000]». Поле заполнено заранее: пробег сейчас + интервал услуги (у машины свой интервал — он); кассир меняет число или оставляет. Очищенное кассиром поле — «не напоминать по этой услуге». Кнопка «+ ещё строку» — только услуги «прочее» этого чека (ниже, ADR-131).
- Пробег следующей замены не меньше пробега сейчас (иначе подсказка и запрет «Провести»); больше пробега сейчас на 200 000 и больше — подсказка «Следующая замена через N — проверьте» (провести можно). В милях — в милях. Режим кассы: крупные поля, цифровая клавиатура по кнопке (ADR-101), страница не прокручивается.
- Без сети — как остальные данные чека, уходит с чеком. Поле пустое только потому, что пробег не вписан, — цели нет: книжка считает срок по интервалу («не напоминать» — только когда кассир очистил поле сам).

### «+ ещё строку» — только услуги этого чека (ADR-131, 27.10.2026)

«В еще строку должно показываться только услуги которые набрались в этом чеке в сервис, а не все подряд». Сначала «+ ещё» предлагал весь справочник услуг, с 26.10.2026 — товары и услуги чека; товары отменены: при «Замене ГУР» с ATF касса предлагала «Масло в коробке» и писала в книжку замену масла коробки.

- «+ ещё строку» предлагает только услуги «прочее» этого чека, у которых строки ещё нет («Замена ГУР», «Смазка кардана»); товары не предлагаются никогда, справочник — тоже. Нечего предложить — кнопки нет. Жидкость без своей услуги — доливка (ADR-117).
- Строка по услуге «прочее» — с названием услуги, заполнена заранее: пробег сейчас + интервал услуги, если владелец его задал, иначе пустая; пустая строка «+ ещё» не отправляется. Убирается «✕».
- Пример: в чеке «Замена со своим маслом», «Замена ГУР», «Смазка кардана», ATF 1 л, антифриз Sintec, воздушный фильтр — в блоке «Замена со своим маслом [258 000]» и «Масло двигателя — и фильтр: воздушный на тот же пробег»; «+ ещё» — только «Замена ГУР», «Смазка кардана»; выбрали — строка «Замена ГУР [ ] ✕»; клиенту потом — «Замена ГУР — на 150 000 км».
- Удалили услугу из чека — её строка «Следующей замены» и правка кассира уходят (и из черновика, и из отложенного); «Вернуть» в режиме кассы возвращает их.
- «Исправить» переносит в черновик следующие замены, заданные кассиром (и очищенные), и строки «+ ещё».
- Режим кассы: над полем — название услуги в две строки (с переносом), строка книжки и что залито — мелко в углу поля; у «прочего» — только название; окно выбора — крупные кнопки (≥56).

### Уточнение 27.10.2026 (ADR-130): жидкость по названию товара, цели только по чеку

- Товар из категории без строки книжки (и не масло, не фильтр) получает строку по названию: «антифриз», «тосол», «охлажда…» — антифриз; «тормозн…» — тормозная жидкость. Дальше — как товар категории со строкой: без услуги той же строки это доливка (ADR-117). Касса и сервер — одно правило.
- Цель по строке, которой в чеке нет (ни товара, ни услуги), сервер не пишет. С ADR-131 цель — только по услуге этого чека: по услуге не из чека, по доливке на вынос и без услуги (строка по товару кассы до 27.10.2026) цели нет.

## 3. Книжка и напоминания

- Сервер записывает в книжку машины по каждой строке: дата, пробег сейчас, услуга, следующая замена на пробеге N (и дата по интервалу в днях, если задан). Это и есть цель для напоминаний SPEC-32 (по среднему пробегу) — вместо интервала по умолчанию.
- Бот клиента и кабинет показывают в книжке «следующая замена на N» по каждой строке; напоминание называет все строки, срок которых подходит в те же 14 дней («масло — на 225 000, антифриз — на 250 000»).
- Услуга «прочее» с целью кассира (ADR-131) — своя строка книжки у каждой услуги (строка «прочее», текст — название услуги, дата — по дням интервала услуги, если задан), своя следующая замена в книжке, кабинете и боте («Замена ГУР — на 150 000 км») и своё напоминание клиенту; в печатный чек и чек книжки «прочее» не идёт (ADR-116).
- Поле SPEC-29 §23 «Через сколько менять» (убрано в SPEC-30 §13) этим заменяется окончательно; `book_intervals` от старых устройств сервер по-прежнему принимает.

## 4. Печать чека — для масляной книжки

- Уточнение заказчика 26.10.2026: «они и в чеке должны записываться — в чеке для масляной книжки». В печатном чеке «В сервис» (и при повторной печати из «Чеков») — блок «Масляная книжка»: машина и госномер, пробег сейчас, по каждой строке — услуга и «следующая замена на пробеге N» (и «или до ДД.ММ.ГГГГ», если задан срок в днях). Пустые (без напоминания) не печатаются.
- Уточнение 27.10.2026 (ADR-130): после чека книжка печатается только по записи этого чека; записи нет — книжку после чека не печатаем и кнопки «Печать книжки» нет; прошлая замена и «Прошлые замены» после чека не печатаются. Печать из карточки клиента — прежняя (ADR-116). Услуга в товарном чеке — название и сумма одной строкой; «N × цена» второй строкой — только при количестве больше одного, без «усл.».

## Как сделано (26.10.2026)

- Миграция 0064: строки книжки `antifreeze` и `brake_fluid` (у категорий, интервалов машины и строк замен); у услуги — `book_slot` (по умолчанию «прочее»), `book_interval_km`, `book_interval_days` (пусто — по строке книжки); строка поставлена услугам по названию (то же правило — `oil_book::service_slot_by_name`; масло без «мотор/двигат» тоже считается маслом двигателя, как раньше считала книжка). У строки замены (`oil_change_items`) — `service_id`, `target_set`, `next_value` + `next_unit`, `next_km`, `next_date`.
- Интервалы по умолчанию новых строк: антифриз — 60 000 км или 730 дней, тормозная жидкость — 40 000 км или 730 дней (`slot_default`). Владелец правит интервал у услуги (экран «Услуги»: «Строка книжки», «Интервал, км», «или дней»), у категории и у машины. Отдельного экрана «настройки книжки» нет: интервал услуги и есть её настройка.
- Новая услуга без заданной строки получает её по названию (и при загрузке из Excel). Строку и интервал меняет только владелец (403 администратору). `GET /services` и снимок кассы отдают `book_slot` и интервал для кассы (`interval_km`, `interval_days` — заданный или по умолчанию строки).
- Касса (`web/src/lib/nextChange.ts`, `Cashier.tsx`): блок «Следующая замена» (`next-change`) под «Пробег сейчас» — по строке на строку книжки (две услуги одной строки — одна строка). Значение заранее — пробег + интервал машины по этой строке, иначе услуги, в единице машины; правка кассира хранится по строке книжки, переживает отложенный чек и перезагрузку; смена машины сбрасывает правки. «+ ещё строку» — окно с услугами «прочее» этого чека (ниже); добавленная строка убирается «✕». Меньше пробега сейчас — красная подсказка у поля и «Не хватает: следующая замена». В режиме кассы блок во всю ширину левой карточки (`service-left`), поля 56 точек, цифры — экранной клавиатурой.
- Чек: `next_changes: [{service_id, slot, next_mileage}]` в единице пробега чека (без сети — так же, в очереди). Сервер (`oil_book::resolve_target`): услуга — строка этого чека и не доливка на вынос (иначе цели нет, ADR-131), пробег не меньше пробега сейчас — иначе 400; у чека без сети ошибка не отклоняет чек — строка остаётся по интервалу, владелец видит причину (`sale.offline_bypass`). Не больше 20 строк.
- Книжка (`record_from_sale`): услуги со строкой книжки сами дают строку (масло клиента, антифриз…), если товара этой строки в чеке нет; иначе подписывают строку товара. Цель кассира ставится на строку этого чека (её нет — цель не пишется, ADR-130), дата — по дням интервала (машины, услуги, категории, по умолчанию); у услуги «прочее» — своя строка (ниже). Следующая замена строки (`slot_next`) — цель из последней замены этой строки, а без цели — по интервалу, как раньше (интервал услуги теперь тоже учитывается). На этой цели работают напоминания SPEC-32 и SPEC-16, книжка в боте и кабинете (у строки замены — «— следующая замена на 225 000 км»).
- Печать: `SaleOut.book` (`oil_book::sale_book`) — машина, пробег, строки с целью; `salePrint.ts` печатает блок «Масляная книжка» у чека «В сервис» (и при «Печать» в «Чеках»); чек из очереди без сети печатает тот же блок из данных кассы (`receiptBook`).
- `book_intervals` (SPEC-29 §23) сервер по-прежнему принимает.

### Как сделано: «+ ещё строку» — только услуги этого чека (27.10.2026, ADR-131)

- Касса (`web/src/lib/nextChange.ts`): `cartSources` — услуги чека со строкой книжки, каждая один раз (доливка на вынос и товары — нет); `nextRows` — строки по услугам не «прочее» (ключ — строка книжки) и строки «+ ещё» по услугам «прочее» (ключ `svc:<услуга>`, название услуги, заранее — пробег + интервал услуги, если задан); `extraChoices` — услуги «прочее» чека без строки; предложить нечего — кнопки нет, а без строк и предложений нет и самого блока (в режиме кассы остаётся «Мастер рекомендовал»). Товары чека (`cartGoods`) нужны только для «Залито» и приписки о фильтрах с маслом.
- `nextPayload`: строка с числом — `{service_id, slot, next_mileage}`; очищенная кассиром — `next_mileage: null` («не напоминать»); пустая, потому что пробег не вписан (касса без сети), и пустая строка «+ ещё» — не отправляются. `nextTooFar` — подсказка «через N — проверьте» при 200 000 и больше.
- Черновик и отложенный чек: правки по строкам (`nextEdits`) и услуги «+ ещё» (`nextServices`); прежнее поле строк по товарам (`nextExtra`) не берётся. Удалили услугу — её строка и правка уходят (`pruneNext`), «Вернуть» в режиме кассы возвращает их.
- Сервер: `resolve_target` (по `sale_id`) берёт цель только по услуге-строке этого чека, не доливке на вынос; «прочее» — цель с днями интервала услуги. `record_from_sale`: цель «прочего» с пробегом — своя строка `other` (текст и услуга — эта услуга), по одной на услугу; очищенная строки не даёт; цели строк книжки — по одной на строку. Книжка (`books`): у «прочего» с услугой — своя следующая замена (`SlotNext.service_id`, подпись — название услуги), строки из тетради — общие «Прочие работы»; бот «Сейчас в машине» — «Замена ГУР — дата, пробег → следующая на …».
- Напоминания SPEC-32: `SlotDue` с услугой — ключ повода `oil:<клиент>:<машина>:other:<услуга>:<цель>` (у строк книжки ключ прежний), текст — название услуги со строчной («А замена ГУР — на 150 000 км»); главной услуга «прочее» становится, только если других строк в сроке нет: в Телеграме «Не забудьте: замена ГУР на …», в шаблоне WhatsApp текст прежний, «что менять» — название услуги. Напоминания по дням (ADR-063) — отметка `other:<услуга>`, текст «Напоминаем: замена масла, замена ГУР для …».
- «Исправить»: черновик чека (`GET /corrections/draft/sale/{id}`) отдаёт `next_changes` записи книжки чека (`oil_book::sale_targets`: по строке одна, у «прочего» — по услуге, фильтры за маслом — нет); касса (`saleFix.ts`, `nextFromDraft`) ставит их правками и строками «+ ещё».
- Печатный чек: блок «Масляная книжка» — только при жидкостях или следующей замене по ним (у чека с одним «прочим» или фильтром блока нет), так же у чека из очереди.
- Режим кассы: подпись над полем — во всю ширину поля и «✕», название услуги до двух строк с переносом (целиком — в подсказке); строка книжки и что залито — мелко в верхнем углу поля (строка книжки первой), высоту ряда не прибавляют; у «прочего» — только название. Поля 6 rem, «✕» 56 точек: масло и две строки «прочего» с «Мастер рекомендовал» помещаются в один ряд. Приписка под строкой масла — «Масло двигателя — и фильтры: воздушный, салонный на тот же пробег»; «Это замена? Добавьте услугу замены масла двигателя» — без названия услуги (у точки её может не быть). Снимки 1366 × 768 — e2e `next-change-cart.spec.ts` (`next-cart-*.png`).

### Исправлено после проверки (27.10.2026)

- Услуга, добавленная плиткой «ходовое», не давала строки «Следующей замены» (плитка не знала её строку книжки): `GET /settings/favorites` отдаёт у услуги те же поля, что `GET /services`, — `book_slot`, `interval_km`, `interval_days`, а заодно `free_with_oil` и `oil_category_id` (цена «бесплатно с нашим маслом» у плитки — как у «Вида замены», ADR-096). Замена масла плиткой при масле клиента — строка «Масло двигателя», в книжку и печать (`favorites_heatmap_and_compare`, e2e «услуга плиткой «ходовое»» в обеих кассах).
- Интервал категории — только строки этой категории, как в книжке (`slot_next`): у общей категории «Фильтры» (строка — масляный фильтр) интервал владельца не задаёт дату воздушному фильтру из неё — у него интервал категории воздушных фильтров, если есть, иначе по умолчанию строки. Так же, когда у своей категории товара интервала нет, а у другой категории этой строки есть (`oil_book::category_interval` — общий для даты цели и книжки; `next_change_only_by_services_of_this_sale`). Строк по товарам на кассе с ADR-131 нет.
- Режим кассы: «+ ещё» прячет экранную клавиатуру (она ложилась на правые края кнопок окна, касание набирало цифру в «Пробег сейчас»), а клавиатура и «⌨» поля за открытым окном не рисуются вообще; фокус — в поиск товара, скан при открытом окне встаёт в чек за окном (раньше пропадал). Добавленная строка прокручивается в видимую часть карточки замены. Список чека, стоящий внизу, остаётся внизу и после выбора клиента. Плашка «снимок каталога устарел» уходит, как только снимок сохранён (e2e `next-change-cart.spec.ts` «под пальцем», `scanner-focus.spec.ts` «+ ещё строку» в обеих кассах, `offline-queue.spec.ts`).

### Как сделано: чек и книжка в чеке (27.10.2026, ADR-130)

- Строка жидкости по названию товара — `oil_book::slot_by_product_name` (сервер, `record_from_sale`: у категории без строки, `book_slot` «none») и `nameSlot` / `goodSlot` в `web/src/lib/nextChange.ts` (касса: `cartGoods`, а через него «Залито», приписка о фильтрах и чек из очереди). Снимок кассы не менялся: у категорий там уже строка книжки («none»), у товаров — название.
- `record_from_sale`: цель без строки этого чека пропускается всегда (прежняя ветка «строка с названием услуги» убрана).
- Касса (`Cashier.tsx`): книжка после чека запоминается и печатается, только если в ней есть запись этого чека; `oilBookHtml` с `saleId` без своей записи возвращает `null`, `printOilBook` тогда ничего не печатает. Выписка из карточки клиента (без `saleId`) — прежняя.
- `salePrint.ts`: строка услуги (`kind` «service») — название и сумма в одной строке; «N × цена» — только при N > 1.
