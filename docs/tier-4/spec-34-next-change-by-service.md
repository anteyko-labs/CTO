# SPEC-34. Следующая замена — по каждой услуге в чеке

Решение заказчика 26.10.2026 — ADR-109: «если там услуги — для каждой услуги чтобы спрашивала у кассира след. замену: ниже, после «Пробег сейчас», выбрал из списка услуг, которые он оплачивает, например замену масла, и написал след. пробег, например 225 000; дальше замену антифриза — 250 000 и т. д.». Лимит долга клиента — общий на все филиалы (как сделано в SPEC-33).

## 1. Услуга и строка книжки

- У услуги в справочнике — «Строка книжки»: что она меняет (масло двигателя, масло в коробке, антифриз, тормозная жидкость, масляный / воздушный / салонный / топливный фильтр, прочее) и интервал по умолчанию в км (или милях — по машине) и днях. Добавляются строки книжки «Антифриз» и «Тормозная жидкость» (интервалы по умолчанию — в настройках книжки, владелец правит). Миграция ставит строку услугам по названию (масл+мотор/двигат → масло двигателя; коробк/АКПП/МКПП/трансмис → коробка; антифриз/охлажд → антифриз; тормоз → тормозная жидкость; фильтр + воздуш/салон/топлив/масл → соответствующий фильтр); остальное — «прочее» без напоминания, пока владелец не выберет.

## 2. Касса

- В чеке «В сервис» под полем «Пробег сейчас» — блок «Следующая замена»: по строке на каждую услугу чека со строкой книжки — «Замена масла в моторе — следующая на пробеге [225 000]». Поле заполнено заранее: пробег сейчас + интервал услуги (у машины свой интервал — он); кассир меняет число или оставляет. Пустое поле — «не напоминать по этой услуге». Кнопка «+ ещё строку» — выбрать из списка услуг, которых нет в чеке (например, клиент сменил антифриз в другом месте, но хочет напоминание) — по желанию кассира (уточнено ниже: только позиции этого чека).
- Пробег следующей замены не меньше пробега сейчас (иначе подсказка и запрет «Провести»); в милях — в милях. Режим кассы: крупные поля, цифровая клавиатура по кнопке (ADR-101), страница не прокручивается.
- Без сети — как остальные данные чека, уходит с чеком.

### Уточнение заказчика 26.10.2026: «+ ещё строку» — только из этого чека

«+ ещё строку в сервисе — он только что в чеке набирает, должен предлагать, а не все подряд».

- «+ ещё строку» предлагает **только то, что есть в этом чеке** и чего ещё нет в блоке: товары чека, у категории которых есть строка книжки (масло двигателя, масло в коробке, антифриз, тормозная жидкость, масляный / воздушный / салонный / топливный фильтр — `categories.book_slot`), и услуги чека со строкой книжки. Весь справочник услуг больше не предлагается. Нечего предложить — кнопки нет.
- Строка из товара — по строке книжки: подпись «Воздушный фильтр (Фильтр воздушный MANN C-110)», заполнено заранее: пробег сейчас + интервал (у машины свой → у категории товара → по умолчанию строки). Уходит с чеком как цель по строке книжки без услуги (`next_changes: [{slot, next_mileage}]` — сервер это уже принимает); книжка пишет цель в строку замены этого товара.
- Удалили товар или услугу из чека — строка «Следующей замены», добавленная по ним, убирается.
- Подсказка в режиме кассы: крупные кнопки по строкам (≥56), в окне выбора — только позиции чека.

### Уточнение 27.10.2026 (ADR-130): жидкость по названию товара, цели только по чеку

- Товар из категории без строки книжки (и не масло, не фильтр) получает строку по названию: «антифриз», «тосол», «охлажда…» — антифриз; «тормозн…» — тормозная жидкость. Дальше — как товар категории со строкой: без услуги той же строки или цели кассира это доливка (ADR-117). Касса и сервер — одно правило.
- Цель по строке, которой в чеке нет (ни товара, ни услуги), сервер не пишет — и с услугой тоже: запас для кассы до 26.10.2026 снят.

## 3. Книжка и напоминания

- Сервер записывает в книжку машины по каждой строке: дата, пробег сейчас, услуга, следующая замена на пробеге N (и дата по интервалу в днях, если задан). Это и есть цель для напоминаний SPEC-32 (по среднему пробегу) — вместо интервала по умолчанию.
- Бот клиента и кабинет показывают в книжке «следующая замена на N» по каждой строке; напоминание называет все строки, срок которых подходит в те же 14 дней («масло — на 225 000, антифриз — на 250 000»).
- Поле SPEC-29 §23 «Через сколько менять» (убрано в SPEC-30 §13) этим заменяется окончательно; `book_intervals` от старых устройств сервер по-прежнему принимает.

## 4. Печать чека — для масляной книжки

- Уточнение заказчика 26.10.2026: «они и в чеке должны записываться — в чеке для масляной книжки». В печатном чеке «В сервис» (и при повторной печати из «Чеков») — блок «Масляная книжка»: машина и госномер, пробег сейчас, по каждой строке — услуга и «следующая замена на пробеге N» (и «или до ДД.ММ.ГГГГ», если задан срок в днях). Пустые (без напоминания) не печатаются.
- Уточнение 27.10.2026 (ADR-130): после чека книжка печатается только по записи этого чека; записи нет — книжку после чека не печатаем и кнопки «Печать книжки» нет; прошлая замена и «Прошлые замены» после чека не печатаются. Печать из карточки клиента — прежняя (ADR-116). Услуга в товарном чеке — название и сумма одной строкой; «N × цена» второй строкой — только при количестве больше одного, без «усл.».

## Как сделано (26.10.2026)

- Миграция 0064: строки книжки `antifreeze` и `brake_fluid` (у категорий, интервалов машины и строк замен); у услуги — `book_slot` (по умолчанию «прочее»), `book_interval_km`, `book_interval_days` (пусто — по строке книжки); строка поставлена услугам по названию (то же правило — `oil_book::service_slot_by_name`; масло без «мотор/двигат» тоже считается маслом двигателя, как раньше считала книжка). У строки замены (`oil_change_items`) — `service_id`, `target_set`, `next_value` + `next_unit`, `next_km`, `next_date`.
- Интервалы по умолчанию новых строк: антифриз — 60 000 км или 730 дней, тормозная жидкость — 40 000 км или 730 дней (`slot_default`). Владелец правит интервал у услуги (экран «Услуги»: «Строка книжки», «Интервал, км», «или дней»), у категории и у машины. Отдельного экрана «настройки книжки» нет: интервал услуги и есть её настройка.
- Новая услуга без заданной строки получает её по названию (и при загрузке из Excel). Строку и интервал меняет только владелец (403 администратору). `GET /services` и снимок кассы отдают `book_slot` и интервал для кассы (`interval_km`, `interval_days` — заданный или по умолчанию строки).
- Касса (`web/src/lib/nextChange.ts`, `Cashier.tsx`): блок «Следующая замена» (`next-change`) под «Пробег сейчас» — по строке на строку книжки (две услуги одной строки — одна строка). Значение заранее — пробег + интервал машины по этой строке, иначе услуги, в единице машины; правка кассира хранится по строке книжки, переживает отложенный чек и перезагрузку; смена машины сбрасывает правки. «+ ещё строку» — окно с позициями этого чека (ниже); добавленная строка убирается «✕». Меньше пробега сейчас — красная подсказка у поля и «Не хватает: следующая замена». В режиме кассы блок во всю ширину левой карточки (`service-left`), подпись — строкой книжки («Масло двигателя»), поля 56 точек, цифры — экранной клавиатурой.
- Чек: `next_changes: [{service_id, slot, next_mileage}]` (у строки по товару — `{slot, next_mileage}`, ниже) в единице пробега чека (без сети — так же, в очереди). Сервер (`oil_book::resolve_target`): услуга должна существовать, «прочее» пропускается, пробег не меньше пробега сейчас — иначе 400; у чека без сети ошибка не отклоняет чек — строка остаётся по интервалу, владелец видит причину (`sale.offline_bypass`). Не больше 20 строк.
- Книжка (`record_from_sale`): услуги со строкой книжки сами дают строку (масло клиента, антифриз…), если товара этой строки в чеке нет; иначе подписывают строку товара. Цель кассира ставится на строку этого чека (её нет — цель не пишется, ADR-130), дата — по дням интервала (машины, услуги, категории, по умолчанию). Следующая замена строки (`slot_next`) — цель из последней замены этой строки, а без цели — по интервалу, как раньше (интервал услуги теперь тоже учитывается). На этой цели работают напоминания SPEC-32 и SPEC-16, книжка в боте и кабинете (у строки замены — «— следующая замена на 225 000 км или до …»).
- Печать: `SaleOut.book` (`oil_book::sale_book`) — машина, пробег, строки с целью; `salePrint.ts` печатает блок «Масляная книжка» у чека «В сервис» (и при «Печать» в «Чеках»); чек из очереди без сети печатает тот же блок из данных кассы (`receiptBook`).
- `book_intervals` (SPEC-29 §23) сервер по-прежнему принимает.

### Как сделано: «+ ещё строку» — только из этого чека (26.10.2026)

- Касса (`cartSources`, `extraChoices` в `web/src/lib/nextChange.ts`): позиции чека со строкой книжки — услуги и товары; строка товара — по его категории, а у фильтров — по «Типу фильтра» (как `oil_book::product_slot`), «прочее» и «не в книжку» не считаются, подарок тоже (книжка его не пишет). Услуги чека по-прежнему встают строками сами; «+ ещё строку» предлагает по одной позиции на строку книжки, которой ещё нет в блоке (первую в чеке — на неё сервер и поставит цель). Справочник услуг не загружается и не предлагается; предложить нечего — кнопки нет, а без строк и предложений нет и самого блока (в режиме кассы остаётся «Мастер рекомендовал»).
- Строка по товару: «Фильтр воздушный (Фильтр воздушный MANN C-110)» — строка книжки и товар; заполнено заранее: пробег сейчас + интервал машины по этой строке, иначе категории этой строки (своей категории товара, если её строка та же, иначе любой категории с этой строкой — как книжка), иначе строки по умолчанию (таблица как `slot_default`); у машины в милях — в милях. Категории — `GET /categories`, заново для каждого чека «В сервис» с машиной и товарами (касса открыта весь день), без связи — из снимка кассы: у категорий в снимке теперь строка книжки и интервал, у товаров — характеристики (тип фильтра); у снимка до 26.10.2026 их нет — товары не предлагаются, черновик не трогается.
- С чеком строка по товару уходит без услуги: `{slot, next_mileage}`. Сервер (`record_from_sale`) ставит цель на первую строку замены этой строки книжки в чеке — строку товара; цель по строке книжки, которой в чеке нет, не пишется: строки, которой не было в чеке, в книжке не появится. Цель по услуге, которой нет в чеке, с 27.10.2026 тоже не пишется (ADR-130). Итог «Записано в масляную книжку» и книжка после чека показывают её «Следующая · Фильтр воздушный: на …»; печатный чек — «Фильтр воздушный — следующая замена на пробеге …» (у строки без услуги — название строки книжки), так же печатает чек из очереди (`receiptBook`).
- Удалили товар или услугу из чека — строка «Следующей замены», добавленная по ним, и правка кассира по их строке книжки уходят из чека, черновика и отложенного (`pruneNext`); «Вернуть» в режиме кассы возвращает их вместе со строкой чека. Снова добавили товар — строка сама не встаёт, её снова предлагает «+ ещё». В черновике и отложенном строки «+ ещё» хранятся строками книжки; прежние (услуги справочника) при открытии не берутся.
- Режим кассы: окно выбора — кнопки по позициям 56 точек и «Отмена» 56, страница не прокручивается; у строки по товару подпись над полем — во всю ширину поля и «✕» («Фильтр воздушный» целиком). Снимки 1366 × 768 — e2e `next-change-cart.spec.ts` (`next-cart-*.png`).

### Исправлено после проверки (27.10.2026)

- Услуга, добавленная плиткой «ходовое», не давала строки «Следующей замены» (плитка не знала её строку книжки): `GET /settings/favorites` отдаёт у услуги те же поля, что `GET /services`, — `book_slot`, `interval_km`, `interval_days`, а заодно `free_with_oil` и `oil_category_id` (цена «бесплатно с нашим маслом» у плитки — как у «Вида замены», ADR-096). Замена масла плиткой при масле клиента — строка «Масло двигателя», в книжку и печать (`favorites_heatmap_and_compare`, e2e «услуга плиткой «ходовое»» в обеих кассах).
- Интервал категории — только строки этой категории, как в книжке (`slot_next`): у общей категории «Фильтры» (строка — масляный фильтр) интервал владельца не задаёт ни пробег заранее, ни дату воздушному фильтру из неё — у него интервал категории воздушных фильтров, если есть, иначе по умолчанию строки. Так же, когда у своей категории товара интервала нет, а у другой категории этой строки есть. Касса (`cartSources`) и сервер (`oil_book::category_interval` — общий для даты цели и книжки) считают одинаково (`nextChange.test.ts`, `next_change_by_product_of_this_sale_goes_to_its_book_line`).
- Режим кассы: «+ ещё» прячет экранную клавиатуру (она ложилась на правые края кнопок окна, касание набирало цифру в «Пробег сейчас»), а клавиатура и «⌨» поля за открытым окном не рисуются вообще; фокус — в поиск товара, скан при открытом окне встаёт в чек за окном (раньше пропадал). Добавленная строка прокручивается в видимую часть карточки замены. Список чека, стоящий внизу, остаётся внизу и после выбора клиента. Плашка «снимок каталога устарел» уходит, как только снимок сохранён (e2e `next-change-cart.spec.ts` «под пальцем», `scanner-focus.spec.ts` «+ ещё строку» в обеих кассах, `offline-queue.spec.ts`).

### Как сделано: чек и книжка в чеке (27.10.2026, ADR-130)

- Строка жидкости по названию товара — `oil_book::slot_by_product_name` (сервер, `record_from_sale`: у категории без строки, `book_slot` «none») и `nameSlot` / `goodSlot` в `web/src/lib/nextChange.ts` (касса: `cartSources`, `cartGoods`, а через них «+ ещё», «Залито» и чек из очереди). Снимок кассы не менялся: у категорий там уже строка книжки («none»), у товаров — название.
- `record_from_sale`: цель без строки этого чека пропускается всегда (прежняя ветка «строка с названием услуги» убрана).
- Касса (`Cashier.tsx`): книжка после чека запоминается и печатается, только если в ней есть запись этого чека; `oilBookHtml` с `saleId` без своей записи возвращает `null`, `printOilBook` тогда ничего не печатает. Выписка из карточки клиента (без `saleId`) — прежняя.
- `salePrint.ts`: строка услуги (`kind` «service») — название и сумма в одной строке; «N × цена» — только при N > 1.
