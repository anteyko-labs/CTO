# SPEC-32. Сообщения клиентам: Телеграм и WhatsApp

Решение заказчика 24.10.2026 — ADR-107. Образцы сообщений заказчика:

> Азиз, здравствуйте! Магазин Avtodom. Не забудьте поменять масло на Toyota Camry 01KG123ABC на пробеге 201 748. А масло в коробке — на 230 748. Бонусы нашего магазина и информация по ТО вашего авто — по ссылке «ссылка на бот».

> Азиз (ОсОО Бишкек такси), здравствуйте! Сегодня был закуп на сумму 1 000 сом. Водитель Чынтемир, машина Sprinter 09KG111JJJ. Общий долг на сегодня — 6 240 сом. Для полного ознакомления пройдите в личный кабинет «ссылка».

## 1. Канал

- Клиент привязан к боту — сообщение в Телеграм (как сейчас, ADR-063: с 09:00 до 20:00 по Бишкеку). Не привязан, есть телефон и включён WhatsApp — в WhatsApp. Нет ни того ни другого — не отправляется (видно в журнале сообщений).
- WhatsApp — официальный WhatsApp Business Platform (Cloud API Meta): переменные `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID` (на точке — `config.ps1`), `WHATSAPP_API_URL` (по умолчанию `https://graph.facebook.com/v26.0` — версия из документации Meta на 24.10.2026). Сообщения, которые программа начинает сама, — только по шаблонам, одобренным Meta: имя шаблона и язык задаёт владелец в «Настройки → Сообщения клиентам» для каждого вида сообщения, переменные подставляет программа в порядке, описанном на экране. Без переменных окружения WhatsApp выключен.
- Журнал сообщений: кому, вид, канал, текст или шаблон и переменные, время, результат (отправлено / ошибка с причиной). Экран «Сообщения клиентам» у владельца: журнал, настройки, «Отправить пробное».
- Один и тот же повод не отправляется дважды (ключ: вид + клиент + машина + цель или документ).

## 2. Ссылка на бот с кодом клиента

- У каждого клиента — скрытый код (случайный, не номер по порядку, не подбирается перебором), клиенту он не показывается. Ссылка `https://t.me/<бот>?start=<код>`: нажал «Старт» — бот сразу привязывает чат к этому клиенту, без телефона. Старая привязка по телефону остаётся.
- Код можно сменить у владельца в карточке клиента («Новая ссылка» — старая перестаёт работать).

## 3. Напоминание о замене масла — по среднему пробегу

- Средний пробег машины в день — по записям книжки (пробег и дата заездов, не меньше двух записей за последние 2 года, не меньше 7 дней между первой и последней); одна запись — пробег по умолчанию из настроек (50 км в день). В милях — в милях.
- Для каждой строки книжки с целевым пробегом (мотор, коробка и прочие с интервалом) — ожидаемая дата, когда машина дойдёт до цели: дата последнего заезда + (цель − пробег на заезде) / средний в день. Напоминание — за 3 дня до этой даты, но не раньше срока по дням, если он задан и наступает раньше (что раньше — то и берётся).
- Текст: имя клиента, «Магазин Avtodom», марка, модель и госномер, мотор — «поменять масло на пробеге N», коробка и прочие строки, у которых срок подходит в те же 14 дней, — одной строкой «А масло в коробке — на N», ссылка на бот (для WhatsApp — всегда, для Телеграма — не нужна).
- Заменяет прежние напоминания бота по дням (ADR-063), если для машины считается средний пробег; без пробега — как раньше по дням.

## 4. Сообщение юрлицу о закупе — сразу

- После каждого проведённого чека фирмы (продажа или возврат) — сообщение фирме сразу (в окно 09:00–20:00; ночью — утром): имя и фирма, «сегодня был закуп на сумму N» (возврат — «возврат на сумму N»), водитель (человек фирмы в чеке), машина и госномер, общий долг фирмы на сейчас, ссылка на кабинет — если задан внешний адрес программы `PUBLIC_URL`; без него — ссылка на бот.
- Кому: чат бота фирмы и её руководителя; в WhatsApp — телефон фирмы (или руководителя). Отключается у фирмы флажком «Не присылать сообщения о закупах».

## 5. Права и журнал

- Настройки и журнал — владелец; журнал действий — `client_message.send`, `client_message.settings`, `client.bot_link_reset`.

## Проверка

- [x] Привязанный к боту — Телеграм; без бота с телефоном и включённым WhatsApp — WhatsApp по шаблону с переменными; без обоих — запись «не отправлено» (`oil_reminder_by_average_mileage_and_channel`, `whatsapp_off_or_error_is_written`).
- [x] Ссылка `?start=<код>` привязывает чат; сменённый код не работает; код не виден клиенту ни в сообщениях, ни в кабинете (`bot_link_with_client_code`).
- [x] Средний пробег по книжке, дата напоминания, мотор и коробка в одном сообщении, мили; одна запись — пробег по умолчанию; не дважды (`oil_reminder_by_average_mileage_and_channel`; модульные `average_mileage_from_book`, `motor_and_gearbox_in_one_message`, `miles_in_text`).
- [x] Закуп фирмы — сообщение сразу, долг верный, ночью — утром; флажок отключает (`firm_purchase_message_now_or_morning`, `firm_link_to_bot_without_public_url_and_test_send`).
- [x] В тестах — подставные серверы Телеграма и WhatsApp (`server/tests/client_messages.rs`); экран — e2e `client-messages.spec.ts`.

## Как сделано (24.10.2026)

- Модуль `server/src/api/client_messages.rs`, миграция 0061. Сообщение сначала составляется — строка `client_messages` (по строке на получателя) и ключ повода в `client_message_keys` одной транзакцией: `oil:<клиент>:<машина>:<строка книжки>:<цель, км>`, `purchase:<чек>`; занятый ключ — повод уже был. Потом отправляется; временная ошибка (нет связи, 429, сбой Meta, ключ не подходит) — повтор позже, после 30 попыток — «ошибка»; постоянная (шаблон не одобрен, неверный номер, бот заблокирован) — «ошибка» с причиной от Meta или Телеграма.
- Фоновая задача — раз в 30 с, только в окно 09:00–20:00 по Бишкеку: составить сообщения о новых чеках фирм и отправить ждущие; раз в час — напоминания о замене. Чек ночью составляется утром: «Вчера был закуп», долг — на момент чека (сумма журнала долга до него). Сообщения о чеках до установки не рассылаются. Задача работает, если есть бот или WhatsApp.
- Строка книжки «Масло в коробке» (`gear_oil`) — новая (SPEC-16). Срок строки: ожидаемая дата по среднему пробегу или срок по дням — что раньше; напоминание — от 3 дней до даты до 3 дней после (пропущенное догоняется); строки, чей срок в 14 дней после главной, — в том же сообщении. Главная — масло двигателя, если его срок подошёл. У машины без пробега в книжке — прежние напоминания по дням, только в Телеграм.
- Имя в обращении — имя клиента (`first_name`), без него — полное; у фирмы — «руководитель (фирма)», руководитель — флажок у работника фирмы (`party_contacts.is_head`). Чат руководителя — подключённая к боту его карточка клиента с тем же телефоном.
- Шаблоны Meta не могут начинаться и кончаться переменной, значения — одной строкой без переводов. Тексты шаблонов для подачи в Meta — на экране «Настройки → Сообщения клиентам» и в `web/src/lib/clientMessages.ts` (сервер проверяет, что они совпадают с текстом журнала):
  - «замена масла»: «Здравствуйте, {{1}}! Магазин Avtodom. Не забудьте поменять {{2}} на {{3}} на пробеге {{4}}. Бонусы нашего магазина и информация по ТО вашего авто — по ссылке: {{5}}» и строкой ниже «Ждём вас в Avtodom!»; {{1}} имя, {{2}} что менять, {{3}} машина, {{4}} пробег и остальное («201 748 км. А масло в коробке — на 230 748 км»), {{5}} ссылка на бот;
  - «закуп юрлица»: «Здравствуйте, {{1}}! {{2}} на сумму {{3}}. Водитель {{4}}, машина {{5}}. Общий долг на сегодня — {{6}}. Для полного ознакомления пройдите в личный кабинет: {{7}}» и строкой ниже «Спасибо, что вы с нами!»; {{1}} имя и фирма, {{2}} «Сегодня был закуп» / «Вчера был возврат», {{3}} сумма, {{4}} водитель, {{5}} машина, {{6}} долг, {{7}} ссылка на кабинет или на бот.
- В Телеграм — текстом заказчика («Азиз, здравствуйте! …»), без ссылки на бот; сообщение фирме — со ссылкой на кабинет, если задан `PUBLIC_URL`.
- API (владелец): `GET/PUT /settings/client-messages`, `GET /client-messages` (журнал, страницами), `POST /client-messages/test` (`party_id`, `kind`: «Отправить пробное» сразу, без окна), `GET /parties/{id}/bot-link`, `POST /parties/{id}/bot-link/reset`. Поля `no_purchase_messages` у клиента и `is_head` у работника фирмы — в прежних запросах карточки. В журнал действий пишутся пробные отправки (`client_message.send`), настройка и смена ссылки; автоматические сообщения — в журнале сообщений.

## Дополнено SPEC-34 (26.10.2026)

- Целевой пробег строки книжки — тот, что кассир задал в чеке («Следующая замена»); по нему считается ожидаемая дата по среднему пробегу. Пустая цель — по строке не напоминать. Новые строки в тексте: «антифриз», «тормозную жидкость».

## Дополнено ADR-131 (27.10.2026)

- Услуга «прочее» с целью кассира («Замена ГУР», «Смазка кардана») — своё напоминание у каждой услуги: ключ повода `oil:<клиент>:<машина>:other:<услуга>:<цель, км>` (у строк книжки ключ прежний — отправленное не повторяется), в тексте — название услуги со строчной: «… А замена ГУР — на 150 000 км».
- Главная строка — масло двигателя, если его срок подошёл, иначе ближайшая строка книжки; услуга «прочее» — главной, только если других строк в сроке нет. Тогда в Телеграме — «Не забудьте: замена ГУР на <машина> на пробеге …»; в WhatsApp шаблон и число переменных прежние, «что менять» ({{2}}) — название услуги.
- Напоминания по дням (машина без пробега в книжке, ADR-063) — так же по каждой услуге: отметка `other:<услуга>`, текст «Напоминаем: замена масла, замена ГУР для …».
- Проверка: модульный `other_services_each_by_name`, `other_services_each_get_own_line_and_reminder` (две услуги «прочее» — две строки и два ключа, текст с названиями).

## Дополнено задачей 002, волна 2 (31.10.2026, ADR-141)

- **«Получили оплату» (П7).** После каждого погашения долга клиента — сообщение должнику: «Здравствуйте, {имя}! Получили оплату {сумма}. Долг на сегодня — {долг}.» Одно сообщение на погашение (части по филиалам — одно), ключ `payment:<первая запись долга>`; долг — на момент погашения по всем филиалам; переплата — «0 сом (аванс …)». Погашение, сторнированное до отправки, и верное погашение «Исправить», если об исходном уже писали, не пишутся. Ночью — утром (окно 09:00–20:00).
- **Раз в месяц (П7б).** В день месяца (1–28, по умолчанию 1) с часа (9–19, по умолчанию 10) по Бишкеку каждому клиенту с долгом больше нуля: «Здравствуйте, {имя}! На {дата} ваш долг — {долг}.»; юрлицу при внешнем адресе — ещё «Подробно — в кабинете: {ссылка}». Ключ `monthly:<клиент>:<ГГГГ-ММ>`; пропущенное (сервер был выключен) догоняется ещё два дня. Клиент общий — по настройке филиала, где завели карточку.
- **Каналы.** Бот — всем подключённым (у юрлица — его чат и чат руководителя); WhatsApp — только юрлицам, по шаблонам «получили оплату» (`{{1}}` имя и фирма, `{{2}}` сумма, `{{3}}` долг) и «долг раз в месяц» (`{{1}}` имя, `{{2}}` дата, `{{3}}` долг, `{{4}}` ссылка) — тексты для Meta на экране и в `web/src/lib/clientMessages.ts`; частному без бота — «не отправлено» с причиной. Юрлицу — ещё строка журнала с каналом «Кабинет»: её показывает вкладка «Сообщения» кабинета (`GET /client/messages`, последние 50).
