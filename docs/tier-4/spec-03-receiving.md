# SPEC-03. Приход и остатки

## Задача

Оформление приходной накладной, пересчёт средней себестоимости, движения склада и проверка остатков.

## Приход

- `POST /receipts {op_id, supplier_id?, supplier_doc?, comment?, lines: [{product_id, qty, cost_tyiyn}]}`
  - `qty` — в единицах учёта (штуки или мл), > 0;
  - `cost_tyiyn` — сумма закупки по строке, ≥ 0.
- `GET /receipts?from=&to=`, `GET /receipts/{id}`.
- `POST /receipts/{id}/reverse {op_id, comment}` — сторно целиком. Второй раз сторнировать нельзя (409), сторно сторно — нельзя.
- Номер — счётчик филиала `receipt_seq`.
- Клиент для масла вводит количество канистр и цену канистры, отправляет `qty = n × container_ml`, `cost = n × цена`.

## Алгоритм проведения прихода

```
в run_operation:
  проверить строки (непустые, товары существуют, qty > 0, cost ≥ 0)
  receipt = insert (number = next(receipt_seq))
  для каждой строки:
     insert receipt_line
     apply_movement(product, +qty, +cost, 'receipt', receipt.id)
     branch_products.last_cost_qty = qty, last_cost_tyiyn = cost   (если qty > 0)
  audit receipt.post
```

```
apply_movement(product, dq, dv, doc_type, doc_id):
  select branch_products ... for update   (строка создаётся, если её нет)
  insert stock_movements(dq, dv)
  stock_qty += dq; stock_value += dv
  если stock_qty < 0 → needs_review = true
```

## Себестоимость списания (ADR-011)

```
cost_of(q, stock_qty, stock_value, last_qty, last_cost):    q > 0
  если stock_qty ≥ q:          вернуть div_round(q · stock_value, stock_qty)
  covered = max(stock_qty, 0)
  part1 = covered > 0 ? stock_value : 0
  rest  = q − covered
  part2 = last_qty > 0 ? div_round(rest · last_cost, last_qty) : 0
  вернуть part1 + part2
```
Функция чистая, живёт в `domain::costing`, покрыта тестами.

Единицы, которые не покрыты ни остатком, ни прошлой закупкой (`last_qty = 0`), — без цены (`unknown_units`): себестоимость строки чека неизвестна, строка помечается `cost_unknown` (ADR-062).

## Сторно прихода

```
для каждой строки исходного прихода:
  apply_movement(product, −qty, −cost, 'receipt_reversal', reversal.id)
receipt reversal: reversal_of = исходный, строки с отрицательными qty и cost
```
Остаток может уйти в минус — товар помечается для проверки (инвариант 10).

Сторно прихода уже проданного товара (ADR-065): если после сторно остаток какого-либо товара накладной уйдёт в минус (строки одного товара складываются, сравнение — с остатком под блокировкой), провести его может только владелец; администратору — 403, ничего не записано. Владельцу в той же транзакции — уведомление `receipt.reverse_negative` «остаток ушёл в минус — проведите верный приход» со списком товаров и остатком после сторно. Сторно непроданного товара — как прежде, владелец и администратор.

## Отмена приёма аккумуляторов

Приём старых аккумуляторов на вес (ADR-048) — закупка из кассы смены. Ошибочный приём отменяется (ADR-065):

```
POST /batteries/intakes/{id}/reverse {op_id, comment?}
в одной транзакции:
  приём уже отменён → 409 (battery_intake_reversals.intake_id уникален)
  администратор: приём сделан в текущую открытую смену его кассы, иначе 403; владелец — любой
  касса приёма с наличными: нужна открытая смена (409), деньги возвращаются в неё
  lock остатка; остаток < веса приёма (часть уже продана) → 409
  insert battery_intake_reversals (документ приёма не меняется)
  последняя закупочная цена — из последнего неотменённого приёма, иначе 0
  apply_movement(−граммы, −стоимость приёма, 'battery_intake_reversal')
  cash_movement(reversal, +сумма приёма, касса приёма)
  audit battery.intake_reverse (уведомление владельцу)
```

`GET /batteries/intakes` — приёмы с отметкой `reversed`: администратору — его открытой смены, владельцу — последние 50. В окне «Приём аккумуляторов» на кассе — список «Приёмы этой смены» с кнопкой «Отменить приём» (причина спрашивается), отменённые зачёркнуты.

## Остатки

- `GET /stock?category_id=&low=true` — остатки филиала; `low` — ниже `min_stock`.
- `GET /stock/verify` (владелец) — сравнивает кэш с суммой движений, отдаёт список расхождений; пустой список — норма.
- `POST /stock/{product_id}/review-done` (владелец) — снимает пометку `needs_review`. Если товар продан без цены закупки и цена ещё не указана — 409 (ADR-062).
- `POST /stock/{product_id}/purchase-price {op_id, price_tyiyn}` (владелец) — цена закупки товара, проданного без неё: за штуку, за канистру (масло) или за килограмм (на вес). Строки чеков без себестоимости получают цену для процента кассира, процент начисляется сегодня (SPEC-07); если приходов не было, цена становится последней закупочной. Ответ — `{lines, accrued_tyiyn}`. В `/stock` у товара `cost_pending: true`, пока цена не указана; на экране «Остатки» — отметка «без цены закупки» и кнопка «Цена закупки» вместо «Проверено».

## Права

Приход и его сторно — владелец и администратор (ADR-008); сторно, уводящее остаток в минус, — только владелец (ADR-065). Средняя цена и стоимость остатка в `/stock` — только владельцу.

## Клиент

- Экран «Приход»: выбор поставщика, номер его документа, строки через сканер или поиск. Незнакомый код открывает быстрое создание товара (SPEC-02) с подставленным кодом. Для масла — канистры и цена канистры, для штучного — количество и цена за штуку; итог по строке и документу.
- Цена строки подставляется из последнего прихода товара (`last_purchase_price_tyiyn` за штуку или канистру, видна обеим ролям по ADR-008) и может быть изменена.
- Кнопка «Печать этикеток» по строкам прихода (количество = пришедшее, для масла — канистры).
- Список приходов, просмотр, сторно с комментарием.
- В строке накладной есть «Этикетки» — печать на этот товар сразу, не дожидаясь проведения, количество берётся из строки, — и «Карточка»: цена, штрихкоды и создание своего кода без ухода с прихода.
- Экран «Остатки»: поиск, категория, быстрые фильтры «Все / Мало / Проверить» со счётчиками; клик по строке открывает карточку товара.
- Масло в остатках считается литрами: сначала общий объём, затем расшифровка тарой — «14,5 л · 3 кан. по 4 л + 2,5 л». Закрытые канистры и початая тара складываются в один объём, потому что на складе лежит столько литров.

## Критерии приёмки

- [ ] Приход 10 шт на 1000 с, затем 10 шт на 2000 с → стоимость остатка 3000 с, средняя 150 с.
- [ ] Продажа всех единиц обнуляет и количество, и стоимость без остатка в тыйынах.
- [ ] `cost_of` при нулевом остатке использует цену последнего прихода.
- [ ] Сторно прихода возвращает остаток и стоимость к прежним значениям.
- [ ] Остаток 14 500 мл при таре 4 л показывается как «14,5 л · 3 кан. по 4 л + 2,5 л».
- [ ] Повторное сторно — 409.
- [x] Сторно прихода уже проданного товара: администратор → 403, владелец проводит, остаток −3, уведомление `receipt.reverse_negative`; непроданный товар администратор сторнирует как прежде (`receipt_reversal_of_sold_goods_is_owner_only`).
- [x] Отмена приёма аккумуляторов возвращает деньги в кассу и снимает вес; второй раз — 409; проданный вес — 409; администратор без открытой смены — 403 (`battery_intake_can_be_reversed_once`).
- [ ] `/stock/verify` пуст после любой последовательности операций в тестах.
