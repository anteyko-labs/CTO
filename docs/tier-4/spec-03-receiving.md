# SPEC-03. Приход и остатки

## Задача

Оформление приходной накладной, пересчёт средней себестоимости, движения склада и проверка остатков.

## Приход

- `POST /receipts {op_id, supplier_id?, supplier_doc?, comment?, lines: [{product_id, qty, cost_tyiyn}]}`
  - `qty` — в единицах учёта (штуки или мл), > 0;
  - `cost_tyiyn` — сумма закупки по строке, ≥ 0.
- `GET /receipts?from=&to=`, `GET /receipts/{id}`.
- `POST /receipts/{id}/reverse {op_id, comment}` — сторно целиком. Второй раз сторнировать нельзя (409), сторно сторно — нельзя.
- Номер — счётчик филиала `receipt_seq`.
- Клиент для масла вводит количество канистр и цену канистры, отправляет `qty = n × container_ml`, `cost = n × цена`.

## Алгоритм проведения прихода

```
в run_operation:
  проверить строки (непустые, товары существуют, qty > 0, cost ≥ 0)
  receipt = insert (number = next(receipt_seq))
  для каждой строки:
     insert receipt_line
     apply_movement(product, +qty, +cost, 'receipt', receipt.id)
     branch_products.last_cost_qty = qty, last_cost_tyiyn = cost   (если qty > 0)
  audit receipt.post
```

```
apply_movement(product, dq, dv, doc_type, doc_id):
  select branch_products ... for update   (строка создаётся, если её нет)
  insert stock_movements(dq, dv)
  stock_qty += dq; stock_value += dv
  если stock_qty < 0 → needs_review = true
```

## Себестоимость списания (ADR-011)

```
cost_of(q, stock_qty, stock_value, last_qty, last_cost):    q > 0
  если stock_qty ≥ q:          вернуть div_round(q · stock_value, stock_qty)
  covered = max(stock_qty, 0)
  part1 = covered > 0 ? stock_value : 0
  rest  = q − covered
  part2 = last_qty > 0 ? div_round(rest · last_cost, last_qty) : 0
  вернуть part1 + part2
```
Функция чистая, живёт в `domain::costing`, покрыта тестами.

Продажа при нулевом или отрицательном остатке берёт себестоимость по последней закупочной цене, не 0 (SPEC-27); стоимость отрицательного остатка в списке товаров — остаток × последняя закупочная.

Единицы, которые не покрыты ни остатком, ни прошлой закупкой (`last_qty = 0`), — без цены (`unknown_units`): себестоимость строки чека неизвестна, строка помечается `cost_unknown` (ADR-062).

## Сторно прихода

```
для каждой строки исходного прихода:
  apply_movement(product, −qty, −cost, 'receipt_reversal', reversal.id)
receipt reversal: reversal_of = исходный, строки с отрицательными qty и cost
```
Остаток может уйти в минус — товар помечается для проверки (инвариант 10).

Сторно прихода уже проданного товара (ADR-065): если после сторно остаток какого-либо товара накладной уйдёт в минус (строки одного товара складываются, сравнение — с остатком под блокировкой), провести его может только владелец; администратору — 403, ничего не записано. Владельцу в той же транзакции — уведомление `receipt.reverse_negative` «остаток ушёл в минус — проведите верный приход» со списком товаров и остатком после сторно. Сторно непроданного товара — как прежде, владелец и администратор.

## Отмена приёма аккумуляторов

Приём старых аккумуляторов на вес (ADR-048) — закупка из кассы смены. Ошибочный приём отменяется (ADR-065):

```
POST /batteries/intakes/{id}/reverse {op_id, comment?}
в одной транзакции:
  приём уже отменён → 409 (battery_intake_reversals.intake_id уникален)
  администратор: приём сделан в текущую открытую смену его кассы, иначе 403; владелец — любой
  касса приёма с наличными: нужна открытая смена (409), деньги возвращаются в неё
  lock остатка; остаток < веса приёма (часть уже продана) → 409
  insert battery_intake_reversals (документ приёма не меняется)
  последняя закупочная цена — из последнего неотменённого приёма, иначе 0
  apply_movement(−граммы, −стоимость приёма, 'battery_intake_reversal')
  cash_movement(reversal, +сумма приёма, касса приёма)
  audit battery.intake_reverse (уведомление владельцу)
```

Старый аккумулятор, сданный в оплату чека (SPEC-27, SPEC-04), приходует на ту же карточку «на вес» по цене приёма, но внутри чека и без денег из кассы: движение `battery_tradein` (документ — чек), последняя цена приёма обновляется так же. В списке приёмов его нет — он виден в чеке; отменяется возвратом чека (`battery_tradein_return`).

`GET /batteries/intakes` — приёмы с отметкой `reversed`: администратору — его открытой смены, владельцу — последние 50. В окне «Приём аккумуляторов» на кассе — список «Приёмы этой смены» с кнопкой «Отменить приём» (причина спрашивается), отменённые зачёркнуты.

## Остатки

- `GET /stock?category_id=&low=true` — остатки филиала; `low` — ниже `min_stock`.
- `GET /stock/verify` (владелец) — сравнивает кэш с суммой движений, отдаёт список расхождений; пустой список — норма.
- `POST /stock/{product_id}/review-done` (владелец) — снимает пометку `needs_review`. Если товар продан без цены закупки и цена ещё не указана — 409 (ADR-062).
- `POST /stock/{product_id}/purchase-price {op_id, price_tyiyn}` (владелец) — цена закупки товара, проданного без неё: за штуку, за канистру (масло) или за килограмм (на вес). Строки чеков без себестоимости получают цену для процента кассира, процент начисляется сегодня (SPEC-07); если приходов не было, цена становится последней закупочной. Ответ — `{lines, accrued_tyiyn}`. В `/stock` у товара `cost_pending: true`, пока цена не указана; на экране «Остатки» — отметка «без цены закупки» и кнопка «Цена закупки» вместо «Проверено».

## Права

Приход и его сторно — владелец и администратор (ADR-008); сторно, уводящее остаток в минус, — только владелец (ADR-065). Средняя цена и стоимость остатка в `/stock` — только владельцу.

## Клиент

- Экран «Приход»: выбор поставщика, номер его документа, строки через сканер или поиск. Незнакомый код открывает быстрое создание товара (SPEC-02) с подставленным кодом. Для масла — канистры и цена канистры, для штучного — количество и цена за штуку; итог по строке и документу.
- В строке — цена продажи товара (за штуку или канистру) и сумма строки по ней; внизу рядом с итогом по закупке — итог по цене продажи (SPEC-27).
- Строка как в старой программе: цена по накладной, наценка %, цена продажи, сумма; наценка и цена продажи связаны, новая цена продажи ставится товару при проведении (владелец и администратор), с записью в журнал и уведомлением владельцу (SPEC-28 §1, ADR-075). Строка хранит цену продажи после прихода (`receipt_lines.sale_price_tyiyn`).
- При выборе товара под ценой — «в прошлый раз: 350 с, 12.10, Автоснаб»: `GET /products/{id}/last-receipt` → `{receipt_id, number, price_tyiyn, created_at, supplier_name}` или `null` — последний непогашенный приход товара и влитых в него карточек, цена за штуку, канистру или кг. Видна обеим ролям (ADR-008).
- Цена строки подставляется из последнего прихода товара (`last_purchase_price_tyiyn` за штуку или канистру, видна обеим ролям по ADR-008) и может быть изменена.
- Кнопка «Печать этикеток» по строкам прихода (количество = пришедшее, для масла — канистры).
- SPEC-29: подсказки при вводе товара — свои товары и позиции старой программы (выбор открывает заполненную полную карточку), ввод подряд с клавиатуры (Enter — следующее поле, следующая строка, поиск), расчёт «оплачена сразу / часть сейчас, остаток в долг / вся в долг» (`paid_now_tyiyn`), фото накладной при проведении и в накладной (ADR-080), «из своих, мимо касс» убрано (ADR-079). Товар без накладной — вариант прихода «Оприходование (без поставщика)» на экране «Новый приход» (`stock_ins` + `stock_in_lines`, ADR-086; список «Приход» показывает оба вида с отбором), возврат поставщику — в его карточке и в меню «Склад» (`supplier_returns`).
- Список приходов, просмотр, сторно с комментарием.
- В строке накладной есть «Этикетки» — печать на этот товар сразу, не дожидаясь проведения, количество берётся из строки, — и «Карточка»: цена, штрихкоды и создание своего кода без ухода с прихода.
- Экран «Остатки»: поиск, категория, быстрые фильтры «Все / Мало / Проверить» со счётчиками; клик по строке открывает карточку товара.
- Масло в остатках считается литрами: сначала общий объём, затем расшифровка тарой — «14,5 л = 3 кан. по 4 л + 2,5 л» (SPEC-27): целые канистры и остаток в литрах дают ровно остаток в мл, без округления; одна полная канистра, минус и ноль — просто литры. Так же считает текст бота (`domain::qty`). Закрытые канистры и початая тара складываются в один объём, потому что на складе лежит столько литров.

## Дополнено SPEC-30 (21.10.2026)

Экран «Остатки» вошёл в «Товары» (SPEC-30 §11). `GET /products/list?stock=low|out|stale|review` — отбор по складу: `low` — остаток меньше минимума (как «Заканчивается» в сводке), `out` — ноль или минус, `stale` — залежалые (ADR-039, тем же запросом, что сводка), `review` — «проверить». У строки залежалого `stale {days, sold_ever}`; в `totals` — `counts {all, low, out, stale, review}` при тех же поиске, категории и характеристиках и `stale_days`; `count`, `purchase_tyiyn` (владельцу) и `sale_tyiyn` — по выбранному отбору.

На «Товарах»: отборы «Все / Ниже минимума / Нет на складе / Залежалые / Проверить» с числами (`?stock=`); в строке остаток и «мин.», отметки «нет», «ниже минимума», «проверить», «без цены закупки», «не продавался N дн.»; владельцу «Цена закупки» и «Проверено» в строке и «Сверить остатки» сверху; «+ Оприходовать», «В брак» и «В архив» в меню строки — по правам (ADR-097); вкладка «Брак» (`?tab=defects`); полярность — и без категории; итоги по всему отбору внизу. Пункта «Остатки» нет; `/stock` ведёт на `/products` (`filter`→`stock`, `q`, `category_id`, `tab`); «Склад сейчас» в сводке ведёт сразу на отбор. `GET /stock` остаётся для бота.

Накладные по фото (SPEC-30 §9, ADR-098): таблица `receipt_drafts` (миграция 0058): источник `bot`/`screen`, фото `bytea` до 5 МБ, состояние распознавания (off / limit / pending / done / failed), распознанное (`jsonb`), расход, статус new → used / removed (правку и удаление запрещает триггер; при «использован» фото переносится в `receipt_files`). API: `GET /receipt-drafts` (`{enabled, items}`, до 50 новых), `POST /receipt-drafts?op_id=&name=` (тело — файл JPEG, PNG, WEBP или PDF до 5 МБ; без ключа — 422, лимит часа — 429, повтор `op_id` — тот же черновик), `GET /receipt-drafts/{id}` (накладная, поставщик, строки с `match` exact/similar/none, итог и сумма строк), `GET /receipt-drafts/{id}/file`, `POST /receipt-drafts/{id}/remove`; `POST /receipts {draft_id?}` прикрепляет фото той же операцией, по использованному или убранному черновику — 409. Доступ — владелец и администратор с правом `receipts`. Журнал: `receipt_draft.add`, `.recognize`, `.use`, `.remove`.

На экране: в «Приходе» блок «Накладные по фото: N» (миниатюра, дата, «из бота» / «с экрана», кто прислал, поставщик и номер, строк, итог; «Открыть», «Убрать»); в «Новом приходе» — «Заполнить по фото» (камера) и «из файла», снимок ужимается до 2000 точек JPEG, ответ — до нескольких минут. Заполнение: поставщик по ИНН (только цифры) или названию без кавычек и формы собственности (точно или сходство ≥ 0,4), не найден — подсказка «Поставщик не найден. В накладной: …» и «завести»; номер — «15 от 20.10.2026»; товар строки — совпал штрихкод или артикул → выбран, похоже название или «бренд + название» (≥ 0,4) → выбран с «проверьте», иначе блок «Строки накладной без товара» («Выбрать товар», «Новый товар», «✕»), пока они есть, приход не проводится; количество и цена из накладной, литры масла — в канистры, только если делятся на объём без остатка; итог накладной сверяется с итогом прихода.

**После проверки вживую (22.10.2026):** без ключа распознавания владелец видит в «Новом приходе» неактивную «Заполнить по фото» с подписью «нужен ключ распознавания (Настройки → Телеграм и баллы / config.ps1)», администратор — ничего. `/receipts/new` без прав `receipts` и `stock_in` — только «Нет права». Нового поставщика (`POST /suppliers` и `POST /parties` с ролью `supplier`) заводит владелец или администратор с правом `receipts` (иначе 403 «Нет права: …»); кнопка «Добавить» на «Поставщиках» — по тому же праву. Карточка товара без права `products` — поля недоступны; у фильтра кросс-номера — одним полем (прежний признак категории `cross` не показывается). Сортировка «Остаток» на «Товарах» не смешивает единицы: штуки, затем литры, затем килограммы, внутри — по количеству; отбор «Полярность» без категории — только если в списке есть аккумуляторы.

## Критерии приёмки

- [ ] Приход 10 шт на 1000 с, затем 10 шт на 2000 с → стоимость остатка 3000 с, средняя 150 с.
- [ ] Продажа всех единиц обнуляет и количество, и стоимость без остатка в тыйынах.
- [x] `cost_of` при нулевом остатке использует цену последнего прихода (`shortage_uses_last_receipt_price`, `negative_stock_sale_costs_last_purchase_price`).
- [ ] Сторно прихода возвращает остаток и стоимость к прежним значениям.
- [x] Остаток 14 500 мл при таре 4 л показывается как «14,5 л = 3 кан. по 4 л + 2,5 л» (`canisters_add_up_to_the_stock`, `format.test.ts`).
- [x] В приходе видны цена продажи, итог по продаже и прошлая закупка (`receipt_shows_last_purchase_price_date_and_supplier`, `receiptLines.test.ts`, e2e stage8).
- [ ] Повторное сторно — 409.
- [x] Сторно прихода уже проданного товара: администратор → 403, владелец проводит, остаток −3, уведомление `receipt.reverse_negative`; непроданный товар администратор сторнирует как прежде (`receipt_reversal_of_sold_goods_is_owner_only`).
- [x] Отмена приёма аккумуляторов возвращает деньги в кассу и снимает вес; второй раз — 409; проданный вес — 409; администратор без открытой смены — 403 (`battery_intake_can_be_reversed_once`).
- [ ] `/stock/verify` пуст после любой последовательности операций в тестах.

## Дополнено SPEC-39 (28.10.2026)

Приход по приёмке на планшете (ADR-134). «На приёмку» в «Новом приходе» (`POST /acceptances`, право `receipts`) сохраняет накладную с теми же проверками, что у проведения, но склад, долг и цены не меняет; черновик фото — «на приёмке» (`receipt_drafts.status = 'acceptance'`, из «Накладных по фото» — 409). Кассир на планшете отмечает принятое, PIN и подпись — `POST /acceptances/{id}/accept` проводит обычный приход (`post_receipt_tx`) одной транзакцией от имени отправившего: строки только принятые больше нуля, сумма строки = сумма по накладной × принято / по накладной (`div_round`, одно округление), расчёт — «в долг» на принятое, новая цена продажи — у принятых строк накладной, фото черновика — в накладную. Таблицы `receipt_acceptances`, `receipt_acceptance_lines`, `receipt_acceptance_extras` (миграция 0074) не удаляются и меняются один раз — из «ждёт» в итог (триггер). В накладной — блок «Принято на планшете»: кассир, расхождения, подпись (`GET /receipts/{id}/acceptance`, `GET /acceptances/{id}/signature`). Сторно и «Исправить» — как у любого прихода; у приёмки отметка «приход сторнирован» или «исправлен → № N».
