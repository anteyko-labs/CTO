# SPEC-30. Доработки по проверке на точке, часть 4 (21.10.2026)

Список заказчика от 21.10.2026, его ответы на вопросы и скриншоты отчёта смены из Умага. Решения — ADR-095 … ADR-103. Всё сделано 21.10.2026 (§15–17 — 22.10.2026, ADR-104, ADR-105); подробности — в разделах «Дополнено SPEC-30» спецификаций, которых касается пункт.

Отложено по решению заказчика: автоматический вход на кассе, правка суммы при закрытии смены владельцем. Поиск по штрихкодам из Умага уже есть (список старой программы, SPEC-20). Прибыль с баллами считается по-прежнему: баллы уменьшают прибыль в день, когда клиент их потратил (SPEC-08). По возврату поставщику заказчик пока не написал, что именно поменять.

## 1. Оплата «По счёту» (юрлицо)

Решение — ADR-095.

- Новый способ оплаты `invoice` — «По счёту»: юрлицо платит перечислением по выставленному счёту. Кнопка стоит рядом с остальными способами оплаты и есть в смешанной оплате.
- **Нужен клиент:** без выбранного клиента касса не проводит (сервер — 422 «По счёту платит клиент — выберите его»).
- **Деньги ложатся на безналичный счёт по умолчанию для «По счёту».** Он выбирается на экране «Счета» так же, как счета для карты и для QR (ADR-077). Пока не выбран — берётся счёт для карты. Счёт кассы наличных выбрать нельзя.
- **Комиссии банка нет:** это перечисление, а не терминал.
- **Без сети** способ доступен, как карта. **Возврат** по такому чеку уходит с того же счёта.
- **Где видно «По счёту» отдельной строкой:**
  - смена, «Поступления», «Чеки за день», отчёт смены (§7);
  - печать чека, кабинет юрлица;
  - лента и отчёты бота.

## 2. Вид замены и ставка мастеру — по услуге

Решение — ADR-096 (заменяет ставку замены за чек из ADR-027 и ADR-043 для новых чеков).

- **Справочник «Услуги».** У каждой услуги:
  - «Цена клиенту» — цена со своим маслом;
  - флажок «Бесплатно с нашим маслом»;
  - «Мастеру» — ставка мастеру за одну услугу.

  В списке все три колонки видны сразу. Правит владелец, как раньше.
- **Миграция:** флажок `free_with_oil` ставится действующим услугам, в названии которых есть «масл». Если в филиале нет ни одной услуги замены масла, заводятся «Замена масла в моторе» и «Замена масла в коробке»: цена 0, мастеру 30 сом, флажок включён. Цены владелец правит сам.
- **Чек «В сервис» без вида замены не проводится.** На кассе выбор «В сервис» сразу открывает выбор услуги: крупные кнопки, на каждой цена клиенту (или «бесплатно — масло наше») и «мастеру N с». Без услуги «Провести» не работает, сервер отвечает 422 «Выберите вид замены». Услуг в чеке может быть несколько.
- **Цена услуги в чеке считается на сервере:**
  - 0, если у услуги флажок «Бесплатно с нашим маслом» и в чеке есть масло (товар категории вида «масло», не подарок);
  - иначе — цена клиенту.

  Касса показывает то же и пересчитывает, когда масло добавили или убрали. Цена ниже этой — скидка (§4).
- **Начисления мастеру:**
  - мастеру начисляется сумма ставок услуг чека (количество × ставка), ставка фиксируется в строке чека;
  - прежняя ставка за чек из настройки `sales.oil_change_master_fee_tyiyn` новым чекам не начисляется;
  - чек без сети со старого устройства («в сервис» без услуг) проводится по старой ставке за чек, а владелец получает причину «чек «в сервис» без вида замены»;
  - возврат по чеку снимает ставки пропорционально, как сейчас.
- **Бот:**
  - в ленте владельца у чека «в сервис» видны услуги и сколько мастеру;
  - в кабинете работника заработок мастера — по услугам (вид, сколько раз, сумма);
  - отчёт «Замены по видам» (§10).
- **Экран «Продаваемые»** получает вкладку «Замены». По каждому виду услуги за период:
  - сколько раз;
  - сколько заплатили клиенты;
  - сколько начислено мастерам;
  - какие масла залиты в этих чеках (литры и канистры по каждому маслу).

  Это «разбивка по маслам» из списка заказчика. Себестоимости там нет.

- **Уточнено 26.10.2026 (ADR-112):** ставка мастеру по умолчанию — 30 сом за каждую услугу; новая услуга без ставки и услуги из выгрузки старой программы получают её, услугам со ставкой 0 она поставлена миграцией 0066; владелец меняет ставку в карточке услуги.

## 3. Чек «В сервис» — данные клиента обязательны

Решение — ADR-100.

- **Без чего чек «В сервис» не проводится:**
  - клиент: человек с именем и фамилией или фирма;
  - телефон клиента;
  - машина с госномером;
  - пробег.

  Касса отмечает недостающее звёздочкой и подсказкой у «Провести».
- **Сервер:** онлайн-чек без этих данных — 422 со списком недостающего. Чек без сети проводится, а владелец получает причину «в сервис без данных клиента: …».
- «Мастер рекомендовал» остаётся необязательным.

## 4. Скидка — только с правом

Решение — ADR-097.

- **Что считается скидкой:** цена строки ниже цены по каталогу. Это касается товара, розлива, веса и услуги (§2). Цена по каталогу — та, что сервер считает ценой строки, `list_price`.
- **Кто может:** владелец и администратор с правом «Скидка в чеке» (§5). Без права:
  - онлайн — 403 «Скидку ставит владелец»;
  - без сети — чек проводится, владелец получает причину «скидка без права: товар, цена, цена по каталогу».
- **Касса без права** не показывает карандаш правки цены.
- **Не скидка:** подарок по правилу, баллы и цена выше каталожной.

## 5. Права администраторов выбирает владелец

Решение — ADR-097.

- **Где:** «Настройки» → «Пользователи и права» → администратор → «Что можно». Флажки по группам. Владелец может всё, администратору включаются отдельные права.
- **Права:**

  | Ключ | Что разрешает | По умолчанию |
  |---|---|---|
  | `sale_return` | Возврат по чеку | да |
  | `sale_debt` | Продажа в долг | да |
  | `discount` | Скидка в чеке (§4) | нет |
  | `debt_payment` | Принять оплату долга клиента | да |
  | `cash_moves` | Внести, изъять, перевести деньги | да |
  | `expenses` | Расходы | да |
  | `payroll_pay` | Выплаты мастерам (§6) | да |
  | `receipts` | Приход товара, оплата поставщику, накладные по фото (§9) | да |
  | `stock_in` | Оприходование | да |
  | `supplier_returns` | Возврат поставщику | да |
  | `defects` | Отметка брака | да |
  | `revision` | Ревизия | да |
  | `oil_transfer` | Перелив масла (ADR-082) | нет |
  | `products` | Заводить и править товары и штрихкоды | да |
  | `clients` | Заводить и править клиентов и машины | да |
  | `battery_intake` | Приём аккумуляторов | да |
  | `old_debts` | Старые долги из тетради (SPEC-38, ADR-133), группа «Деньги» | нет |
  | `till_pay_fix` | Наличные ↔ QR в открытой смене (SPEC-37, ADR-149), группа «Деньги» | нет |

- **Миграция:** существующим администраторам выдаются все права со значением «да» по умолчанию, так что для них ничего не меняется, кроме скидки. Новому администратору права ставятся по умолчанию, владелец правит.
- **Проверка на сервере:** каждое действие администратора, которое сейчас разрешено, сервер сверяет со своим правом. Без права — 403 с названием права. Экраны прячут пункты меню и кнопки без права.
- **Не выдаются правом:** себестоимость, прибыль, маржа (инвариант 6), «Исправить» документов владельца (ADR-085), цены товаров (ADR-032), отмена перелива, начисления, бонусы, удержания.
- **Журнал:** изменение прав — запись `user.permissions`: кто, кому, что включено и что выключено.

### Дополнено задачей 003 (31.10.2026, Н8, ADR-151)

- **Где:** пункт меню «Пользователи и права» (у владельца, «Справочники») и «Настройки → Пользователи и права» — один экран; в «Сотрудниках» у владельца — ссылка туда же.
- **«Что можно»:** у каждой группы — «Включить всё» / «Выключить всё»; наборы «По умолчанию», «Только касса» (возврат, долг, оплата долга, клиенты), «Старший администратор» (всё, что выдаётся правом) и «Как у …» (права другого администратора этого филиала) — только расставляют флажки, сохраняет «Сохранить» (тем же `PUT /users/{id}/permissions`, `op_id`, журнал). Под каждым правом — «Открывает: …» (пункты меню и кнопки). Серый блок «Только у владельца — правом не выдаётся»: сводка и прибыль, себестоимость и закупочные суммы, безнал, уведомления и Телеграм владельца, «Исправить» и сторно, начисления и выплаты кассирам, ставка мастера, отмена перелива, цена литра, пользователи, филиалы и настройки (I13, I14). Счётчик «N из M».
- **Права доходят без перезагрузки:** клиент перечитывает `/auth/me` раз в 60 секунд, при возврате на вкладку и сразу после ответа 403 «Нет права: …»; меню и кнопки обновляются. Без сети остаётся прежнее.
- **Новые права** (всего 33 вместе с `till_pay_fix` задачи 003 Н1, по умолчанию 25):

  | Ключ | Группа | Что разрешает | По умолчанию |
  |---|---|---|---|
  | `view_sales` | Разделы | «Чеки» за прошлые дни (без права — только сегодня: `GET /sales?date=` не сегодня → 403) | да |
  | `view_debts` | Разделы | «Долги»: должники и долги поставщикам (`GET /debts/list`) | да |
  | `view_payroll` | Разделы | «Расчёт» (`GET /payroll/month`; `GET /payroll/day` — с этим правом или с `payroll_pay`, день нужен закрытию смены) | да |
  | `view_income` | Разделы | «Поступления» (`GET /reports/income`) | да |
  | `view_accounts` | Разделы | «Счета»: движения и итоги сейфов и счетов (`GET /cash/accounts/{id}`, `/summary`); движения кассы смены — без права (экран «Смена»); список счетов с остатками — без права (нужен кассе) | да |
  | `view_suppliers` | Разделы | «Поставщики»: поставки и накладные (`/suppliers/{id}/deliveries…`, `/supplies`; `/parties/{id}/invoices` — с этим правом или с `receipts`, оплата поставщику) | да |
  | `view_stock` | Разделы | «Остатки» и «Продаваемые» (`/products/list?group=category`, `/stock`, `/reports/top-products`, `/reports/service-kinds` — вкладка «Замены»; что брал один клиент — `party_id` — без права) | да |
  | `reconciliation` | Разделы | «Акт сверки» клиента и поставщика (`GET /parties/{id}/reconciliation`); кабинет юрлица и бот владельца — без изменений; без права документ о долге на кассе печатается без истории долга | да |
  | `payroll_view_all` | Деньги | «Расчёт → За месяц»: кассиры (без права администратору — только мастера, как «За день», ADR-122); выплачивает кассирам по-прежнему владелец | нет |
  | `employees` | Справочники | Сотрудники: заводить мастеров, переименовывать, отключать (`POST /employees`, `PATCH /employees/{id}`); кассира, телефон и PIN — владелец | да |
  | `services` | Справочники | Услуги: заводить и править (`POST /services`, `PATCH /services/{id}`); ставка мастера — владелец | да |
  | `prices` | Справочники | Цены товаров (общая и своя цена филиала, `PATCH /products/{id}/prices`) и цена услуги; каждое изменение — в уведомления «было → стало» с тем, кто менял | нет |
  | `products_archive` | Справочники | Убирать товар в архив и возвращать (`PATCH /products/{id}` с `archived`) | нет |

  Без права пункт меню и маршрут скрыты (прямой адрес уводит на кассу), сервер отвечает 403 «Нет права: <подпись>» (I12). Всегда у администратора: Касса, Смена, Клиенты, Товары, Настройки → Этикетки и Категории (по `products`). Сводка, Прибыль, Безнал, Уведомления — только владелец.
- **Ошибки закрыты заодно:** `GET /expenses` и `/expenses/summary` — по праву `expenses`, как пункт меню.
- **Миграция `0081`:** проверка списка прав дополняется новыми ключами (как 0074); существующим администраторам выдаются права «да» по умолчанию — сегодня ничего не пропадает; `prices`, `products_archive`, `payroll_view_all` не выдаются.
- **Логин и филиал администратора:** «Изменить» — поле «Логин» (занят — 409 «логин занят»; сеансы не обрываются) и у владельца нескольких филиалов — «Филиал» (только администратору, только открытый филиал — иначе 422). Права переходят в новый филиал той же операцией (I7, I16), чат Телеграма отвязывается (в нём запомнен прежний филиал). Журнал `user.update` — `old_login`, `old_branch_id` → `branch_id` (I5); уведомление «логин был …», «переведён в другой филиал».

### Дополнено задачей 005 (02.11.2026, Н1, ADR-{n1})

- **Личный вход сотрудника** — тот же администратор со своими правами: владелец заводит его в карточке сотрудника («Вход в программу»: логин, пароль, включить/отключить), права по умолчанию — как у нового администратора (25 из 33), правятся здесь же «Что можно». В строке пользователя — «сотрудник: <имя>», у такого входа нет выбора роли и филиала.
- **Права кассира смены (ADR-152)** урезают только вход без сотрудника (общий вход кассы); личный вход — по своим правам, на экране `cashierDenied` его не ограничивает.
- **Без права, для себя:** «Профиль» — сменить свой пароль (любой вход); «Мой заработок» (меню «Деньги», только у входа с сотрудником) — заработано, выплачено, должны, по дням и выплаты; право «Расчёт» для этого не нужно. Новых прав нет (по-прежнему 33).

## 6. Выплаты: администратор — только мастерам

- Администратор с правом `payroll_pay` выдаёт деньги только мастерам. Выплаты кассирам и остальным — только владелец. Сервер отвечает 403 «Кассиру выплачивает владелец».
- Окно закрытия смены показывает администратору к выплате только мастеров.

## 7. Отчёт смены, как в Умаге

- **Страница «Смена № N».** Открывается из «Смена» (текущая и прошлые смены) и из бота по ссылке. Вверху кассир, касса, время открытия и закрытия.
- **Вкладка «Обзор»:**
  - **Движение денег кассы смены:**
    - остаток на начало;
    - приход наличных: продажи наличными, оплаты долга покупателей, внесения, переводы в кассу, деньги от поставщиков;
    - расход: оплаты накладных, возвраты покупателям, расходы, выплаты, изъятия, переводы из кассы (сдача в сейф и прочее);
    - остаток на конец, «должно быть», разница (излишек или недостача).
  - **Выручка за смену:** продажи, возвраты, итог; по способам оплаты — наличные, карта / QR банка, QR владельцу, по счёту, в долг, баллами, аккумулятором.
  - **Только владельцу:** себестоимость проданного и возвращённого, валовая прибыль. Администратору сервер их не отдаёт.
  - **Сравнение с прошлой сменой:** выручка, разница в сомах и процентах. Смена ещё идёт — прошлая берётся за то же время от открытия (`compare.same_time`, подпись «за то же время от открытия»; в боте — «к смене № N за то же время»).
  - **Продажи по часам** — столбики, без новой библиотеки; сумма коротко над столбиком («2,5 т»).
- **Вкладка «Продажи»:**
  - итоги: продажи, получено, баллами, в долг;
  - поиск по номеру чека, отбор по способу оплаты;
  - колонки: №, время, способ, счёт, кассир, клиент, сумма. Строка открывает чек.
- **Вкладка «Возвраты»** — то же для возвратов.
- **Вкладка «Закупки»:** приходы за время смены, у каждого — сколько оплачено из кассы смены.
- **Вкладка «Денежные операции»:**
  - итоги: внесения, переводы в кассу, оплаты долга, расходы, выплаты, изъятия, переводы из кассы;
  - список: время, вид (у расхода — статья), сумма, счёт, пользователь, контрагент или сотрудник, комментарий.; по умолчанию сначала поздние, кнопка «Сначала поздние ⇅» / «Сначала ранние ⇅» показывает текущий порядок.
- **Вкладка «Долги»:** продажи в долг и оплаты долга за смену — клиент, чек, сумма.
- **Вкладка «Выплаты»:** кому сколько выдано за смену — сотрудник, сумма, за что, с какого счёта.
- **Вкладка «Отменённые товары»** — §8.
- **Бот:** в «Сменах» отчёт смены коротко:
  - движение денег и разница;
  - выручка по способам;
  - кому сколько выплачено;
  - оплаты долгов, расходы, переводы;
  - отменённые товары (сколько и на какую сумму);
  - владельцу ещё валовая.

## 8. Отменённые товары

Решение — ADR-099.

- **Что записывается.** Каждая строка, удалённая из чека до проведения:
  - удаление крестиком;
  - «Очистить»;
  - удаление отложенного чека.

  У записи: время, пользователь, кассир смены, смена, товар или услуга, количество, сумма. Если после удаления чек провели, запись связывается с чеком. Уменьшение количества кнопкой «−» не записывается.
- **Как уходит на сервер.** Удалённые строки уходят вместе с проведённым чеком (`removed_lines`). Строки чека, который так и не провели («Очистить», удаление отложенного), — отдельной операцией `POST /sales/cancelled-lines {op_id, shift_id?, lines}`. Без сети они ложатся в очередь устройства, как чеки.
- **Где видно:** отчёт смены (§7) и бот. Администратор видит без себестоимости.

## 9. Накладная по фото

Решение — ADR-098.

- **Бот.** Владелец присылает в бот фото накладной: фото или картинку файлом, до 10 МБ. Бот:
  1. отвечает «Принял, распознаю…»;
  2. сохраняет фото (ADR-080);
  3. распознаёт его через внешний сервис по ключу `ASSISTANT_API_KEY`;
  4. отвечает: «Накладная распознана: поставщик, N строк, итого X. Откройте «Приход» → «Накладные по фото»».

  Проводить приход из бота нельзя. Не распознал — фото сохраняется черновиком без строк, бот отвечает «Не удалось распознать — заполните вручную». Без ключа — «Распознавание накладных не настроено».
- **«Приход» в программе:**
  - блок «Накладные по фото: N» и кнопка «Заполнить по фото» в «Новом приходе» (загрузить файл или снять камерой) — то же распознавание;
  - открыть черновик — «Новый приход» заполнен.
- **Как заполняется «Новый приход»:**
  - **Поставщик** — по ИНН или названию. Не найден — поле пустое и подсказка «В накладной: …».
  - **Товар строки:**
    - штрихкод или артикул совпал точно — товар выбран;
    - название похоже (сходство ≥ 0,4) — товар выбран с отметкой «проверьте»;
    - иначе строка «не найден — выберите товар или заведите новый» (со списком старой программы).
  - **Количество и цена** — из накладной. Литры масла переводятся в канистры, если товар — канистра.
  - **Итог:** итог накладной сверяется с суммой строк, расхождение подсвечивается.
- **После проведения:** фото прикрепляется к приходу, черновик отмечается использованным. «Убрать» удаляет черновик.
- **Кто может:**
  - в боте — чаты владельца;
  - в программе — владелец и администратор с правом `receipts`.
- **Ограничения:** не больше 20 распознаваний в час на филиал (общий счётчик с вопросами боту). Распознанное — только подсказка, проводит человек.

### Дополнено задачей 002 (30.10.2026)

- **«Ещё фото» (П2).** В открытом черновике «Нового прихода» — кнопка «Ещё фото» (камера или файл): вторая страница или ещё одна накладная. Фото распознаётся и дописывает тот же черновик; его строки добавляются в этот же приход. Строка с товаром, который уже есть в приходе, — отметка «уже есть в приходе — сложить?»: «Сложить» (та же единица строки и та же цена, иначе — подсказка исправить) или «Оставить отдельно». Другой поставщик или № накладной у нового фото — предупреждение над приходом, не отказ. Поставщик и номер берутся с первого фото. Не больше 10 фото в черновике. При проведении все фото переходят к накладной. В «Накладных по фото» черновик один, с числом фото. «Убрать» убирает его вместе с дописанными фото.
- **Варианты товара (П3).** У строки «проверьте» под названием — до трёх других похожих товаров: название, артикул, остаток, цена прошлого прихода. Выбор — одним нажатием, количество и цена пересчитываются из строки накладной. Если по штрихкоду или артикулу нашлось два товара и больше, строка не считается «без товара»: все совпадения показываются на выбор («с этим кодом несколько товаров — выберите нужный»).
- **Запомненный выбор (П3).** Выбранный для строки товар запоминается: «название строки у поставщика → товар». Источник выбора — вариант, «Выбрать товар» или «Новый товар». Запоминается только при выбранном поставщике. В следующей накладной этого поставщика такая строка совпадает точно, с отметкой «запомнено». Название сравнивается без регистра и лишних пробелов. Новый выбор заменяет прежний. Запоминает филиал (I16): у филиалов свои приёмщики и свои привычки выбора. Поставщики и каталог при этом общие. Список — в карточке поставщика, вкладка «Строки накладных», с кнопкой «Забыть» (право «Товары» или владелец). Запоминать может владелец и администратор с правом «Приход товара».
- **Найти накладную (П6).** В «Приходе» — строка поиска. Ищет по № накладной поставщика, поставщику, названию товара и сумме: сумма вводится в сомах («1 234,50») и сравнивается с итогом в тыйынах. С поиском период не действует, поиск идёт за всё время. Без поиска период — последние 30 дней, как раньше. Ещё есть отбор «с фото». В строке накладной с фото — значок фото: нажатие открывает накладную сразу с фото на весь экран. В накладной снимки тоже открываются на весь экран, с листанием. Филиал видит только свои приходы.

## 10. Бот: полная книжка, замены по видам

- **Масляная книжка клиента** — вся история по каждой машине, от новой к старой. В каждой записи:
  - дата и пробег;
  - справа масло: название, литры или канистры;
  - фильтры и прочее из чека;
  - мастер;
  - что рекомендовал мастер.

  Длинная книжка делится на несколько сообщений.
- **Отчёт владельцу «Замены по видам»** за период — как вкладка «Замены» (§2).
- **Кабинет работника:** заработок мастера по услугам (§2).

## 11. «Товары» и «Остатки» — один экран

- В сводке владельца — карточка «Баллы у клиентов».
- В боте владельца — строка в «Клиентах».

## 13. Касса: поиск, подарок, «Через сколько менять», оплата долга

- **Enter в поиске** выбирает только из найденного по всему набранному тексту. Пока найдено по началу текста, Enter ждёт ответа на полный текст.

  Причина: 21.10.2026 кассир набрал моторное масло, нажал Enter, и в чек встал воздушный фильтр — первый из найденного по первым буквам.
- **Исправлено 26.10.2026 — сканер после касания кнопки.** Жалоба: «в чеке постоянно добавляет воздушный фильтр». Касание плитки или кнопки кассы оставляло фокус на ней: знаки кода терялись, а `Enter` сканера нажимал кнопку ещё раз. Плитка или «+» у строки фильтра добавляли фильтр вместо отсканированного масла, «Точно очистить?» стирал чек, «Печать чека» печатал прошлый чек, после крестика скан пропадал, код в поле количества становился количеством, а в «Получено» — суммой, и `Enter` проводил чек.
  - Теперь на кассе знак, набранный не в поле ввода, переводит фокус в поиск товара — и код, и `Enter` сканера уходят туда.
  - В поле ввода экрана (количество, цена, «Получено», пробег, комментарий, поиск клиента; и за окном подарка, вставшим, пока фокус в количестве) знаки придерживаются на 60 мс: 6 и больше знаков быстрее человека и `Enter` — это скан, код уходит в поиск, поле и чек не меняются; иначе знаки встают в поле, как набраны.
  - Плитки не забирают фокус, после касания плитки фокус — в поиске. Окно открыто, а фокус за ним — `Enter` и пробел гасятся.
  - Скан, начатый, пока ищется предыдущий код, не дописывается к нему: поле освобождается, как только код ушёл на поиск.
- **Исправлено 26.10.2026 — Enter берёт товар, только если выбор однозначен.** Enter (и «Enter ↵» экранной клавиатуры) клал первую из нескольких найденных строк, а первым по названию почти всегда шёл «Фильтр воздушный …» (поиск фильтра по машине: «в» раньше «м» и «с»); короткий код Умага («1024» у масла на розлив) искался как текст — и вставал «E1024L01 ВОЗДУШКА РОБОТ».
  - Enter берёт строку, только если: её выбрали стрелками; найдена одна строка; ровно одна строка совпала по коду или артикулу точно.
  - Найдено несколько — в чек ничего, над списком «Найдено N — выберите нужную строку»; строку выбирают касанием или стрелками и Enter.
  - Строка из цифр короче 6 знаков (доп. код Умага) ищется только как код: нет такого кода — «Код N не найден — выберите строку в списке», товар с этими цифрами в названии не берётся.
  - В режиме кассы список найденного кончается над экранной клавиатурой и ярлыком набранного; ярлык пустеет, когда поиск очищен после выбора.
  - Правило одно для всех экранов с поиском товара: касса, приход, ревизия, перелив, брак, возврат, плитки.
- **Исправлено 26.10.2026 — «Вернуть» под пальцем.** В режиме кассы после крестика над списком вставала полоса «Удалено: … Вернуть» и сдвигала строки: «Вернуть» оказывалась на месте крестика первой строки, и второе касание (двойное или «удалить следующую») возвращало удалённый фильтр. Теперь плашка «Вернуть» — поверх списка слева внизу, над названиями строк: строки не сдвигаются, крестик, «−» и «+» открыты. Второе касание крестика в первые 0,35 с после удаления не принимается — двойное касание не удаляет и следующую строку.
- **Порядок найденного:** точный штрихкод или артикул, потом название с начала, потом остальное, внутри — по названию.
- **Строка подарка** показывает остаток товара, а не «undefined».
- **Поле «Через сколько менять» убирается** с кассы. Книжка берёт срок из настроек, как до SPEC-29 §23.
- **Окно «Оплата долга» на кассе:**
  - крупное: широкое окно, крупные строки должников, сумма долга крупно;
  - если в чеке выбран клиент с долгом, окно сразу открывается на нём.

## 14. Режим кассы: клавиатура по кнопке

Решение — ADR-101.

- Экранная клавиатура скрыта и сама не появляется. Открывает её кнопка «⌨ Клавиатура» в полосе режима кассы и у поля в фокусе. «Скрыть» на клавиатуре прячет её.
- **Цифровые поля** получают цифровую клавиатуру, как сейчас.
- **Текстовые поля** (поиск, имя, госномер, комментарий) — полную клавиатуру: русские буквы, переключение на латиницу, ряд цифр, пробел, стереть, Enter.
- Открытая клавиатура остаётся открытой при переходе между полями, пока её не скроют.

## 15. Бесплатная замена — только с маслом того же вида

Решение заказчика 22.10.2026 по итогам проверки вживую — ADR-104 (уточняет ADR-096).

- У услуги с флажком «Бесплатно с нашим маслом» владелец выбирает **категорию масла** (например «Моторные масла» для замены в моторе, «Трансмиссионные масла» — в коробке). Миграция ставит категорию по названию услуги («АКПП», «короб», «трансмис» → трансмиссионная категория; иначе — моторная), если такие категории есть; без категории флажок не действует.
- Услуга бесплатна, только если в чеке нашего масла этой категории (не подарок) не меньше одной канистры — объёма наименьшей канистры среди этих строк. Иначе — цена клиенту. Считает сервер, касса показывает то же.
- **Возврат масла:** если после возврата масла этой категории в чеке остаётся меньше канистры, а услуга была бесплатной и не возвращается, из суммы возврата удерживается цена услуги (по количеству услуги). В возврате это видно строкой «Удержано за замену: N с»; в прибыль и в «Замены» удержанное идёт как оплата услуги.
- Флажки услуг рабочей базы, поставленные по слову «масл», владелец проверяет сам на экране «Услуги».

## 16. Возврат без чека — только владелец

Решение заказчика 22.10.2026 — ADR-105.

- «Чеки» → «Возврат без чека» (и в режиме кассы у владельца): товары (поиск, скан), количество, сумма строки (по умолчанию текущая цена продажи), как вернуть деньги (наличные — при открытой смене, карта / QR / по счёту — со счёта), клиент необязательно, причина обязательна.
- Товар возвращается на склад по текущей средней себестоимости; выручка уменьшается на сумму возврата, себестоимость — на стоимость вернувшегося товара. 2 % кассиру и ставки мастеру не трогаются (исходного чека нет).
- Только владелец (сервер — 403 для администратора); журнал, уведомление владельцу; в отчёте смены «Возвраты» — «Без чека»; в «Чеках за день» — отметка «без чека».

## 17. Режим кассы: данные замены — слева под чеком

- На 1366 × 768 при чеке «В сервис» мастер, вид замены, клиент, машина, пробег и «Мастер рекомендовал» стоят в левой колонке под строками чека (строки чека прокручиваются в своей части), правая колонка — тип, итог, оплата и «Провести». Страница не прокручивается; у полей видны подписи.

## Дополнено задачей 003 (31.10.2026): права кассира без входа (к §5)

Решение — ADR-152.

- **Где:** «Сотрудники» → кассир → «Что можно на кассе» (только владелец). Флажки прав групп «Касса» и «Деньги»; по умолчанию всё отмечено — «как у входа». «Как у входа» — снять все ограничения одной кнопкой.
- **Как действует:** пока открыта смена этого кассира, у вошедшего администратора — пересечение: можно только то, что можно входу **и** не снято у кассира. Кассир не получает больше, чем дано входу. Владельца не ограничивает. Закрытая смена — без ограничений.
- **Отказ:** 403 «Нет права у кассира <имя>: <подпись права>». Без права у входа — прежний ответ («Нет права: …», «Скидку ставит владелец»). Без сети чек проводится, владелец получает причину «скидка без права у кассира …» / «продажа в долг без права у кассира …» (I10).
- **Касса:** снятые права прячут свои кнопки (по `cashier_denied` открытой смены в `GET /shifts/current`); проверяет сервер.
- **API:** `GET /api/v1/employees/{id}/permissions` → `{employee_id, full_name, keys, denied}`; `PUT` `{op_id, denied}` — только владелец, ключи только групп «Касса» и «Деньги» (иначе 422), не кассиру — 422; повтор `op_id` — тот же ответ.
- **Журнал:** `employee.permissions` — что снято (`off`), что возвращено (`on`), было → стало.
- **Проверка:** `server/tests/object_rights.rs` (пересечение, имя кассира в отказе, смена другого кассира, владелец, не расширяет права входа, `op_id`, 403 администратору); `web/src/lib/permissions.test.ts`; e2e `web/e2e/object-rights.spec.ts`.

## Дополнено задачей 003 (31.10.2026): документы склада по праву и цена новой услуги (к §5, ADR-160)

- **Списки и карточки документов склада — по праву своего пункта меню (I12):** `GET /receipts` и `GET /receipts/{id}` — «Приход товара» (`receipts`); `GET /stock-ins`, `GET /stock-ins/{id}` и `GET /receipts?kind=stock_in` — «Оприходование» (`stock_in`); `GET /supplier-returns`, `GET /supplier-returns/{id}` и `GET /supplier-returns/price` — «Возврат поставщику» (`supplier_returns`). `GET /receipts?kind=all` отдаёт то, на что есть право (накладные и/или оприходования); без обоих — 403 «Нет права: Приход товара».
