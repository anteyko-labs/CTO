# SPEC-09. Касса без сети

## Задача

Продажа, оплата, поиск товара и печать чека работают без интернета. Чеки копятся на устройстве и уходят на сервер при появлении связи; сервер решает окончательно (инварианты 9–11).

## Условия связи

Со слов владельца связь пропадает примерно на час, резервный модем подключают в течение пяти минут. Значит очередь должна переживать часы, а не сутки, и чек почти всегда уходит в тот же учётный день. Из этого следуют два ограничения: снимок каталога устаревает заметно уже через пару часов, а чек с временем устройства старше двух дней считается не перебоем связи, а давно не включённым устройством и попадает в день проведения (SPEC-08).

## Офлайн доступно / недоступно

| Офлайн | Только с сетью |
| --- | --- |
| Поиск и сканирование товара, продажа, оплата, печать чека | Возврат, смена, внесение и изъятие, расходы, выплаты, приход, справочники, цены, отчёты |

Экраны «только с сетью» без связи показывают «Нет связи с сервером» и не дают отправить форму.

## Библиотеки (нужен ADR)

- `vite-plugin-pwa` (Workbox) — Service Worker, предварительное кэширование оболочки приложения, манифест для установки.
- `idb` — тонкая обёртка IndexedDB с промисами.

Обе соответствуют стеку (`docs/tier-0/stack.md`: Workbox + IndexedDB). Блокировка синхронизации между вкладками — встроенный Web Locks API, без библиотек.

## Снимок каталога

`GET /offline/snapshot` (с `ETag`, ответ 304 без изменений) →
```
{ version, server_time,
  products:  [{id, name, brand, article, category_id, category_kind, unit, container_ml,
               barcodes[], sale_price_tyiyn, pour_price_per_l_tyiyn (от цены канистры, ADR-074), stock_qty}],
  categories: [{id, name, kind}], employees (активные), services (активные: id, name, price_tyiyn,
  master_fee_tyiyn), receipt_settings,
  clients: [{id, kind, name, phone, inn, credit_limit_tyiyn, balance_tyiyn,
             contacts: [{id, full_name, position}], vehicles: [{id, plate, brand, model, mileage_unit}]}],
  bank_accounts: [{id, name, default_card, default_transfer}] }
                                     -- действующие безналичные счета (ADR-076, ADR-077)
```

`category_kind` нужен вопросу «Это замена масла?» без сети (SPEC-29 §18). `clients` — действующие покупатели филиала с долгом или авансом, с покупками за 180 дней или с машинами, не больше 1000 (сначала должники, потом недавние): без связи касса находит клиента по имени, телефону, ПИН/ИНН и госномеру, выбирает машину и «кто приехал» для долга и замены масла; единица пробега машины — из снимка. Услуги и сотрудники (кассиры и мастера) без связи берутся из снимка — и после перезагрузки страницы (ADR-093).
Без себестоимости и стоимости остатка для любой роли — касса их не использует.

`bank_accounts` — банки для карты и QR без сети (SPEC-28 §5): действующие, с отметками «по умолчанию для карты» и «по умолчанию для перевода» (ADR-077); счета «только владелец» — только владельцу. Касса берёт список с сервера, без связи — из снимка: у карты заранее выбран счёт по умолчанию для карты, у перевода — для перевода, кассир может выбрать другой банк для этого чека; выбранный банк уходит в чеке как `payments[].account_id`. Сервер проверяет счёт при проведении: если за время в очереди его убрали в архив (или его нет, или он не банк, или он «только владелец» для администратора), чек без сети не отклоняется — деньги ложатся на счёт по умолчанию для этого способа оплаты, а причина «счёт «X» в архиве — оплата записана на «Счёт»» уходит владельцу в `sale.offline_bypass` (ADR-062, ADR-076). Онлайн-чек с таким счётом — 422.

Клиент хранит снимок в IndexedDB и обновляет: при входе, при открытии кассы, каждые 10 минут со связью и сразу при появлении связи. Ответ 304 подтверждает снимок: время снимка (`saved_at`) обновляется, предупреждение «устарел» уходит. После своего чека без сети уменьшает `stock_qty` в снимке локально. Снимок старше 2 часов — предупреждение на экране кассы: цены и остатки могли измениться.

«Есть связь» для кассы — сервер отвечает, а не только `navigator.onLine`: признак обновляется по каждому запросу (ответ сервера — есть, обрыв или 502/503/504 — нет); пока сервера нет, касса каждые 30 с проверяет его запросом снимка. Баллы и аккумулятор в оплату доступны только при связи с сервером (ADR-093).

Поиск офлайн: точное совпадение штрихкода по индексу, текст — по названию, бренду, артикулу в снимке.

## Очередь отправки

Каждый чек, со связью и без, сначала записывается в очередь IndexedDB `outbox`, затем отправляется. Один путь кода: обрыв связи посреди запроса не теряет чек, повтор безопасен благодаря `op_id` (ADR-013).

```
outbox item: { op_id, user_id, user_name, created_at, body (POST /sales), temp_no,
               status: pending | sending | done | rejected, attempts, last_error, server_number?,
               next_try_at?, claimed_by?, receipt (чек для печати: строки с названиями, итог, оплаты) }
```

`op_id` — UUID v7 с устройства (время в начале, ADR-093).

- `temp_no` — «Ч-<4 символа устройства>-<локальный номер>», печатается на чеке, пока нет серверного номера.
- Тело запроса из очереди дополняется `offline: true` и `seen_list_price_tyiyn` у каждой строки — прайсовая цена из снимка. Живая отправка с кассы признака не ставит: если сервер ответил отказом, кассир видит ошибку, а покупатель ещё у кассы.

## Синхронизация

```
запуск: при старте приложения, по событию online (без пауз), каждые 30 с при непустой очереди
под navigator.locks 'outbox-sync':
  для item в порядке created_at, только user_id = вошедший пользователь (или взятые владельцем),
  кроме ждущих паузы (next_try_at в будущем; «Отправить сейчас» и появление сети паузу не ждут):
     POST /sales
     2xx  → done, сохранить серверный номер
     401  → остановить, показать вход; очередь сохраняется
     409      → сначала GET /sales/by-op/{op_id}: чек уже проведён (например, от другого
                пользователя этой кассы) → done с его номером; иначе повтор до 5 раз, потом как 422
     422 и прочие 4xx → POST /sales/offline-rejected; принят → rejected, last_error;
                ответ 409 (отказ уже сообщён, например другим пользователем кассы) → rejected,
                если чек при этом проведён → done; не принят → чек pending с паузой, отчёт
                повторится (ADR-062), следующие чеки идут дальше
     5xx  → attempts+1, пауза 30 с → 1 мин → 5 мин (максимум) для этого чека, следующие идут дальше
     сеть → attempts+1, та же пауза, остановить: без связи не уйдут и остальные
```

Ни один чек не держит очередь навсегда: отказ сервера и сбой по одному чеку дают паузу только этому чеку (ADR-093).

`GET /sales/by-op/{op_id}` — номер проведённого чека с этим `op_id` в филиале пользователя (любой вошедший пользователь филиала), иначе 404. При онлайн-отправке с кассы ответ 5xx или 401 чек тоже не удаляет: он остаётся в очереди и уходит сам (ADR-062).

Записи `done` хранятся 7 дней для повторной печати, потом удаляются при запуске приложения. Окно очереди печатает любой чек (временный номер, после отправки — серверный).

## Сервер: приём офлайн-чека

Изменения в `POST /sales` (SPEC-04) при `offline: true` и указанном `client_time` (ADR-093: давность не проверяется — чек может уйти из очереди и через секунды после продажи; признак только смягчает проверки, всё смягчённое уходит владельцу в `sale.offline_bypass`, права на счета и скрытые данные проверяются как онлайн):
- Сотрудник, товар, услуга должны существовать, но могут быть уже неактивными или в архиве: продажа на кассе уже состоялась.
- Всё, что онлайн-продажа отклонила бы, — товар в архиве, отключённые сотрудник, клиент, услуга или правило подарка, долг отключённому клиенту, учётный день раньше сегодняшнего (задним числом, при любой оплате), убранная клиентом машина (она возвращается в список), — проводится, а владелец получает одно уведомление `sale.offline_bypass` со списком причин (ADR-062).
- Журнал `sale.price_override` пишется, если `unit_price ≠ seen_list_price` (цена изменена кассиром), а не при расхождении с текущим прайсом. `seen_list_price_tyiyn` учитывается только у чека без сети; у онлайн-чека правка цены определяется по прайсу сервера (ADR-062). Расхождение `seen_list_price` с текущим прайсом пишется отдельным `sale.stale_price` — владельцу видно, что продали по старой цене.
- `business_date` по правилу SPEC-08; смена — открытая в момент проведения (SPEC-05).
- Кассир чека без сети (ADR-071, SPEC-27): если в момент чека на устройстве (`client_time`) на кассе была открыта смена (с учётом её закрытий и переоткрытий до этого момента), кассир чека — кассир той смены, присланный `cashier_id` не учитывается. Если смены в тот момент не было — остаётся кассир, выбранный на устройстве. Касса при открытой смене кассира не спрашивает и запоминает кассира смены на устройстве: пропала связь — чек уходит с ним; без смены выбор кассира помнится на устройстве до открытия смены. Последняя известная смена (номер, кассир) хранится на устройстве и без связи не сбрасывается, в том числе после перезагрузки страницы — касса не начинает спрашивать кассира посреди смены; напечатанный чек без сети называет кассира (ADR-093).
- Минус остатка — проводим и помечаем товар (инвариант 10, уже реализовано).
- Пробег — любое число: слишком большое, дробное или строкой не роняет чек ошибкой формата («неверный формат запроса»); вне диапазона 0–5 000 000 онлайн — 422 с понятной причиной, без сети — чек проводится без пробега, причина владельцу (ADR-090, ADR-093). Поле пробега на кассе — не больше 7 цифр.
- Время устройства расходится с сервером больше чем на 2 дня (или впереди больше чем на 5 минут) — чек ложится в день проведения (SPEC-08), владельцу причина «проверьте часы кассы» в `sale.offline_bypass`.
- Цена ниже закупочной не отклоняет чек: строки пишутся в `sale.below_cost`, владелец получает уведомление (ADR-042). Признак `offline: true` ставит фоновая отправка очереди.
- В `audit sale.post` — `offline`, `client_time`, задержка отправки.

Отклонённый чек не исчезает молча: `POST /sales/offline-rejected {op_id, body, error}` пишет его в журнал (`sale.offline_rejected`) и в список «Требуют внимания» у владельца. Повтор отчёта о том же `op_id` — от любого пользователя филиала — возвращает прежний ответ, а не 409. Удалить такой чек из очереди устройства можно только после этой записи.

На кассе отклонённые чеки видны (ADR-093): полоса над экраном «отклонено сервером: N — разберите» не прячется, пока они есть; в окне очереди — список: временный номер, время, сумма, строки, причина; «Распечатать» и «Убрать» (с подтверждением «Точно убрать?»). Владелец о них уже знает из уведомления.

## Чеки другого пользователя

Каждая запись очереди помнит, кто пробил чек (`user_id`, `user_name`). Очередь отправляет только чеки вошедшего пользователя: чек не уходит молча от чужого имени. Если на устройстве есть неотправленные чеки другого пользователя, касса показывает «N чеков пользователя <имя> ждут его входа». Владелец может нажать «Отправить от себя»: чек уходит с `claimed_user_id`, сервер проводит его от владельца и записывает в журнал `sale.post` `data.claimed_user_id` и `data.claimed_user_name`. `claimed_user_id` другого пользователя от не-владельца — 403 (ADR-093). Записи без `user_id` (до ADR-093) считаются общими.

Выход из системы не очищает очередь. При неотправленных чеках этого пользователя или без связи — окно «Выйти из программы?»: «N чеков ещё не отправлены… останутся на этом устройстве и уйдут, когда вы снова войдёте», «Нет связи с сервером: войти снова получится только при связи»; кнопки «Остаться» и «Выйти, чеки останутся на устройстве».

## Клиент

- В шапке индикатор: «В сети» / «Нет сети», число неотправленных чеков, время снимка. Нажатие открывает очередь: статусы, ошибки, повторная печать, «Отправить сейчас».
- Касса без сети работает так же, как с сетью; после проведения — `temp_no` и печать.
- При старте запрашивается `navigator.storage.persist()`, чтобы браузер не очистил очередь. Браузер отказал — касса показывает предупреждение «браузер может стереть неотправленные чеки — разрешите хранение» (ADR-062).
- Касса открывается только по HTTPS или `localhost`: без этого браузер не включает Service Worker и офлайна не будет. Адрес внутри точки обеспечивает развёртывание (ADR-025).
- Обновление Service Worker: «Доступна новая версия — обновить», без автоматической перезагрузки посреди чека. Само обновление применяется только на экране кассы с пустым чеком и без открытого окна; на остальных экранах — только плашка (ADR-059). Service Worker регистрируется и на экране входа.
- Закрытие смены на устройстве, где в очереди есть неотправленные чеки, — предупреждение «N чеков ещё не отправлены — дождитесь связи»; закрыть можно только отметкой «закрыть всё равно». Если наличный чек без сети пришёл, когда его деньги уже не попадут в пересчёт, — уведомление владельцу `sale.offline_after_close` «Чек без сети пришёл после пересчёта смены № N» (ADR-059). Смен в день несколько (ADR-071), поэтому смена ищется по времени чека, а не по учётному дню: смена, открытая в момент чека, если она с тех пор закрыта; если смены в тот момент не было — первая смена, открытая после чека, если при её открытии кассу пересчитали или она уже закрыта. Чек в смену, которая ещё открыта, уведомления не даёт.

## Дополнено SPEC-30 (21.10.2026)

В очереди устройства, кроме чеков, лежат записи с адресом (`path`) — отменённые строки (`POST /sales/cancelled-lines`, SPEC-30 §8). Уходят той же отправкой, повтор безопасен по `op_id`; принятая или отклонённая по существу запись удаляется; экраны очереди и подсчёт неотправленных чеков их не учитывают.

## Критерии приёмки

- [ ] Playwright: сеть выключена (`context.setOffline(true)`) → товар находится сканом и поиском, чек проводится, печатается с `temp_no`.
- [ ] Сеть включена → чек уходит, получает номер, виден в «Чеках за день» на сервере.
- [ ] Обрыв после записи на сервере, до ответа → повтор не создаёт дубль.
- [ ] Офлайн-продажа сверх остатка → проведена, товар помечен.
- [ ] Сотрудник деактивирован, пока чек ждал → офлайн-чек проведён.
- [ ] Цена изменена в прайсе, пока чек ждал → чек по старой цене, `sale.stale_price` в журнале, `price_override` нет.
- [ ] Снимку больше 2 часов → на экране кассы предупреждение.
- [x] Перезагрузка страницы и браузера без сети → очередь сохранена, касса открывается, смена и кассир те же, мастер, клиент и машина выбираются из снимка (`offline-queue.spec.ts`).
- [x] Пробег с лишними цифрами без сети не теряет чек: проведён без пробега с причиной у владельца; онлайн — 422 с причиной, а не «неверный формат» (`offline_queue_rules_adr_093`, `offline-queue.spec.ts`).
- [x] Чек из очереди через секунды после продажи — чек без сети (старая цена — `sale.stale_price`, не `price_override`) (`offline_queue_rules_adr_093`).
- [x] Отклонённый сервером чек виден на кассе списком с причиной, печатается и убирается с подтверждением (`offline-queue.spec.ts`); повторный отчёт об отказе от другого пользователя — не 409.
- [x] Чужой чек: администратор от себя не отправит (403), владелец — с `claimed_user_id` в журнале (`offline_queue_rules_adr_093`).
- [ ] Две вкладки не отправляют один чек одновременно.
- [ ] Снимок не содержит себестоимости ни для владельца, ни для администратора.
- [x] Снимок содержит действующие безналичные счета без архивных и чужих; чек без сети на архивный банк проводится на счёт по умолчанию с причиной у владельца, онлайн — 422 (`card_sale_goes_to_chosen_bank_with_fee_and_refund_returns_there`).
- [x] Снимок несёт обе отметки: «Оптима» — по умолчанию для карты, «Карта владельца» — для перевода; касса без сети выбирает по ним тот же счёт, что сервер (`bank_fee_per_account_and_default_bank_per_method`, `accounts.test.ts`).

## Решения для ADR

- Библиотеки `vite-plugin-pwa` и `idb`.
- Все чеки идут через очередь; офлайн-чек принимается с неактивными справочниками; отправка чужих чеков владельцем.
- Очередь по пользователям, паузы по чеку, признак «без сети» без проверки давности, снимок с клиентами и услугами — ADR-093.
