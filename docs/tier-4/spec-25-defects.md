# SPEC-25. Брак: списание и возврат поставщику

## Задача

Бракованный товар (течёт канистра, битый фильтр, не тот размер) не должен продаваться и не должен висеть в остатке. Администратор отмечает брак, владелец решает его судьбу: списать в убыток или вернуть поставщику. Поставщик за возврат даёт новый товар, скидку на следующий приход (то же, что вычесть из нашего долга ему) или деньги.

## Отметить брак (администратор или владелец)

- «Склад → товар → В брак»: количество (шт, мл или г — как у товара), причина (обязательно), поставщик (по умолчанию — из последнего прихода товара, можно сменить или оставить пустым).
- Товар уходит из продаваемого остатка движением `defect` по средней себестоимости (инвариант 2). Стоимость фиксируется в записи брака.
- Остатка меньше количества — отказ (брак отмечается только из того, что есть).
- Владельцу уведомление «В брак: Totachi 0W-20 4 л × 1, 1 450 с — течёт канистра».
- Запись брака ждёт решения владельца: экран «Брак» (вкладка на «Складе») — ожидают решения, решённые.

## Решение владельца

| Решение | Склад | Деньги и долги | Прибыль |
|---|---|---|---|
| **Списать** | ничего (товар уже вне остатка) | — | убыток = стоимость брака, строка «Списание брака» |
| **Вернуть → новый товар** | приход того же товара на то же количество по стоимости брака (движение `defect_replace`) | — | 0 |
| **Вернуть → скидка / из долга** | — | поставщик должен нам сумму возмещения: запись в журнале долга поставщика; при следующей накладной в долг сумма зачитывается сама (баланс поставщика) | разница «стоимость − возмещение» — убыток, если возмещение меньше |
| **Вернуть → деньгами** | — | поступление в выбранную кассу (`supplier_refund`); администратору нельзя, решение только владельца | разница — убыток или доход |

- Сумма возмещения по умолчанию = стоимость брака, владелец может изменить (поставщик дал меньше или больше). Разница идёт в прибыль строкой «Брак: разница возмещения».
- Новый товар можно получить и меньшим количеством — тогда недостающее списывается в убыток той же операцией.
- Решение — одна операция, одна транзакция, с `op_id`. Отменить решение — сторно со ссылкой (владелец), запись брака возвращается в «ожидает решения».
- Брак можно отметить и снять отметку (вернуть в продажу) до решения владельца — сторно отметки, товар возвращается в остаток по той же стоимости.

## Где видно

- Экран «Брак»: товар, количество, стоимость, причина, кто отметил, поставщик, решение и возмещение.
- Карточка поставщика (SPEC-26): возвраты ему и ожидаемые возмещения.
- Отчёт о прибыли: «Списание брака» и «Брак: разница возмещения».
- Уведомления и лента бота владельца: отметка брака и решение.

## Данные

```
defects (id, branch_id, product_id, qty, cost_tyiyn, reason, supplier_id?, user_id, created_at,
         status: pending | written_off | returned, resolved_at?)
defect_resolutions (id, defect_id unique, kind: write_off | replace | credit | cash,
         replace_qty?, refund_tyiyn?, account_id?, user_id, created_at, reversal_of?)
stock_movements + kinds defect, defect_back, defect_replace
cash_movements + kind supplier_refund
```

## Реализация

- API: `GET /defects?status=pending|resolved`, `POST /defects` (отметка), `GET /defects/supplier-hint?product_id=` (поставщик последнего прихода), `POST /defects/{id}/unmark`, `POST /defects/{id}/resolve` (владелец), `POST /defects/{id}/resolution/reverse` (владелец, с причиной). Миграция `0036_defects.sql`.
- Снятая отметка получает статус `cancelled` (товар вернулся движением `defect_back`). У записи брака меняются только статус и время решения — остальное защищено триггером.
- В `defect_resolutions` хранится несколько строк на брак: решение и его сторно (`reversal_of`, суммы с обратным знаком). Действует одно неотменённое решение; параллельные решения исключает блокировка записи брака. Кроме полей из «Данных» строка хранит поставщика возврата, стоимость товара взамен (`replace_tyiyn`), убыток списания (`writeoff_tyiyn`) и разницу возмещения (`diff_tyiyn`) — из них отчёт о прибыли берёт строки по дню решения.
- Сторно возврата новым товаром — движение `defect_replace` с минусом; скидка — запись долга поставщика `defect` / `defect_reversal` (сторно такой записи в карточке долга не делается — только отменой решения); деньги — `supplier_refund` и сторно `reversal` в ту же кассу, для «Кассы» нужна открытая смена.
- Стоимость брака, возмещение и разницу сервер отдаёт только владельцу.
- Бот владельца: `stock_report` → `defects` (только чтение).

## Критерии приёмки

- [x] Отмеченный брак уходит из остатка и не продаётся; стоимость = средняя на момент отметки.
- [x] Администратор отмечает, но не решает (403); владелец получает уведомление.
- [x] Списание даёт убыток ровно на стоимость брака в отчёте о прибыли.
- [x] Возврат с новым товаром возвращает остаток, прибыль не меняется.
- [x] Возврат со скидкой: поставщик должен нам сумму; следующая накладная в долг уменьшает наш долг на неё.
- [x] Возврат деньгами: касса растёт, разница со стоимостью — в прибыли.
- [x] Снять отметку до решения — товар возвращается в остаток по той же стоимости.
- [x] Сторно решения возвращает запись в «ожидает решения» и откатывает деньги, долг и склад.
- [x] Остаток сходится с суммой движений после всех случаев.
