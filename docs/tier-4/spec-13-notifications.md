# SPEC-13. Уведомления владельцу

## Задача

Владелец не стоит за кассой и должен узнавать о важном сам: изменили цену, оформили возврат, сторнировали приход, простили долг, сдали кассу в сейф, завели пользователя. Уведомления — это выборка из журнала действий, а не новая сущность (ADR-034).

## Данные

Отдельной таблицы нет: журнал `audit_log` уже хранит, кто, когда и с какого устройства что сделал (инвариант 5). Уведомление — строка журнала с действием из списка наблюдаемых. Отметка «просмотрено» хранится в `settings` по ключу `notifications_seen:<user_id>` как время последнего открытия экрана.

Наблюдаемые действия:

| Действие | О чём говорит |
| --- | --- |
| `product.prices` | изменена цена товара: было и стало; у масла — и розлив за литр, посчитанный от цены канистры (ADR-074) |
| `sale.price_override` | цену поменяли прямо в чеке |
| `sale.credit_limit_exceeded` | клиент вышел за лимит долга |
| `sale.return` | оформлен возврат |
| `receipt.reverse` | сторно прихода |
| `debt.adjust` | долг исправлен вручную |
| `user.create`, `user.update` | изменились доступы |
| `shift.handover` (этап 2) | смена закрыта и касса сдана: ожидали, пересчитали, расхождение, сколько ушло в сейф и сколько осталось (SPEC-05) |
| `cash.reverse`, `cash.transfer_reverse` (этап 2) | сторно внесения, изъятия или перемещения денег |
| `sale.below_cost` | чек без сети продан дешевле закупки (ADR-042) |
| `receipt.cost_above_price` | закупка дороже цены продажи: пока цену не поднимут, товар не продать (ADR-042) |
| `sale.return_over_paid` (этап 2) | деньгами вернули больше, чем по чеку платили деньгами (ADR-041) |
| `auth.login_flood` | 20 неверных паролей к одному логину (сотрудника или кабинета) с разных адресов за 15 минут; вход не закрыт, не чаще раза в 15 минут (ADR-059) |
| `employee.create`, `employee.update` | добавлен или изменён сотрудник: роли, отключение, назначена ли оплата кассира (ADR-059) |
| `sale.offline_after_close` | наличный чек без сети пришёл, когда смена его дня уже закрыта: сумма даст расхождение следующей смены (ADR-059) |
| `vehicle.plate_conflict` | клиент добавил в боте (или точка в карточке клиента) машину с номером, записанным на другого клиента точки: машина заведена пустой, разбирается владелец (SPEC-22, ADR-061, ADR-062) |
| `receipt.supplier_payment` | накладная оплачена сразу: сумма и откуда — из какой кассы или «из своих, мимо касс» (SPEC-10, ADR-062) |
| `sale.offline_bypass` | чек без сети прошёл мимо проверок онлайн-продажи: список причин — товар в архиве, отключённые сотрудник, клиент, услуга или правило подарка, долг отключённому клиенту, задним числом, убранная машина (SPEC-09, ADR-062) |
| `sale.cost_unknown` | товар продан без цены закупки: 2 % кассиру с этих строк ждут, пока владелец укажет цену (SPEC-07, ADR-062) |
| `party.limit_change` | изменён лимит долга или срок оплаты клиента: было и стало (SPEC-10, ADR-062) |
| `shift.reopen` | смена переоткрыта, с причиной (SPEC-05, ADR-063) |
| `debt.reverse`, `payout.reverse`, `payroll.accrual_reverse` | сторно записи долга, выплаты или начисления сотруднику (ADR-063) |
| `payroll.rule`, `payroll.rule_close` | назначена или закрыта ставка оплаты сотрудника (SPEC-07, ADR-063) |
| `settings.loyalty` | изменён процент начисления баллов (SPEC-19, ADR-063) |
| `gift.rule_toggle` | правило подарка включено или отключено (ADR-063) |
| `backup.failed` | ночная копия базы не создана: «⚠️ Копия базы не создана» и причина (ADR-057, ADR-063) |
| `telegram.code_flood` | 20 неверных кодов привязки бота за 15 минут: привязка закрыта на 15 минут (SPEC-18, ADR-063) |
| `telegram.customer_ambiguous` | клиент не подключился к боту: его номер записан в нескольких карточках (SPEC-18, ADR-063) |
| `receipt.reverse_negative` | сторно накладной, товар которой уже продан: остаток ушёл в минус — «проведите верный приход»; по каждому товару остаток после сторно (SPEC-03, ADR-065) |
| `battery.intake_reverse` | отменён приём аккумуляторов: вес, сколько вернулось в кассу, причина (SPEC-03, ADR-065) |
| `settings.payment_fee` | изменена ставка комиссии банка: было, стало и с какой даты (SPEC-08, ADR-065) |
| `telegram.employee_link` | работник подключился к боту своим номером и видит свой заработок (SPEC-23, ADR-066) |

Список расширяется вместе с этапом 2; новая запись в журнале появляется в уведомлениях без миграции.

## API

- `GET /notifications?limit=` → `{unseen, items[]}`, где у каждого `title`, `details`, кто и когда, и признак `new`. Только владелец, администратору 403 (инвариант 13).
- `POST /notifications/seen` → отмечает всё прочитанным.

Текст уведомления собирает сервер: клиент не знает, как расшифровывать данные журнала, и одно и то же событие должно читаться одинаково везде.

## Клиент

- Пункт меню «Уведомления» виден только владельцу, рядом — число новых.
- Открытие экрана отмечает всё прочитанным; новые строки подсвечены до следующего захода.
- На телефоне это первое, что владелец смотрит утром: что было вчера без него.

## Чего здесь нет

Писем нет. Сообщения в Телеграм — только через бот владельца (SPEC-18, ADR-050): туда уходят эти же события и текущая работа точки. Уведомления живут внутри системы, владелец открывает её с телефона через туннель (ADR-025).

## Критерии приёмки

- [ ] Администратор меняет минимальный остаток — уведомления нет; владелец меняет цену — уведомление есть, с ценой до и после.
- [ ] Возврат, сторно прихода и правка долга попадают в список.
- [ ] Администратор: `GET /notifications` → 403.
- [ ] После открытия экрана `unseen` равен нулю, а новые события снова его увеличивают.
- [ ] Список не длиннее 500 строк за запрос.
