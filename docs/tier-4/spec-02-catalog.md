# SPEC-02. Каталог, штрихкоды, этикетки, справочники

## Задача

Справочник товаров с категориями и характеристиками, поиск по штрихкоду и тексту, создание собственных штрихкодов и печать этикеток; справочники сотрудников, услуг и поставщиков.

## Категории

- `kind`: `oil`, `filter`, `battery`, `other`. Масло (`oil`) всегда учитывается в миллилитрах, остальные — в штуках.
- `attributes` — список характеристик: `{key, label, type: text|number|select, options?, filterable}`. При создании категории каждого вида предлагаются стандартные:
  - масло: вязкость (select), основа (select: синтетика, полусинтетика, минеральное), допуски (text), объём тары задаётся полем товара;
  - фильтр: тип (select: масляный, воздушный, салонный, топливный), кросс-номера (text);
  - аккумулятор: ёмкость А·ч (number), пусковой ток (number), полярность (select: «прямая» — «+ слева, Л», «обратная» — «+ справа, П»). Категория аккумуляторов без полярности получает её миграцией `0039` (SPEC-27).
- Полярность показывается отметкой «(Л)» / «(П)» после названия: в поиске и строке кассы, в списке товаров и остатках, на этикетке и в чеке; фильтр по ней — в списке товаров (характеристика категории) и в остатках («Полярность: прямая / обратная»).
- Строка масляной книжки (SPEC-16, SPEC-27): `book_slot` — `none` | `oil` | `oil_filter` | `air_filter` | `cabin_filter` | `fuel_filter` | `other`, и интервал строки по умолчанию `book_interval_km`, `book_interval_days` (оба или ничего; 500–200 000 км, 1–1095 дней). Не задана — по виду: масла — масло, фильтры — масляный фильтр, остальное в книжку не идёт. Новая категория фильтров без заданной строки получает её по названию: «воздуш…» — воздушный, «салон…» — салонный, «топлив…» — топливный, «масл…» — масляный (проверка 20.10.2026). Товар фильтра со своим «Типом» пишется в строку своего типа; в списке категорий у фильтров с характеристикой «Тип» строка показывается как «По типу фильтра» с пометкой «без типа — …». Задаёт владелец: `POST/PATCH /categories` с `book: {slot, interval_km?, interval_days?}`, администратору — 403; журнал `category.update` хранит было/стало. На экране «Категории» — колонка «Строка книжки» и поля в окне категории.
- Эндпоинты: `GET/POST /categories`, `PATCH /categories/{id}`.

## Товары

- Поля: `name`, `brand`, `article`, `category_id`, `container_ml` (обязательно и > 0 для масла), `attrs` (значения по ключам категории), `barcodes[]`.
- Штрихкод обязателен: товара без кода в системе не бывает. Если `barcodes` пуст, при создании выдаётся внутренний код (ADR-026). Миграция выдаёт коды товарам, заведённым раньше.
- Цены филиала: `sale_price_tyiyn` (за штуку или канистру; цену существующего товара меняет только владелец, ADR-032; исключение — новая цена продажи в строке прихода, её ставит и администратор, SPEC-28 §1, ADR-075), `min_stock`. У масла одна цена — цена канистры (ADR-074): `pour_price_per_l_tyiyn` в ответах только для чтения и считается сервером — `цена канистры × 1000 / container_ml`, до тыйына (`domain::money::canister_pour_price`, на экране `canisterPourPrice`). Задать её отдельно нельзя: `POST /products` и `PATCH /products/{id}/prices` с `pour_price_per_l_tyiyn` → 422 (администратору — 403).
- Эндпоинты:
  - `GET /products?q=&category_id=&kind=&attr.<key>=<value>&limit=` — поиск по названию, бренду, артикулу, штрихкоду (подстрока без учёта регистра) и фильтрам характеристик; `kind` — вид категории (`oil` — все масла, им пользуется экран перелива).
  - `GET /products/list?q=&category_id=&attr.<key>=&archived=&sort=&dir=&limit=` — список «как в Умаге» (SPEC-27): у строки код (артикул или первый штрихкод), `stock_sale_tyiyn` — остаток по цене продажи, владельцу ещё `purchase_price_tyiyn` (средняя за штуку, канистру или кг; без остатка — последняя закупочная) и `stock_purchase_tyiyn` (стоимость остатка; минус — по последней закупочной). `sort`: `name`, `code`, `stock`, `purchase`, `sale`, `stock_purchase`, `stock_sale`; `dir=desc`. `totals` — по всему отбору, не только по показанным строкам: `count`, `sale_tyiyn`, владельцу `purchase_tyiyn`; итог — сумма округлённых строк. Администратору закупка, средняя, стоимость и последняя закупочная в этом ответе не отдаются, сортировка по ним — по названию (ADR-008).
  - `GET /products/by-barcode/{code}` → товар или 404.
  - `GET /products/similar?name=` → до 5 товаров с близким названием (`pg_trgm`, сходство ≥ 0,3).
  - `POST /products`, `PATCH /products/{id}`, `PATCH /products/{id}/prices`.
  - `POST /products/{id}/barcodes {code?}` — добавить заводской код или, без `code`, создать внутренний. Кодов у товара сколько угодно: один товар с тремя кодами лучше трёх карточек-дублей.
  - `DELETE /products/{id}/barcodes/{code}` — отвязать код. Последний код не удаляется (422): иначе товар останется без штрихкода.
- Ответ содержит остаток филиала (`stock_qty`), для масла — разбивку на канистры. Поля `avg_cost_tyiyn` и `stock_value_tyiyn` — только владельцу.
- Изменение цены пишется в журнал со старым и новым значением. Правка карточки (`product.update`) — тоже: в журнале только изменённые поля, было и стало (ADR-062).

## Внутренний штрихкод

```
EAN-13: "22" + 10 цифр порядкового номера (общая последовательность internal_barcode_seq) + контрольная цифра
контрольная: сумма цифр на нечётных позициях (1-я, 3-я, …) ×1, на чётных ×3; check = (10 − сумма mod 10) mod 10
```
Код уникален глобально; если заводской код совпадает с существующим — 409 с указанием товара.

## Этикетки

- Настройка филиала `labels`: `{width_mm, height_mm, show_name, show_price, show_article, show_brand, show_spec}`; пресеты 58×40, 40×30, 30×20. `show_brand` — бренд строкой над названием, `show_spec` — характеристики: вязкость и объём масла, тип фильтра, ёмкость и ток аккумулятора (SPEC-29 §6); у прежних настроек обе — да.
- `GET /settings/labels`, `PUT /settings/labels`.
- Клиент: выбор товара и количества копий → страница печати с CSS `@page { size: Wmm Hmm }`, штрихкод EAN-13 (или CODE128 для нестандартного кода), название, цена. Печать через диалог браузера.
- QR-код генерируется на клиенте для ссылок (используется в этапе 3).

## Справочники

- Сотрудники: `GET/POST /employees`, `PATCH /employees/{id}` — ФИО, кассир/мастер, активен. Признак «кассир» ставит и снимает только владелец: с ним назначается оплата (SPEC-07, ADR-059); администратор заводит мастеров и правит имя.
- Услуги: `GET/POST /services`, `PATCH /services/{id}` — название, цена, начисление мастеру (по умолчанию 30 сом = 3000 тыйын).
- Услуги из Excel (проверка 20.10.2026): на экране «Услуги» владелец выбирает выгрузку товаров старой программы (тот же файл, что для списка старой программы, SPEC-20) и видит строки с отметками; заранее отмечены похожие на услуги — категория «Незаданные» (или пустая) либо без закупочной цены, единица — штуки. `POST /services/import {op_id, items: [{name, price_tyiyn}]}` — только владелец (иначе 403), одной транзакцией, повтор с тем же `op_id` — тот же ответ; названия, которые уже есть (без учёта регистра и пробелов по краям), и повторы в списке пропускаются — ответ `{created, skipped}`; ставка мастера — 0, её задаёт владелец; пустой список или отрицательная цена — 422; в журнале — `service.create` с отметкой `import`.
- Поставщики: `GET/POST /suppliers`, `PATCH /suppliers/{id}`.
- Удаления нет, только деактивация.

## Клиент

- Экран «Товары»: поиск, фильтры по категории и характеристикам, таблица — название, код, остаток, закупка (владельцу), продажа, сумма по закупке (владельцу) и по продаже; щелчок по заголовку сортирует, внизу итоги по отбору (SPEC-27). Строка открывает карточку товара; «Этикетки» — галочкой в строке. «+ Товар» в заголовке (на телефоне — круглая «+» внизу) открывает полную карточку нового товара; новый товар принимает несколько штрихкодов подряд; в меню строки — «+ Оприходовать» (SPEC-29 §2, §7, §8).
- Экран «Категории»: «+ Товар» в строке категории открывает форму товара с этой категорией (SPEC-27).
- Экран «Продаваемые» (меню «Склад»): самые продаваемые товары за период по выручке или количеству, с фильтром по категории — `GET /reports/top-products` (SPEC-27).
- Поиск в кассе и приходе ищет одновременно по названию, бренду, артикулу и штрихкоду и показывает список сразу, не дожидаясь Enter: вставленный из буфера код тоже находится. Enter выбирает точное совпадение по коду или первую строку списка.
- Создание товара: поле штрихкода (сканер), по мере ввода названия показываются похожие товары с предупреждением «возможно, уже заведён». Код можно не вводить — система создаст свой и сразу предложит напечатать этикетку. Категорию можно создать не выходя из карточки товара: кнопка «+ новая категория».
- Карточка товара: список штрихкодов с кнопками «Добавить код», «Создать свой код» и «Отвязать».
- Неизвестный код при сканировании (касса, приход): предлагается «Привязать к товару» с поиском по названию или «Создать товар». Привязка к существующему товару — главный способ не разводить дубли.
- Экраны справочников: категории, сотрудники, услуги, поставщики.
- Настройка этикеток с предпросмотром.

## Дополнено SPEC-30 (21.10.2026)

Поиск (SPEC-30 §13): `GET /products?q=` отдаёт найденное по порядку — точный штрихкод или артикул (без учёта регистра), затем название с начала, затем остальное; внутри — по названию. Без сети снимок ищет в том же порядке. Enter в поиске берёт товар только из найденного по всему тексту: пока показано найденное по началу, Enter сразу запрашивает полный текст и берёт первое из ответа; строку, выбранную стрелками, и клик — как раньше (`resolveEnter`, `planEnter` в `web/src/lib/pickerResults.ts`). Причина — 21.10.2026 вместо моторного масла в чек встал воздушный фильтр, первый из найденного по первым буквам.

Справочник «Услуги» (SPEC-30 §2): колонки «Цена клиенту / С нашим маслом / Мастеру»; флажок «Бесплатно с нашим маслом» (`services.free_with_oil`) ставит владелец. Миграция 0055 ставит флажок действующим услугам с «масл» в названии, переносит прежнюю ставку за чек услугам замены со ставкой 0 и заводит «Замена масла в моторе» и «… в коробке» (цена 0, флажок включён), если в филиале нет замены масла. Новая услуга получает ставку из прежней настройки (без неё — 30 сом). Ставки за чек на экране больше нет — только строка-пояснение для старых чеков без сети.

## Критерии приёмки

- [ ] Масло без `container_ml` не создаётся (422).
- [ ] Контрольная цифра: для `220000000001` → `2200000000019`.
- [ ] Повторный штрихкод даёт 409 с названием существующего товара.
- [ ] Товар, созданный без штрихкода, получает внутренний код; ответ содержит его.
- [ ] Привязка второго и третьего кода к товару: поиск находит товар по каждому из них.
- [ ] Отвязка последнего кода → 422; отвязка при двух кодах проходит.
- [ ] После миграции товаров без штрихкода нет.
- [ ] Объединение дублей: коды и остаток переходят на основной товар, дубль уходит в архив, чеки остаются за ним.

## Объединение дублей

Два товара на один и тот же товар всё равно иногда появляются. Операция `POST /products/{id}/merge {op_id, into_product_id}` сливает их (ответ заказчика, вопрос 13):

```
в run_operation:
  товары разные, оба не в архиве, единицы учёта совпадают
  штрихкоды и кросс-номера (SPEC-17) дубля перевешиваются на основной товар
  остаток и стоимость переносятся движениями: из дубля −qty −value, в основной +qty +value
  дубль уходит в архив и больше не ищется в кассе
  журнал product.merge: что в что слили, сколько перенесли, какие штрихкоды и кросс-номера (ADR-062)
```

Проведённые чеки и накладные остаются за дублем: переписывать историю нельзя (инвариант 4). В отчётах он виден как архивный товар с продажами до объединения.
- [ ] Администратор не меняет цену розлива (403) и не видит `avg_cost_tyiyn`.
- [x] Одна цена масла (ADR-074): канистра 4 л за 2 000 с — в ответе розлив 500 с за литр; новая цена канистры меняет розлив; отдельная цена розлива при создании и в `PATCH /prices` → 422; лента владельца показывает розлив «было / стало» (`oil_has_one_price`, `domain::money` `pour_price_comes_from_canister`, `money.test.ts`).
- [ ] Поиск находит товар по части артикула и по штрихкоду.
- [ ] Похожие товары находятся при опечатке в названии.
- [x] Итоги списка товаров равны сумме строк; администратор не получает закупку и стоимость остатка (`product_list_totals_equal_rows_and_admin_sees_no_purchase`, SPEC-27).
