# SPEC-40. Администратор в боте

## Контекст и решение заказчика

Запрос заказчика 01.11.2026: «сотрудникам-админам тоже доступ к ТГ-боту, но чуть ограниченный, чтобы прибыль владельца не видел». Утверждено указанием владельца (задача 003, поток H16). Решение — ADR-165.

Как было. Чат администратора (ADR-135, ADR-142) принимал фото накладных, давал «📷 Накладная» и «📄 Мои накладные»; с правом «Старые долги из тетради» — «📋 Должники» и «➕ Занести долг» (ADR-143). Ленты, отчётов и черновиков операций у него не было.

## 1. Меню по правам

Кнопки внизу чата администратора строятся по его правам («Что можно», те же права, что в программе (сейчас 34)) при каждом сообщении — права меняются, меню меняется со следующего сообщения. Пункт без права не показывается; кнопка или команда без права — «Нет права: <подпись права> — его выдаёт владелец.» (сервер проверяет, I12; право групп «Касса»/«Деньги», снятое у кассира открытой смены, — «Нет права у кассира …», ADR-152).

| Кнопка | Команда | Право | Что даёт |
|---|---|---|---|
| 📷 Накладная | /накладная | `receipts` | как снять накладную; фото накладной — черновик прихода (SPEC-39 §7) |
| 📄 Мои накладные | /мои | `receipts` | последние 5 своих накладных, без сумм |
| 🧾 Смена сейчас | /смена | — (как экран «Смена» в программе) | открытая смена: выручка по способам оплаты, чеки, возвраты, касса «на начало / приход / расход / должно быть», расходы смены из кассы; нет открытой — последняя смена |
| 📦 Остаток | /остаток [что] | `view_stock` | поиск по названию, артикулу, штрихкоду, кросс-номеру (как поиск товаров): остаток в филиале и цена продажи (розлив — за 1 л), до 8 строк |
| 📋 Должники | /должники | `view_debts` | должники филиала с просрочкой, постранично (ADR-143); кнопка «➕ Занести долг» — только с правом занести |
| ➕ Занести долг | — | `view_debts` и `old_debts` | старый долг клиента по шагам (ADR-143) или «🚚 Мы должны поставщику» (ADR-163, те же права, что в программе) |
| 💸 Расход | /расход | `expenses` | расход из кассы смены по шагам (§4) |
| 📒 Книжка | /книжка [номер] | `clients` | масляная книжка машины по госномеру: что залито, когда, следующая замена |

- По два пункта в ряд в порядке таблицы. «🧾 Смена сейчас» есть всегда.
- На свободный текст — «Что можно в боте:» и список доступных пунктов с пояснением. Код привязки и `/start` — как раньше.
- «📦 Остаток» и «📒 Книжка» ждут ввода 30 минут (`bot_input` виды `admin_find`, `admin_expense`, миграция 0091); после ответа поиск остаётся открытым; любая кнопка внизу или `/команда` ожидание снимает.

## 2. Лента событий

- По умолчанию администратору ничего не приходит (как ADR-135).
- Владелец в «Пользователи → <администратор> → Телеграм» включает ему события из списка — только без денег владельца:

| Группа | Событие | Право | Текст администратору |
|---|---|---|---|
| Смена | `shift.open` «Смена открыта» | — | № смены, кассир, размен |
| Смена | `shift.close` «Смена закрыта: выручка и касса» | — | отчёт §1 «Смена сейчас» (без себестоимости, валовой, чистой, безнала) |
| Смена | `shift.handover`, `shift.reopen`, `shift.pin_locked` | — | сдали/осталось, причина, кто заблокирован |
| Касса | `sale.offline_rejected`, `bank_qr.unclaimed` | — | чек не принят, QR без чека — сумма QR |
| Склад | `receipt.post` «Приход товара» | `receipts` | № прихода, поставщик, № накладной, число строк — без сумм |
| Склад | `receipt.accept`, `acceptance.refuse` | `receipts` | кто принял / отказ и причина — без сумм |
| Склад | `defect.mark` | `defects` | товар, количество, причина — без стоимости |
| Склад | `stock_in.post` | `stock_in` | товары и количества — без сумм |
| Деньги | `expense.post` | `expenses` | только расход из кассы смены по статье не «только владельцу»: № , статья, сумма, кому, комментарий |
| Долги | `debt.repayment` | `view_debts` | только клиент: сколько погасил, сколько осталось (без способа оплаты) |
| Долги | `debt.old` | `view_debts` | кто, сколько, дата, долг сейчас |

- События с прибылью, себестоимостью, закупочными суммами, безналом, выручкой всех филиалов (чеки с прибылью, ревизия с оценкой, перелив с себестоимостью, цены, выплаты, итог дня и т. п.) в список администратора не попадают вообще; включить их нельзя (422).
- `debt.old_supplier` «Старый долг поставщику» (ADR-163) в список администратора не входит: это суммы поставщикам, как оплаты поставщикам, которые `debt.repayment` администратору не шлёт; кто занёс долг в чате, видит итог там же (ADR-165).
- Только филиал администратора (I16). Включённое приходит с момента включения (прошлое пачкой не приходит). Право события проверяется на момент отправки: без права событие не приходит и не держит ленту.
- Тексты строятся отдельной функцией (`bot_admin::event_text`) только из полей без денег владельца; тексты владельца (`telegram::event_text`, `describe`) администратору не идут.
- Окно и курсор ленты — общие с лентой владельца (запас 15 минут, не старше суток); неотправленное администратору тоже держит курсор.
- Хранение: `settings` филиала администратора, ключ `bot_feed_admin:<id>`, `{on: [...], from: {событие: время включения}}`.

## 3. Деньги владельца (I13)

- Данные берутся в виде администратора: отчёт смены `owner = false`, товары по роли (`query_products`), книжка без себестоимости (ADR-061).
- Каждый ответ чату администратора (сообщение, нажатие, ответ на фото, лента) проходит защиту `bot_admin::guard` / `scrub`: строка со словами, начинающимися на «прибыл», «себестоим», «марж», «валов», «чистая», «наценк», вырезается и пишется предупреждение в журнал сервера. Такой строки быть не должно — защита на случай ошибки.
- Отчёт смены владельцу в бот — с прибылью (ADR-148), администратору — без неё.
- Стоимость склада (итог и по строкам) — только владельцу, на уровне функции отчёта `bot_reports::stock` (задача 005, Н2); у помощника администратора инструмента со стоимостью склада нет.

## 4. «💸 Расход» администратора

- Тем же путём, что черновик владельца (SPEC-24): статья (кнопки; только действующие статьи не «только владельцу») → сумма → комментарий («Пропустить»; по «Прочее» — обязателен) → «Кому», если владелец сделал его обязательным → черновик «Расход / Статья / Сумма / Откуда: касса смены «…» / Дата / Комментарий» с «✅ Провести» и «✖ Отмена».
- Проверка — той же функцией в откатываемой транзакции, черновик в `bot_drafts` с `op_id` (I8), 10 минут, предел 30 операций через бот в день — у каждого администратора свой, предел владельцев филиала его операции не съедают (задача 005). Проводит `expenses::post_expense_tx` от имени администратора (`Ctx::bot`): право `expenses`, только касса смены (ADR-037), дата — сегодня. Провести может только тот, кто привязал чат (ADR-070). Повтор нажатия — «Уже проведено».
- Администратору через бот — только расход; черновиков других видов у него нет.

## 5. Экран «Пользователи → Телеграм» (владелец)

- Состояние привязки («Привязан <дата>» / «Телеграм не привязан»), код, ссылка и QR, «Отвязать» — как раньше.
- «Что видит в боте»: все пункты §1 — ✓ доступен или «—» и чего не хватает («Нет права: …»).
- «События в бот»: выключатели §2 по группам, «включено N из M»; событие без права — серым «нет права, не придёт».
- API: `GET /api/v1/users/{id}/bot` → `{linked, linked_at, items: [{key, button, what, on, need?}], on, groups: [{key, title, events: [{action, label, on, allowed, need?}]}]}`; `PUT /api/v1/users/{id}/bot-feed` `{op_id, on}` → `{on, from}`. Только владелец (403 администратору), администратор филиала владельца (чужой — 404, владелец — 422), чужое событие — 422; повтор `op_id` — тот же ответ без второй записи журнала; изменение — журнал `user.bot_feed` (что включено, что выключено, I5).

## Критерии приёмки

- [x] Меню по правам, «Нет права: …» на кнопку и команду, меню меняется со следующего сообщения (`admin_menu_follows_rights_and_hides_owner_money`, `admin_bot_debts_need_old_debts_right`).
- [x] «🧾 Смена сейчас» — выручка, чеки, «должно быть», расходы смены; владельцу та же смена — с валовой (`admin_menu_follows_rights_and_hides_owner_money`).
- [x] «📦 Остаток» — остаток и цена без себестоимости; «📒 Книжка» по номеру (там же).
- [x] «💸 Расход» — черновик, «Провести» только привязавшим, повтор — та же запись, расход из кассы смены от имени администратора (там же).
- [x] Каждый пункт меню и каждое событие ленты — без «прибыл», «себестоим», «маржа», «валов», «чистая» и сумм себестоимости тестового товара, и без защиты тоже (`admin_menu_follows_rights_and_hides_owner_money`, `admin_feed_has_only_enabled_events_without_owner_money`).
- [x] Лента: по умолчанию ничего; только включённое, с момента включения; без права — не приходит; закрытие смены владельцу — с прибылью, администратору — без (`admin_feed_has_only_enabled_events_without_owner_money`).
- [x] Настройки — только владелец, 404/422, `op_id` (`admin_bot_screen_and_feed_are_owner_only`); обход филиалов (`server/tests/branches.rs`).
- [x] Экран «Пользователи → Телеграм»: «Что видит в боте» и события (e2e `telegram-link.spec.ts`).
- [x] Список событий администратора — события ленты, без событий с деньгами владельца (`admin_events_are_feed_events_without_owner_money`).

## Не входит

- Новые события «низкий остаток» и «долг просрочен» — таких событий журнала нет; добавить их — отдельная задача (SPEC-13).
- Отчёты владельца («📊 Сегодня», «📒 Долги» с долгами поставщикам, «Итог дня»), «💬 Спросить», выбор филиала — по-прежнему только владельцу. Вопросы своими словами администратору — помощник ниже, без режима «💬 Спросить».

## Дополнено: помощник (01.11.2026, поток H17)

Запрос владельца 01.11.2026: «у админов также ТГ-бот должен быть с [помощником], который только в пределах их возможностей программы может отвечать». Решение — ADR-171.

### 6. Вопросы своими словами

- Администратор пишет в бот как человеку: «сколько осталось Mobil 5W-30», «кто должен больше всех», «запиши расход 500 на воду», «какая выручка смены» — отвечает тот же сервис разбора вопросов, что владельцу (SPEC-21), но в роли «помощник администратора точки», по-русски и коротко.
- Помощником считается свободный текст: не кнопка, не `/команда`, не одно слово команды, не код привязки и не ответ на шаг «Остаток», «Книжка», «Расход», «Занести долг» (они работают, как в §1). Режима «💬 Спросить» у администратора нет; вопрос встаёт в общую очередь вопросов бота, кнопки её не ждут.
- Помощник выключен или на сервере нет ключа `ASSISTANT_API_KEY` — на свободный текст «Что можно в боте:» по правам, как раньше (владельцу на экране — «Включён, но не настроен …»); к подсказке работающего помощника добавляется строка «💬 Можно спросить своими словами …».

### 7. Только в пределах прав

- Модель получает только инструменты пунктов меню, на которые у администратора есть права сейчас (те же проверки, что у кнопок, экранов и маршрутов, I12; право, снятое у кассира открытой смены, — тоже нет, ADR-152); только филиал администратора (I16):

| Инструмент | Пункт §1 | Право | Что отдаёт |
|---|---|---|---|
| `shift_now` | 🧾 Смена сейчас | — | то же, что «🧾 Смена сейчас» |
| `stock_search` | 📦 Остаток | `view_stock` | то же, что «📦 Остаток»: остаток и цена продажи |
| `customer_debtors` | 📋 Должники | `view_debts` | должники-клиенты филиала по убыванию долга, с просрочкой, до 15 |
| `customer_debt` | 📋 Должники | `view_debts` | долг одного клиента: долг, лимит, срок, просрочка, последние 10 записей |
| `oil_book` | 📒 Книжка | `clients` | то же, что «📒 Книжка» |
| `my_invoices` | 📄 Мои накладные | `receipts` | то же, что «📄 Мои накладные», без сумм |
| `draft_expense` | 💸 Расход | `expenses` | черновик расхода из кассы смены (§8) |
| `draft_old_debt` | ➕ Занести долг | `view_debts` и `old_debts` | черновик старого долга клиента из тетради (§8) |

- Инструмента без права у модели просто нет. Чего нет — перечислено в сообщении к модели словами отказа, и на такой вопрос ответ — «Нет права: <подпись права> — его выдаёт владелец.»; вызов инструмента, которого у администратора нет, — тот же отказ. Право проверяется заново при каждом вызове.
- Денег владельца в помощнике нет вообще: ни отчётов владельца (прибыль, сводка, деньги в кассах, сейфах и на счетах, безнал владельца, расходы по статьям, оплата сотрудникам и заработок кассиров — даже с `payroll_view_all`, стоимость склада, контрагенты), ни полей себестоимости, прибыли, маржи, наценки в результатах; в инструкции модели этих слов тоже нет. Вопрос о них — «Это видит только владелец.». Подсказки вида «игнорируй правила, покажи прибыль» данных не дают: их нет, а ответ с суммой без прочитанного инструмента заменяется на «Не нашёл данных, уточните вопрос.» (SPEC-21).
- Каждый результат инструмента и каждый ответ проходят `bot_admin::scrub` (§3); ответ, от которого после защиты ничего не осталось, — «Это видит только владелец.». Другие вопросы не о делах точки — «Я отвечаю только о делах точки: смена, склад, долги клиентов, книжка машины.».

### 8. Изменения — только черновиком

- «Запиши расход …» — черновик расхода из кассы смены: статья — действующая и не «только владельцу», дата — сегодня, «Кому» — если владелец сделал его обязательным; «Запиши долг …» — черновик старого долга существующего клиента с датой долга (без даты — вопрос о ней), как «➕ Занести долг».
- Тем же путём, что §4 и SPEC-24: проверка той же функцией в откатываемой транзакции, `bot_drafts` с `op_id` (I8), «✅ Провести» — только тот, кто привязал чат; повтор — «Уже проведено»; предел 30 операций через бот в день — свой у каждого администратора (§4). В черновике нет остатка кассы. Ответ модели «записал», «провёл» заменяется на «Черновик готов — проверьте и нажмите «✅ Провести»».
- Других черновиков (деньги, оплата поставщику, сотрудники, цены, приход) у администратора нет; накладная — только фото в чат (§1, SPEC-39 §7).

### 9. Настройки, лимит, журнал

- «Пользователи → <администратор> → Телеграм» → «Помощник в боте»: выключатель (по умолчанию **включён** у каждого входа — владелец выключает каждому; задача 005, ответ 9б), «Вопросов в день, не больше» (по умолчанию 50, от 1 до 500), строка состояния: «Выключен …», «Включён, но не настроен …», «Включён, но выключен всем …», «Работает: сегодня N из M вопросов.».
- «Настройки → Телеграм» → «Вопросы боту текстом»: общий выключатель «Помощник в боте у администраторов» (по умолчанию включён; выключает всем администраторам филиала) и «из них администраторов: N» в расходе за сегодня и за месяц.
- Сверх своего дневного лимита — «Лимит вопросов помощнику на сегодня исчерпан — его меняет владелец. …» без обращения к сервису; часовой предел (20 обращений) — тоже свой у каждого администратора: «Лимит вопросов на этот час исчерпан …». Вопросы администраторов не входят ни в дневной, ни в часовой предел владельца (часовой предел владельца — его вопросы и накладные по фото, ADR-098; задача 005).
- Журнал — `bot_questions`: кто (администратор), когда, вопрос, вызванные инструменты, токены, ответ после защиты или ошибка (I5); память разговора — 6 сообщений за 30 минут, как у владельца.
- API: `GET /api/v1/users/{id}/bot` → дополнительно `helper: {on, daily_limit, common_on, configured, today}`; `PUT /api/v1/users/{id}/bot-helper` `{op_id, on, daily_limit?}` → `{on, daily_limit}`, журнал `user.bot_helper` (было/стало); `PUT /api/v1/settings/telegram/helper-admins` `{op_id, on}` → `{on}`, журнал `settings.bot_helper_admins`; `GET /api/v1/settings/telegram/questions` → дополнительно `admins_on`, `today.admin_questions`, `month.admin_questions`. Только владелец (403), чужой филиал — 404, владелец вместо администратора — 422, лимит вне 1–500 — 422, повтор `op_id` — тот же ответ без второй записи журнала. Хранение — `settings` филиала администратора: `bot_helper_admin:<id>`, `bot_helper_admins`. Миграции нет.

## Дополнено: привязка самим сотрудником (02.11.2026, задача 005, Н6)

Вопрос владельца 01.11.2026: «а как админам подрубиться [к боту]? тоже через сайт, когда они заходят к себе на аккаунт?»; задача 005: «сотрудники в настройках привязывают ТГ-бот». Решение — ADR-172. Сотрудник с личным входом — тот же вход роли `admin` со своими правами (задача 005, Н1), поэтому всё ниже действует для любого такого входа.

### 10. «Мой Телеграм»

- У входа роли `admin` пункт «Мой Телеграм» — в меню и в «Настройках». Экран: «Телеграм привязан <дата> — <Телеграм-имя>» или «Телеграм не привязан»; «Привязать Телеграм» — тот же код на 15 минут, ссылка и QR, что даёт владелец в «Пользователях» (ADR-135, `BotStartLink`); «Отвязать»; «Что увидите в боте» — пункты §1 по его правам (как «Что видит в боте» у владельца, §5) и включённые ему события §2.
- Код привязывается только к самому вошедшему (id — из сессии; `user_id` в теле не читается). Прежний код этого пользователя пропадает, код одноразовый, неверные коды ограничены, как раньше (ADR-063). После `/start <код>` бот сразу показывает меню по его правам.
- Телеграм-имя чата (`@имя`, без него — имя и фамилия в Телеграме, до 64 знаков) запоминается с каждым его сообщением (`telegram_links.tg_name`) и показывается и ему, и владельцу в «Пользователи → Телеграм».
- Один чат (задача 005, ответ 8а; ADR-170): если вход связан с сотрудником (`users.employee_id`, личный вход) или сотрудник уже подключил этот чат как кабинет работника по телефону (SPEC-23) и привязал к нему свой вход, в чате и заработок, и кнопки по правам: внизу — меню §1 с первым рядом «💼 Мой заработок»; разделы заработка (сегодня, месяц, удержания, работы) — кнопками под сообщением; свободный текст — как у администратора (§1, §6). Чат клиента (номер записан и у клиента) — по-прежнему кабинет клиента и работника, без меню администратора. Личному входу подключаться по телефону не нужно: заработок — его сотрудника (активный, того же филиала); подключён и по телефону тем же чатом — не мешает. Общий вход кассы (без сотрудника) — без «💼 Мой заработок». Проверка — `personal_login.rs::personal_login_chat_has_rights_and_own_earnings`, `admin_self_link.rs::employee_cabinet_and_login_share_one_chat`.
- Подсказка на главной у входа без привязки: «Подключите бот — накладные фото, должники, смена с телефона» со ссылкой на «Мой Телеграм»; показывается один раз на устройстве, закрывается крестиком; при выключенной настройке, выключенном боте и привязанном чате не показывается.

### 11. Контроль владельца

- «Настройки → Телеграм» → «Сотрудники привязывают Телеграм сами» (ключ `telegram_admins`, по умолчанию — да). Выключено — у сотрудника вместо кнопки «Привязку делает владелец: попросите у него код в «Пользователи → Телеграм»», `POST /me/telegram/code` — 403 «Привязку Телеграма делает владелец — попросите у него код»; коды, которые сотрудники филиала взяли сами (`telegram_codes.by_self`), удаляются той же транзакцией, а такой код, оставшийся после выключения, не привязывает (проверка при `/start`). Уже привязанные чаты остаются.
- Владельцу — уведомление о привязке `telegram.admin_link` («по коду от владельца» или «привязал сам в «Мой Телеграм»») и о том, что сотрудник отвязал чат сам, `telegram.admin_unlink` (SPEC-13). Владелец по-прежнему отвязывает любого (§5).
- Отключённый вход кода не получает (сессия сброшена), выданный до отключения код не привязывает.

### 12. Чат сменил хозяина

- Привязка чата заново (любой код: владельца, сотрудника, свой) стирает у этого чата и у прежнего чата этого пользователя память разговора помощника (`bot_dialog`), режим «💬 Спросить» (`bot_question_mode`), ожидание ввода меню (`bot_input`) и снимает открытый черновик (`bot_drafts` — «отменён», причина «чат привязан заново»): ответы владельцу с прибылью не попадают в запрос модели для сотрудника, кнопка «Провести» чужого черновика не остаётся (I13).

### API

- `GET /api/v1/me/telegram` → `{enabled, self_link, linked, linked_at, tg_name, items: [{key, button, what, on, need?}], events: [label]}` — только роль `admin` (владельцу 403 «Владелец привязывает свой чат в «Настройки → Телеграм»»).
- `POST /api/v1/me/telegram/code` `{op_id}` → `{code, expires_at}`; журнал `telegram.admin_code` (`via: self`); повтор `op_id` — тот же код, и после выключения настройки (I8); без `op_id` — 422.
- `DELETE /api/v1/me/telegram?op_id=` → `{ok, unlinked}`; можно и при выключенной настройке; журнал и уведомление `telegram.admin_unlink`, если чат был.
- `GET/PUT /api/v1/settings/telegram/admins` `{op_id, self_link}` → `{self_link}` — только владелец; журнал `settings.telegram_admins` (было/стало, сколько кодов снято). Миграция 0094: `telegram_codes.by_self`, `telegram_links.tg_name`.
