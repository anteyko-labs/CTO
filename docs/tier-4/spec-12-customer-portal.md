# SPEC-12. Кабинет клиента по ссылке

## Задача

Клиент открывает свою страницу по личной ссылке или QR-коду и видит покупки, долг и масляную книжку своих машин. Только просмотр: брать в долг и погашать оформляет касса (ADR-029).

## Доступ

```
party_links (token pk, branch_id, party_id, created_at, created_by, revoked_at?)
  token — 32 случайных байта в base64url, в базе хранится только хеш sha256
```

- Ссылка `/c/{token}`, она же в QR-коде на печать.
- Пароля нет: ссылка и есть ключ. Поэтому токен длинный, в журнале фиксируется, кто его создал, и владелец может отозвать ссылку и выдать новую (`revoked_at`).
- Запросы по токену ограничены: 60 в минуту на токен и 600 в минуту на филиал (как ADR-016, счётчики в PostgreSQL). Неизвестный или отозванный токен → 404 без подсказок.
- Публичный роутер: только `GET`, вход не требуется, сессия не создаётся. Ни одна операция через него не проводится.

## Что отдаётся

`GET /public/c/{token}` →

```
{ shop: {name, phone, address},
  party: {name, kind},
  balance_tyiyn,                       -- долг клиента, 0 если долгов нет
  ledger: [{date, kind, amount_tyiyn, comment}],        -- последние 50 движений
  purchases: [{date, sale_number, total_tyiyn, contact_name?, vehicle_plate?,
               lines: [{name, qty_text, amount_tyiyn, gift}]}],   -- последние 50 чеков
  cars: [{plate, brand, model,
          services: [{date, mileage_km, oil, filters[], next_mileage_km}]}] }
```

У фирмы в покупках видно, кто из работников приезжал и на какой машине, а в `cars` — все машины фирмы: у директора одна страница на весь парк (ADR-030). Телефоны и ИНН работников на странице не показываются — только имя в строке покупки.

Отдаётся только то, что относится к этому контрагенту. Не отдаётся никогда: себестоимость, маржа, прибыль, закупочные цены, данные других клиентов, фамилии сотрудников, остатки склада (инварианты 13 и 12).

Масляная книжка берётся из записей замен (этап 3, отдельная спецификация); до её появления `cars` пустой.

## Управление ссылками

- `POST /debts/{party_id}/link {op_id}` → новый токен, прежний отзывается. Ответ содержит полную ссылку и данные для QR-кода: показать её можно только сейчас, в базе остаётся хеш.
- `DELETE /debts/{party_id}/link {op_id}` → отзыв без выдачи новой.
- Печать: страница с QR-кодом, названием магазина и именем клиента; QR рисуется на клиенте (`qrcode`, ADR-012).
- Выдают ссылку владелец и администратор, отзывает — владелец.

## Клиент

- Страница кабинета — отдельный маршрут без меню и без входа, своя лёгкая вёрстка, читается с телефона: баланс крупно, список покупок, история машин.
- Если долга нет — «Задолженности нет».
- Кнопок операций на странице нет вообще: ни оплаты, ни заявки. Внизу телефон магазина.
- В карточке клиента (SPEC-10) — кнопки «Ссылка и QR» и «Отозвать ссылку», видно, когда ссылка выдана.

## Критерии приёмки

- [ ] Ссылка открывается без входа и показывает покупки, долг и машины этого клиента.
- [ ] Чужой `party_id` по этому токену недоступен: других клиентов в ответе нет.
- [ ] Страница фирмы показывает её машины и имя приехавшего в каждой покупке, без телефонов работников.
- [ ] Ответ не содержит себестоимости, маржи и прибыли ни в одном поле.
- [ ] Отозванная ссылка → 404; новая выдача делает прежнюю недействительной.
- [ ] 61-й запрос в минуту по токену → 429.
- [ ] Токен в базе хранится хешем: в таблице нет значения из ссылки.
- [ ] Никакой `POST` через публичный маршрут не проходит (405 или 404).
- [ ] Страница читается на телефоне шириной 360 точек без горизонтальной прокрутки.

## Решения для ADR

- ADR-029: кабинет клиента — ссылка с токеном, только просмотр; клиент сам долг не берёт и не гасит.
