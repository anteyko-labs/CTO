# SPEC-04. Касса: продажа и возврат

## Задача

Чек на вынос или с заменой, с товарами, маслом канистрой и на розлив; кассир и мастер из справочника; ручная оплата наличными, картой, переводом, в том числе смешанная; возврат сторнирующим чеком.

## Замена масла — отметка, а не услуга

Замена в чеке строкой не печатается, и цена масла одна и та же, забирают его с собой или меняют на посту (ADR-027). «В сервис» — отметка чека плюс мастер; за такой чек мастеру начисляется ставка замены, по умолчанию 30 сом, из настройки филиала `sales.oil_change_master_fee_tyiyn`. Один чек — одна замена: за чек начисляется одна ставка, сколько бы канистр в нём ни было. Забрали масло без замены — мастеру не начисляется ничего.

Ставка фиксируется в `sales.master_fee_tyiyn` при проведении и позже не пересчитывается (инвариант 3). Строки `kind = service` остаются в API для прочих работ, но касса их не добавляет, и начисление по строке больше не считается (`master_fee_tyiyn` строки = 0): иначе за один чек мастеру начислилось бы дважды. Ставку правит владелец на экране «Услуги».

## Продажа

`POST /sales`
```
{
  op_id, client_time,
  sale_type: takeaway | service,
  cashier_id, master_id?,           -- master обязателен при service
  comment?,
  lines: [
    {kind: piece,     product_id, qty,             unit_price_tyiyn},
    {kind: container, product_id, qty (канистры),  unit_price_tyiyn},
    {kind: pour,      product_id, qty (мл),        unit_price_tyiyn (за литр)},
    {kind: service,   service_id, qty,             unit_price_tyiyn}
  ],
  payments: [{method: cash|card|transfer, amount_tyiyn}]
}
```

## Алгоритм

```
в run_operation:
  проверить: строки есть; cashier активен и is_cashier; при service — master активен и is_master;
             при takeaway строк service нет и master не указан
  для каждой строки:
     piece:     товар unit=piece; units = qty;                 amount = qty · price;  list = sale_price
     container: товар unit=ml;    units = qty · container_ml;  amount = qty · price;  list = sale_price
     pour:      товар unit=ml;    units = qty;                 amount = div_round(qty · price, 1000); list = pour_price
     service:   units = 0;                                      amount = qty · price;  list = service.price,
                master_fee = qty · service.master_fee
     qty > 0, price ≥ 0
  total = Σ amount
  master_fee чека = ставка замены из настроек, если sale_type = service, иначе 0
  Σ payments = total, каждый платёж > 0, иначе 422
  sale = insert (number = next(sale_seq))
  для товарных строк:
     bp = branch_products for update
     cost = cost_of(units, bp...)
     apply_movement(product, −units, −cost, 'sale', sale.id)
     line.cost_tyiyn = cost
  insert lines, payments
  если unit_price ≠ list_price → журнал sale.price_override по строке
  audit sale.post
  ответ: чек (cost_tyiyn — только владельцу)
```

Остаток может уйти в минус: продажа проводится, товар помечается для проверки (инвариант 10).

## Возврат

`POST /sales/{id}/return {op_id, comment, lines: [{line_no, qty}], payments: [{method, amount_tyiyn}]}`

```
исходный чек должен быть kind=sale
для каждой строки возврата:
  уже_возвращено = Σ qty этой строки во всех возвратах
  qty ≤ исходное qty − уже_возвращено, иначе 422
  amount = div_round(исходный amount · qty, исходное qty)
  cost   = div_round(исходный cost · qty, исходное qty)
  master_fee строк аналогично; начисление за замену возвращается целиком, только если
    возвращены все товарные строки чека: саму работу мастер уже сделал
  товарная строка: units пропорционально; apply_movement(+units, +cost, 'sale_return')
return_sale: kind=return, reversal_of=исходный, суммы со знаком минус
Σ payments = Σ amount возврата
```

## Чтение

- `GET /sales?date=YYYY-MM-DD` (по Asia/Bishkek) → список с итогами и суммами по способам оплаты.
- `GET /sales/{id}` → чек со строками, платежами и возвратами.

## Отложенные чеки

Клиент ушёл за второй канистрой, а за ним очередь: чек откладывается кнопкой «Отложить» и касса свободна. Отложенных может быть сколько угодно, в них можно докладывать позиции, оплачивается чек в самом конце.

Отложенные живут на устройстве (`localStorage`), а не на сервере: это незавершённый чек, он ничего не списывает и не занимает номер, а касса на точке одна. Переживают перезагрузку страницы и браузера. Возврат к отложенному откладывает текущий чек, так что ничего не теряется; проведённый чек из отложенных удаляется.

## Клиент — экран «Касса»

- Переключатель «На вынос / В сервис». В сервисе — выбор мастера; кнопок услуг нет, цена масла не меняется.
- Выбор кассира (запоминается до смены).
- Поле сканера всегда в фокусе: Enter после кода добавляет товар; повторный скан увеличивает количество.
- Поиск товара по тексту с фильтром по категории.
- Для масла выбор: «Канистра» или «Розлив, л» (ввод литров с шагом 0,1 → мл).
- Цена строки редактируется; изменённая цена подсвечивается.
- Цена строки не может быть ниже закупочной, кроме подарка (ADR-042): сервер сравнивает сумму строки с её себестоимостью при проведении и отвечает 422 «цена ниже закупочной». Администратору сама закупочная цена в ответе не называется (инвариант 13). Чек без сети принимается и уходит владельцу уведомлением `sale.below_cost` (SPEC-09).
- Итог, оплата: кнопки «Наличные», «Карта», «Перевод», «Смешанная». Для наличных — поле «получено» и сдача.
- После проведения — номер чека, кнопка «Печать чека» (HTML-шаблон), очистка.
- Количество меняется кнопками −/+ (шаг 1 или 0,5 л для розлива); строка, где продают больше остатка, помечается (продажа не запрещается, инвариант 10).
- Единственный активный кассир или мастер выбирается автоматически.
- Кнопка «Провести» заблокирована, пока не заполнено обязательное: нет строк, не выбран кассир, в сервисе не выбран мастер, сумма оплат не равна итогу. Рядом с кнопкой перечислено, чего не хватает; сервер те же проверки делает заново (инвариант 12).
- Для наличных — кнопки «Без сдачи» и ближайших купюр, крупный показ сдачи; Enter в поле «Получено» или Ctrl+Enter проводят чек.
- Незавершённый чек хранится в sessionStorage вкладки и не теряется при переходе на другой экран.
- «Чеки за день»: переключение дней стрелками, выручка, число чеков, средний чек, возвраты, суммы по способам оплаты; список, просмотр, оформление возврата.

## Доставка

Доставка бесплатная (BLUEPRINT §6, вопросы 16 и 21), поэтому в чеке только адрес: `delivery_address` в `POST /sales`, переключатель «Доставка (бесплатно)» с обязательным адресом в кассе, адрес в печатном чеке и на экране чека. В выручку и прибыль доставка не входит.

## Критерии приёмки

- [x] Строка дешевле своей себестоимости → 422; ровно по себестоимости и подарок проводятся (ADR-042).
- [ ] Розлив 1500 мл по 333,33 с/л → 49 999,5 тыйын округляется до 50 000 (500,00 с).
- [ ] Сумма оплат не равна итогу → 422, ничего не записано.
- [ ] Продажа в сервис без мастера → 422.
- [ ] Чек «в сервис» на две канистры: `master_fee_tyiyn` чека = 3000 тыйын, строк услуг в чеке нет.
- [ ] Тот же товар на вынос и в сервис стоит одинаково.
- [ ] Чек на вынос с `master_id` → 422.
- [ ] Отложенный чек возвращается в кассу с товарами, клиентом и мастером; проведение его удаляет.
- [ ] Отложенный чек возвращается в кассу с товарами, клиентом и мастером; проведение его удаляет.
- [ ] Полный возврат чека с заменой снимает начисление мастеру; частичный возврат его оставляет.
- [ ] Продажа списывает остаток и стоимость, себестоимость строки фиксируется.
- [ ] Возврат больше проданного → 422; частичный возврат возвращает пропорциональную стоимость.
- [ ] Администратор не получает `cost_tyiyn` в ответе.
- [ ] Повтор `op_id` не создаёт второй чек.
- [ ] Продажа при нулевом остатке проходит и помечает товар.
