# SPEC-04. Касса: продажа и возврат

## Задача

Чек на вынос или с заменой, с товарами, маслом канистрой и на розлив; кассир и мастер из справочника; ручная оплата наличными, картой, переводом, в том числе смешанная; возврат сторнирующим чеком.

## Замена масла — отметка, а не услуга

Замена в чеке строкой не печатается, и цена масла одна и та же, забирают его с собой или меняют на посту (ADR-027). «В сервис» — отметка чека плюс мастер; за такой чек мастеру начисляется ставка замены, по умолчанию 30 сом, из настройки филиала `sales.oil_change_master_fee_tyiyn`. Один чек — одна замена: за чек начисляется одна ставка, сколько бы канистр в нём ни было. Забрали масло без замены — мастеру не начисляется ничего.

Ставка фиксируется в `sales.master_fee_tyiyn` при проведении и позже не пересчитывается (инвариант 3). Строки `kind = service` остаются в API для прочих работ, но касса их не добавляет, и начисление по строке больше не считается (`master_fee_tyiyn` строки = 0): иначе за один чек мастеру начислилось бы дважды. Ставку правит владелец на экране «Услуги».

## Продажа

`POST /sales`
```
{
  op_id, client_time,
  sale_type: takeaway | service,
  cashier_id, master_id?,           -- master обязателен при service
  comment?,
  lines: [
    {kind: piece,     product_id, qty,             unit_price_tyiyn},
    {kind: container, product_id, qty (канистры),  unit_price_tyiyn},
    {kind: pour,      product_id, qty (мл),        unit_price_tyiyn (за литр)},
    {kind: service,   service_id, qty,             unit_price_tyiyn}
  ],
  payments: [{method: cash|card|transfer|debt|bonus|battery, amount_tyiyn, grams?, price_per_kg_tyiyn?}]
}
```

### Старый аккумулятор в оплату (SPEC-27, ADR-071)

Платёж `{method: battery, grams, amount_tyiyn}`: клиент сдал старый аккумулятор, сумма = вес × цена за кг: присланная `price_per_kg_tyiyn` (кассир поменял цену в чеке, больше нуля, ADR-078), без неё — цена приёма из настройки `batteries.intake_per_kg_tyiyn` (SPEC-03, ADR-048), с округлением в одном месте (`div_round(grams · price, 1000)`). Сумму считает сервер; касса показывает её заранее («12 кг × 50 с = 600 с, к оплате 9 400 с»), и если присланная сумма не совпала с расчётом сервера (цену приёма поменяли), чек не проводится (422 «цена приёма изменилась»). В чеке не больше одного такого платежа; вес — от 1 г до 10 т; цена приёма 0 — способ недоступен.

- Сумма уменьшает остаток к оплате; Σ платежей по-прежнему равна итогу чека.
- В той же транзакции лом приходует на склад: карточка «Аккумуляторы б/у (на вес)», `apply_movement(+grams, +amount, 'battery_tradein', sale.id)`, последняя цена приёма обновляется — как у приёма за наличные, только без денег из кассы. Движение `battery_tradein`, как приход и приём, задаёт стоимость остатка, ушедшего в минус (ADR-044).
- Выручка чека не уменьшается: строки и итог те же, лом — запас со своей стоимостью (SPEC-08).
- 2 % кассира — с этой части тоже: это оплата, а не скидка (в отличие от баллов, ADR-065). Комиссии банка нет, в кассу денег не приходит. Баллы клиенту (SPEC-19) с этой части не начисляются: только с денег.
- Без сети способ недоступен: касса блокирует кнопку «Сдал аккумулятор», цену считает сервер (SPEC-09).
- В ленте владельцу (SPEC-13): «аккумулятор 12 кг — 600 с»; на печати чека — «Аккумулятор 12 кг»; в чеках дня и смене — строка «Аккумуляторами».

### Полярность в названии (SPEC-27)

У товара с характеристикой `polarity` (аккумуляторы, SPEC-02) название строки чека — с отметкой «(Л)» для прямой (+ слева) и «(П)» для обратной (+ справа): в ответе чека, на печати, в поиске и строке кассы.

## Алгоритм

```
в run_operation:
  проверить: строки есть; cashier активен и is_cashier; при service — master активен и is_master;
             при takeaway строк service нет и master не указан
  для каждой строки:
     piece:     товар unit=piece; units = qty;                 amount = qty · price;  list = sale_price
     container: товар unit=ml;    units = qty · container_ml;  amount = qty · price;  list = sale_price
     pour:      товар unit=ml;    units = qty;                 amount = div_round(qty · price, 1000);
                list = canister_pour_price(sale_price, container_ml) — от цены канистры (ADR-074)
     service:   units = 0;                                      amount = qty · price;  list = service.price,
                master_fee = qty · service.master_fee
     qty > 0, price ≥ 0
  total = Σ amount
  master_fee чека = ставка замены из настроек, если sale_type = service, иначе 0
  Σ payments = total, каждый платёж > 0, иначе 422
  sale = insert (number = next(sale_seq))
  для товарных строк:
     bp = branch_products for update
     cost = cost_of(units, bp...)
     apply_movement(product, −units, −cost, 'sale', sale.id)
     line.cost_tyiyn = cost
     часть units без остатка и без прошлой закупки → line.cost_unknown, 2 % кассира ждут цены (SPEC-07)
  insert lines, payments
  если unit_price ≠ list_price → журнал sale.price_override по строке
     (прайс, который видела касса, — только у чека без сети, SPEC-09; онлайн — прайс сервера)
  машина клиента убрана (active = false) → 409 «верните её в карточке клиента» (SPEC-16)
  audit sale.post
  ответ: чек (cost_tyiyn — только владельцу)
```

Остаток может уйти в минус: продажа проводится, товар помечается для проверки (инвариант 10).

## Возврат

`POST /sales/{id}/return {op_id, comment, lines: [{line_no, qty}], payments: [{method, amount_tyiyn}]}`

```
исходный чек должен быть kind=sale
для каждой строки возврата:
  уже_возвращено = Σ qty этой строки во всех возвратах
  qty ≤ исходное qty − уже_возвращено, иначе 422
  amount = div_round(исходный amount · qty, исходное qty)
  cost   = div_round(исходный cost · qty, исходное qty)
  master_fee строк аналогично; начисление за замену возвращается целиком, только если
    возвращены все товарные строки чека: саму работу мастер уже сделал
  товарная строка: units пропорционально; apply_movement(+units, +cost, 'sale_return')
return_sale: kind=return, reversal_of=исходный, суммы со знаком минус
Σ payments = Σ amount возврата
```

Возврат с выдачей наличных (платёж `cash` > 0) проводится только при открытой смене «Кассы»: иначе 409 «возврат наличными — только при открытой смене: откройте смену на экране «Смена»» (ADR-065, SPEC-05). Проверка — после проверок сумм, долга и баллов, поэтому их ошибки (422) приходят первыми. Возврат на карту, перевод, с долга и баллами смены не требует. Возврат только онлайн: офлайн-очередь кассы возвратов не содержит (SPEC-09). Экран возврата предупреждает «Смена не открыта» до отправки.

Возврат чека с оплатой аккумулятором (SPEC-27): деньгами возвращается не больше, чем по чеку платили не аккумулятором (за вычетом прежних возвратов); остальное — платёж `battery` с суммой (вес сервер считает сам — доля веса чека по сумме, последняя часть забирает остаток). Вес уходит со склада той же стоимостью (`battery_tradein_return`), денег за него не выдают. Попытка вернуть эту часть деньгами — 422 «… верните аккумулятором». Если лом уже продан (на складе меньше нужного веса) — 409 «… может вернуть деньгами только владелец»; владелец передаёт `battery_cash: true` и возвращает её деньгами (журнал `sale.return_battery_cash`), администратору это 403. Экран возврата сам делит сумму: «600 с возвращается аккумулятором», у владельца — отметка «Лом уже продан — вернуть эту часть деньгами».

Комиссия банка возврата картой — по ставке учётного дня исходного чека и не больше невозвращённой комиссии чека (SPEC-08). Процент кассира снимается так же, как начислялся: с валовой за вычетом баллов (SPEC-07, ADR-065).

## Чтение

- `GET /sales?date=YYYY-MM-DD` (по Asia/Bishkek) → список с итогами и суммами по способам оплаты.
- `GET /sales/{id}` → чек со строками, платежами и возвратами.

## Отложенные чеки

Клиент ушёл за второй канистрой, а за ним очередь: чек откладывается кнопкой «Отложить» и касса свободна. Отложенных может быть сколько угодно, в них можно докладывать позиции, оплачивается чек в самом конце.

Отложенные живут на устройстве (`localStorage`), а не на сервере: это незавершённый чек, он ничего не списывает и не занимает номер, а касса на точке одна. Переживают перезагрузку страницы и браузера. Возврат к отложенному откладывает текущий чек, так что ничего не теряется; проведённый чек из отложенных удаляется.

## Клиент — экран «Касса»

- Переключатель «На вынос / В сервис». В сервисе — выбор мастера; кнопок услуг нет, цена масла не меняется.
- Выбор кассира (запоминается до смены).
- Поле сканера всегда в фокусе: Enter после кода добавляет товар; повторный скан увеличивает количество.
- Поиск товара по тексту с фильтром по категории.
- Для масла выбор: «Канистра» или «Розлив, л» (ввод литров с шагом 0,1 → мл). На розлив продаётся любое масло; цена литра — от цены канистры (ADR-074), касса считает её той же функцией, что сервер (`pourPricePerL`).
- Цена строки редактируется; изменённая цена подсвечивается.
- Цена строки не может быть ниже закупочной, кроме подарка (ADR-042): сервер сравнивает сумму строки с её себестоимостью при проведении и отвечает 422 «цена ниже закупочной». Администратору сама закупочная цена в ответе не называется (инвариант 13). Чек без сети принимается и уходит владельцу уведомлением `sale.below_cost` (SPEC-09).
- Итог, оплата: кнопки «Наличные», «Карта», «Перевод», «Смешанная». Для наличных — поле «получено» и сдача.
- После проведения — номер чека, кнопка «Печать чека» (HTML-шаблон), очистка.
- Количество меняется кнопками −/+ (шаг 1 или 0,5 л для розлива); строка, где продают больше остатка, помечается (продажа не запрещается, инвариант 10).
- Единственный активный кассир или мастер выбирается автоматически.
- Кнопка «Провести» заблокирована, пока не заполнено обязательное: нет строк, не выбран кассир, в сервисе не выбран мастер, сумма оплат не равна итогу. Рядом с кнопкой перечислено, чего не хватает; сервер те же проверки делает заново (инвариант 12).
- Для наличных — кнопки «Без сдачи» и ближайших купюр, крупный показ сдачи; Enter в поле «Получено» или Ctrl+Enter проводят чек.
- Незавершённый чек хранится в sessionStorage вкладки и не теряется при переходе на другой экран.
- «Чеки за день»: переключение дней стрелками, выручка, число чеков, средний чек, возвраты, суммы по способам оплаты; список, просмотр, оформление возврата.

## Доставка

Доставка бесплатная (BLUEPRINT §6, вопросы 16 и 21), поэтому в чеке только адрес: `delivery_address` в `POST /sales`, переключатель «Доставка (бесплатно)» с обязательным адресом в кассе, адрес в печатном чеке и на экране чека. В выручку и прибыль доставка не входит.


## Плитки «ходовое» (ADR-055)

Над чеком — плитки товаров и услуг, которые продают чаще всего: одно касание добавляет строку (масло — канистрой). Состав и порядок (до 24) задаёт владелец ссылкой «Настроить»; хранится в настройке `favorites`, `GET/PUT /settings/favorites`. Влитые карточки ведут на основную, архивные и отключённые не показываются.
## Дополнено SPEC-29, часть B (19.10.2026)

- Касса крупнее для пальца (SPEC-29 §17): плитки «ходовое», «−»/«+» и количество, способы оплаты, купюры, «Провести чек» — не ниже 48 точек.
- «Это замена масла?» (SPEC-29 §18): чек на вынос с моторным маслом перед проведением спрашивает; «Да» — чек «В сервис» (мастер, клиент, машина), «Нет» — на вынос; для одного чека — один раз.
- Пробег — в единице машины (`mileage`, `mileage_unit`, ADR-084); «через сколько менять» масло — `book_intervals` в чеке замены, сохраняется интервалом машины в транзакции чека (SPEC-29 §23).

## Дополнено SPEC-30 (21.10.2026)

**Оплата «По счёту»** (SPEC-30 §1, ADR-095): кнопки оплаты 3 + 3 — наличные, карта / QR банка, QR владельцу; «По счёту», в долг, смешанная. «По счёту» есть и в смешанной оплате; нужен клиент (иначе 422 «По счёту платит клиент — выберите его»); деньги — на счёт с отметкой «По умолчанию для «По счёту»», без неё — на счёт карты; комиссии нет; без сети доступна; возврат — с того же счёта.

**Вид замены и ставка мастеру** (SPEC-30 §2, ADR-096; заменяет раздел «Замена масла — отметка, а не услуга» для новых чеков):
- «В сервис» сразу открывает окно «Вид замены»: на кнопке (от 96 точек) цена клиенту или «бесплатно — масло наше» и «мастеру N с»; видов в чеке может быть несколько. Без вида — 422 «Выберите вид замены».
- Цена вида замены — 0 при флажке «Бесплатно с нашим маслом» и нашем масле в чеке (товар категории вида «масло», не подарок), иначе цена клиенту; касса пересчитывает её при добавлении и удалении масла, если цену не меняли руками.
- Мастеру — сумма ставок видов замены (количество × ставка, фиксируется в строке). Ставка за чек из `sales.oil_change_master_fee_tyiyn` — только чеку без сети без вида замены, с причиной владельцу «чек «в сервис» без вида замены».
- Возврат: ставка уходит вместе с возвращённой строкой вида замены, по количеству (`payroll::ReturnAccrual.fee_back`); возврат товара ставку не трогает; ставка за чек у прежних чеков — при возврате целиком.

**Данные клиента** (SPEC-30 §3, ADR-100): чек «В сервис» — клиент-человек с именем и фамилией (прежняя карточка — полное имя из двух слов) или фирма; телефон клиента или приехавшего работника фирмы; машина с госномером; пробег больше 0. Онлайн — 422 «Чек «в сервис» — нужны данные клиента: …»; без сети — проведение с причиной «в сервис без данных клиента: …». Касса отмечает недостающее красной звёздочкой и даёт дописать имя, фамилию и телефон прямо в карточку; без связи касса чек из-за этого не держит.

**Скидка** (SPEC-30 §4, ADR-097): цена строки ниже `list_price` (у чека без сети — ниже прайса, который видела касса) — владелец или администратор с правом `discount`; онлайн без права — 403 «Скидку ставит владелец», без сети — причина «скидка без права: товар, цена, цена по каталогу». Для чека, отправленного владельцем за другого (`claimed_user_id`), проверяется право того пользователя. Касса без права цену не правит (карандаша нет). Подарок, баллы и цена выше каталожной — не скидка.

**После проверки вживую (22.10.2026):** без права `discount` цену строки можно поднять — поле правится; ниже прайса — подпись «ниже прайса … — скидку ставит владелец» и «Провести» недоступно (сервер и так принимает только повышение). Цена строки вне правки — с разрядами и «с» («2 500 с»). Вид замены выбирается отметками, окно закрывает «Готово»; снятая отметка убирает вид из чека. Клиент, найденный по имени или телефону, — его единственная машина ставится сама; госномер из запроса ищется среди машин, только если запрос похож на госномер (`looksLikePlate`). Подпись поля клиента: в чеке «В сервис» — «Для чека «В сервис» обязателен», иначе «Для продажи в долг — обязателен» — только при праве `sale_debt`. На чеке — разбивка «Мастеру за замену» по видам замены (строки с `master_fee_tyiyn`).

**Бесплатная замена — только с маслом того же вида** (SPEC-30 §15, ADR-104; уточняет «Вид замены»):
- Услуга «бесплатно с нашим маслом» стоит 0, только если в чеке нашего масла её категории (`services.oil_category_id`, не подарок) не меньше одной канистры — наименьшего `container_ml` среди этих строк; розлив считается в мл вместе с канистрами. Иначе — цена клиенту. Считает сервер (`with_our_oil`, `domain::oil_service`), касса — так же (`oilEnough`, `servicePrice` в `web/src/lib/serviceSale.ts`); цена в чеке пересчитывается при добавлении и удалении масла, если её не меняли руками.
- Возврат по чеку: если возврат масла этой категории опускает его ниже канистры, а бесплатная услуга остаётся (не возвращается и ещё не удержана), из суммы возврата удерживается цена услуги из справочника × оставшееся количество, не больше суммы возврата. В документе возврата это строка услуги с плюсом (`sale_lines.withheld_for` — номер строки услуги исходного чека; номер строки — 1000 + он, количество 0, ставки мастеру нет); итог возврата и оплаты — за вычетом удержания. В окне возврата, на экране чека и в печати — «Удержано за замену: N с». Удержанное входит в выручку услуг (прибыль) и в «Замены» как оплата клиента; удерживается один раз на строку услуги. `SaleLineOut` отдаёт `oil_category_id`, `withhold_price_tyiyn` (бесплатная услуга, ещё не удержанная) и `withheld_for`.

**Возврат без чека** (SPEC-30 §16, ADR-105): `POST /sales/return-without-receipt {op_id, lines: [{kind, product_id, qty, amount_tyiyn}], method, account_id?, party_id?, cashier_id?, comment}` — только владелец (администратору 403). Строки — штуки, канистры, розлив (мл), вес (г); сумма строки задаётся (окно подставляет текущую цену продажи). Причина обязательна (422). Деньги: `cash` — из «Кассы» только при открытой смене (иначе 409), `card` / `transfer` / `invoice` — со счёта (выбранного или по умолчанию для способа), комиссии банка нет. Документ — `sales` вида `return` без `reversal_of`, `no_receipt = true` (миграция 0059 меняет ограничение); кассир — кассир открытой смены, без смены — указанный. Товар возвращается на склад по текущей средней себестоимости (остатка нет — по последней закупочной, закупок не было — 0; `costing::return_value`); выручка уменьшается на сумму, себестоимость — на стоимость вернувшегося товара. 2 % кассиру и ставки мастеру не трогаются, долг и баллы — тоже. Журнал и уведомление владельцу — `sale.return_no_receipt`; повтор `op_id` — тот же документ. Экран: «Чеки за день» → «Возврат без чека» и кнопка у владельца в режиме кассы (окно `NoReceiptReturn`: поиск и скан товара, количество, сумма, способ, кассир без смены, клиент, причина; после — «Печать» и «Открыть»). В «Чеках за день» и в боте — отметка «возврат без чека», в отчёте смены во вкладке «Возвраты» — «Без чека», в печати — «Возврат без чека» с причиной.

## Критерии приёмки

- [x] Строка дешевле своей себестоимости → 422; ровно по себестоимости и подарок проводятся (ADR-042).
- [ ] Розлив 1500 мл по 333,33 с/л → 49 999,5 тыйын округляется до 50 000 (500,00 с).
- [x] Канистра 4 л за 2 000 с: прайс розлива 500 с за литр, 4 л розливом = 2 000 с, 2,5 л = 1 250 с, правки цены нет (`pour_price_comes_from_canister_price`, ADR-074).
- [ ] Сумма оплат не равна итогу → 422, ничего не записано.
- [ ] Продажа в сервис без мастера → 422.
- [ ] Чек «в сервис» на две канистры: `master_fee_tyiyn` чека = 3000 тыйын, строк услуг в чеке нет.
- [ ] Тот же товар на вынос и в сервис стоит одинаково.
- [ ] Чек на вынос с `master_id` → 422.
- [ ] Отложенный чек возвращается в кассу с товарами, клиентом и мастером; проведение его удаляет.
- [ ] Отложенный чек возвращается в кассу с товарами, клиентом и мастером; проведение его удаляет.

- [ ] Продажа списывает остаток и стоимость, себестоимость строки фиксируется.
- [ ] Возврат больше проданного → 422; частичный возврат возвращает пропорциональную стоимость.

## Дополнено SPEC-31 (22.10.2026)

- Оплата «Карта / QR банка» (и часть картой в смешанной) может ссылаться на оплаченный QR банка Optima Business: у оплаты поле `bank_qr_id`. Сервер проверяет: QR этого филиала оплачен, сумма та же, к другому чеку не привязан — иначе 409; деньги ложатся на счёт учёта из настройки «Optima Business». Чек без сети с такой ошибкой проводится без ссылки, причина уходит владельцу (`sale.offline_bypass`). Без QR — как раньше, ручная отметка. Возврат ссылку не несёт.
- На кассе «QR на сумму» видна, когда интеграция настроена и сервер на связи; пока QR ждёт оплаты, «Провести чек» недоступна.

## Дополнено SPEC-35 (26.10.2026)
