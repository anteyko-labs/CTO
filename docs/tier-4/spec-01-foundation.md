# SPEC-01. Основа: вход, роли, журнал, идемпотентность

## Задача

Каркас сервера и клиента, на котором строятся остальные функции: вход владельца и администратора, проверка прав на сервере, журнал действий, защита от повторной отправки, единое правило округления.

## Состав

1. Схема БД: `branches`, `users`, `sessions`, `operations`, `audit_log`, `settings`, счётчики номеров документов.
2. Первичная настройка: если пользователей нет, при старте создаются филиал «Основной» и владелец из `BOOTSTRAP_OWNER_LOGIN` / `BOOTSTRAP_OWNER_PASSWORD`. Без этих переменных и без пользователей сервер пишет предупреждение и работает (вход невозможен).
3. Эндпоинты:
   - `POST /auth/login {login, password}` → cookie + `{user}`.
   - `POST /auth/logout`.
   - `GET /auth/me` → `{id, login, full_name, role, branch_id}`.
   - `GET /users`, `POST /users`, `PATCH /users/{id}` — только владелец. Нельзя деактивировать или понизить последнего активного владельца.
4. Модуль денег `domain::money`: единственная функция деления с округлением.

## Алгоритм

**Вход**
```
найти активного пользователя по login (без учёта регистра)
если нет или argon2.verify(password) ложь → 401 (одинаковый ответ, задержка не раскрывает наличие логина)
token = 32 случайных байта; хранить sha256(token)
expires_at = now + 30 дней
cookie avtodom_session = hex(token)
журнал: auth.login
```

**Ограничение перебора** (ADR-016)
```
ключ = логин в нижнем регистре
если login_attempts[ключ].locked_until > now → 429 «повторите через N мин»
неудача → failures += 1 (сброс до 1, если прошлой неудаче больше 15 мин)
failures ≥ 5 → locked_until = now + 15 мин, failures = 0
успех → удалить запись
```
Неизвестные логины учитываются так же, как существующие.

**Проверка сессии** — извлекатель `CurrentUser` в каждом защищённом обработчике: cookie → sha256 → сессия не истекла → пользователь активен. Иначе 401. `RequireOwner` — дополнительно `role = owner`, иначе 403.

**Устройство** — извлекатель `DeviceId`: заголовок `X-Device-Id`, UUID. Для изменяющих запросов обязателен, иначе 422.

**Идемпотентность**
```
fn run_operation(op_id, kind, user, f):
  tx = begin
  если в operations есть op_id:
     если kind или user другие → 409
     вернуть сохранённый response
  resp = f(tx)
  insert operations(op_id, user, kind, resp)   -- при гонке unique violation → rollback, прочитать сохранённый ответ
  commit
  вернуть resp
```

**Журнал** — `audit(tx, ctx, action, entity, entity_id, data)` в той же транзакции. Таблица `audit_log` защищена триггером от изменения и удаления (ADR-014).

**Округление**
```
div_round(n, d): целочисленное деление с округлением половины от нуля; d > 0
  q = n / d, r = n % d
  если 2·|r| ≥ d → q += sign(n)
```
Расчёт в i128, результат проверяется на вхождение в i64.

## Клиент

- Экран входа, хранение `device_id` в localStorage (создаётся один раз).
- Каркас приложения: меню по ролям, выход.
- Экран «Пользователи» для владельца.
- Общая функция запросов: добавляет `X-Device-Id`, при 401 ведёт на вход.
- Форматирование: `formatSom(tyiyn)` → «1 234,50 с», `formatLiters(ml)` → «2,5 л». Только для показа.

## Критерии приёмки

- [ ] Неверный пароль и несуществующий логин дают одинаковый ответ 401.
- [ ] Администратор получает 403 на `/users`.
- [ ] Повтор запроса с тем же `op_id` возвращает тот же ответ и не создаёт вторую запись.
- [ ] `UPDATE`/`DELETE` в `audit_log` отклоняются базой.
- [ ] `div_round`: 5/2=3, −5/2=−3, 7/3=2, 1/3=0, 2/3=1.
- [ ] Нельзя отключить последнего владельца.
- [ ] После 5 неудачных попыток вход по логину блокируется на 15 минут (429), в том числе с верным паролем; другие логины не затронуты.
