# SPEC-11. Подарки в чеке

## Задача

Подарок добавляется в чек сканированием штрихкода и правилом «при покупке X дать Y»; списывается со склада по себестоимости и уменьшает прибыль через себестоимость, а не через скидку (BLUEPRINT §3.3).

## Данные

```
gift_rules (id, branch_id, trigger_product_id, gift_product_id, gift_qty,
            active, user_id, created_at)
sale_lines.gift boolean not null default false   -- добавляется к SPEC-04
```

Подарок — обычная строка чека с `unit_price_tyiyn = 0` и признаком `gift`. Признак нужен, чтобы отличать подарок от скидки в 100 %: в отчёте владельца это разные вещи.

## Проведение

В `POST /sales` строка подарка приходит как обычная, с `gift: true`:

```
проверка: у строки gift цена 0, иначе 422
          подарок — только товарная строка (piece, container, pour)
списание и себестоимость — как у проданного товара (ADR-011):
          apply_movement(−units, −cost, 'sale'), cost фиксируется в строке
amount = 0, поэтому в выручку подарок не попадает, а в себестоимость попадает
```

Автоподарок: если в чеке есть `trigger_product_id` активного правила, сервер проверяет, что соответствующая строка подарка в чеке есть. Не добавляет сам — чек собирает касса, сервер только принимает (инвариант 12 касается прав, а не удобства). Клиент подставляет подарок сразу при добавлении товара-условия и разрешает его удалить.

Возврат подарка: строка возвращается как обычная, сумма 0, себестоимость возвращается на склад.

## API

- `GET /gift-rules`, `POST /gift-rules {trigger_product_id, gift_product_id, gift_qty}`, `PATCH /gift-rules/{id} {active}` — владелец.
- `GET /gift-rules/for-products?ids=` — правила по товарам чека; касса спрашивает их при добавлении товара и в снимке офлайна (SPEC-09).
- `GET /reports/gifts?from&to` → подарено штук и на какую себестоимость, по товарам. Только владелец.

## Клиент

- В кассе кнопка «Подарок»: следующий отсканированный код добавляется строкой с ценой 0 и пометкой «подарок». Тот же результат — кнопка «Сделать подарком» у строки.
- Подарок в чеке виден: цена 0, пометка, в печатном чеке строка «подарок».
- При добавлении товара-условия подарок подставляется автоматически с подсказкой «добавлен по правилу», кассир может удалить.
- Экран «Подарки» у владельца: правила и отчёт за период.

## Права

| Действие | Владелец | Администратор |
| --- | --- | --- |
| Добавить подарок в чек | да | да |
| Правила подарков: создание и правка | да | нет |
| Отчёт по подаркам (себестоимость) | да | нет |

## Критерии приёмки

- [ ] Подарок с ценой больше 0 → 422.
- [ ] Чек с подарком: выручка не изменилась, себестоимость выросла на себестоимость подарка, остаток уменьшился.
- [ ] Прибыль дня уменьшилась ровно на себестоимость подарка (SPEC-08).
- [ ] Подарок добавляется сканированием кода и виден в печатном чеке пометкой.
- [ ] Товар-условие добавлен → касса подставила подарок по правилу; удаление подарка возможно.
- [ ] Возврат чека с подарком возвращает подарок на склад.
- [ ] Администратор: создание правила → 403.
