# SPEC-19. Бонусные баллы клиентов через Телеграм-бот

## Задача

Карта лояльности — это Телеграм-бот (SPEC-18): клиент, подключившийся своим номером, копит баллы за каждую замену масла (ADR-124), видит их в боте и тратит на кассе как скидку (решение заказчика, ADR-053).

## Правила

- 1 балл = 1 сом. Храним в тыйынах в журнале `loyalty_ledger`; остаток — сумма записей. Записи не правятся.
- Начисление — 0,5 % от оплаченного деньгами (наличные, карта, QR), с товаров и с услуг чека, — только за чек «В сервис» с заменой масла: услугой с флажком «Бесплатно с нашим маслом» и категорией масла (ADR-104, ADR-124); остальные чеки баллов не дают, списать баллы можно в любом. Чек без сети сервер разбирает так же. С долга и с оплаченного баллами не начисляется. Процент владелец меняет в «Настройки → Телеграм» (0–10 %); ставка запоминается в записи.
- Участник — покупатель, у которого есть привязка в боте (`telegram_customers`). Не подключён — баллов нет. После отключения от бота новые не начисляются, накопленные сохраняются.
- Списание — на кассе «Услуги → Скидка баллами»: кассир вводит номер телефона, касса находит подключённого клиента и показывает остаток, кассир указывает, сколько списать (не больше остатка и итога). Чек оплачивается способом «Баллы» (`bonus`), остаток — как обычно. Клиент записывается в чек.
- Без связи баллы не списываются (касса не пускает). Если чек с баллами пришёл из очереди с признаком «без сети» (онлайн-отправка оборвалась без ответа), сервер проверяет остаток в момент проведения, как у онлайн-чека: хватает — проводит, не хватает — отказ, чек уходит владельцу как отклонённый. В минус баллы не уходят (ADR-059).
- Возврат: баллы, которыми платили, возвращаются способом «Баллы» (не больше списанного по чеку); с возвращённых денег начисленное снимается по той же ставке, но не больше начисленного по чеку.
- Прибыль: оплаченное баллами уменьшает чистую прибыль строкой «Скидки баллами» в день чека. Выручка и валовая не меняются, кассе и смене баллы денег не дают.
- Процент кассира (2 %) с части чека, оплаченной баллами, не начисляется: база — валовая прибыль чека за вычетом скидки баллами, не меньше нуля (SPEC-07, ADR-065).
- Бот: в книжке и на любое сообщение — остаток баллов; кнопка «⭐ Баллы» (`/баллы`) — остаток и последние 10 операций. После каждого чека клиенту приходит сообщение «начислено / списано, теперь у вас N» — с 09:00 до 20:00 по Бишкеку, ночные — утром (ADR-063).

## Данные

```
loyalty_ledger (id, branch_id, party_id, kind accrual|redeem|refund|accrual_back,
                amount_tyiyn, rate_bp?, doc_type, doc_id, created_at)   -- неизменяемый
loyalty_notices (ledger_id, sent_at)                                    -- что уже сообщили
sale_payments.method + 'bonus'
settings 'loyalty' { rate_bp }  -- по умолчанию 50
```

## API

- `GET /loyalty/lookup?phone=` → клиент из бота и остаток баллов (касса). Ищется только в филиале кассира и только если карточка с этим номером одна; несколько — 422 «оставьте номер в одной» (ADR-063).
- `GET /parties/{id}/loyalty` → остаток и история (карточка клиента).
- `GET/PUT /settings/loyalty { rate_bp }` — процент, менять может владелец.
- Продажа и возврат — прежние `POST /sales`, `POST /sales/{id}/return` с оплатой `bonus`.

## Дополнено SPEC-30 (21.10.2026)

Баллы у всех клиентов (SPEC-30 §12): `GET /parties/summary` отдаёт `points_tyiyn` и `points_clients` по всем клиентам филиала, без отбора экрана; на «Клиентах» — «Баллы у клиентов: N, на N с, у K клиентов». Сводка владельца (`GET /owner/dashboard`, поле `points {clients, points_tyiyn}`) — карточка «Баллы у клиентов», ведёт на «Клиенты». Считаются положительные остатки по клиентам (`loyalty::branch_total`).

## Критерии приёмки

- [x] Не подключён к боту — не начисляется, оплатить баллами нельзя.
- [x] 1000 с наличными → 5 баллов; списать больше остатка нельзя.
- [x] Списали 5 баллов, 495 с картой → начислено 2,48.
- [x] Возврат такого чека возвращает 5 баллов и снимает 2,48; вернуть баллами больше списанного нельзя.
- [x] Клиенту в бот — по сообщению на чек; кнопка «⭐ Баллы» показывает остаток.

## Дополнено задачей 002, П1 (31.10.2026) — баллы по товару, категории и общей ставке (ADR-140)

- Правило строки чека: товар → категория → общая ставка. В карточке товара «Баллы клиенту»: как в категории / не начислять / % от оплаченного / баллов за штуку (литр, кг — по единице товара). В категории — то же для её товаров («по общей ставке» вместо «как в категории»). Услуга — по общей ставке. Меняет только владелец: `PATCH /products/{id}` и `PATCH /categories/{id}` с `points {mode: inherit|none|percent|fixed, value}` (процент — сотые доли, 1–10 000; за единицу — тыйыны, до 1 000 000 баллов), `POST /products` — тоже; администратору — 403, правка без изменения баллов проходит как раньше. Изменение — в журнал `product.update` / `category.update` (было/стало).
- «Телеграм и баллы»: общая ставка (0–10 %) и выключатель «Начислять только в чеке с заменой масла» (по умолчанию — да, как ADR-124). `settings 'loyalty' {rate_bp, oil_change_only}`; `PUT /settings/loyalty` без `oil_change_only` его не меняет. Выключено — баллы дают любые чеки участника; текст бота «⭐ Баллы» — «За покупки — бонусные баллы».
- Начисление по строкам: деньги чека (наличные, карта, QR, по счёту) делятся по суммам строк; строки с одинаковым процентом считаются одним округлением и делятся по строкам — чек целиком по общей ставке даёт ровно прежнее `оплачено деньгами × ставка`. «За единицу» — ставка × единицы в доле оплаченного деньгами, не больше оплаченного за строку; подарок — 0. Долг и баллы по-прежнему не начисляют. Расчёт — `domain::points` (без float, I1).
- Запись `accrual` раскладывается по строкам в `loyalty_lines (ledger_id, sale_id, line_no, amount_tyiyn, source product|category|common)`, неизменяемая. Возврат строки снимает её баллы в доле возвращённого (последняя часть — точный остаток) записью `accrual_back` со строками (I4). Чеки до задачи 002 — как раньше: с возвращённых денег по ставке чека.
- Клиенту в бот: «Баллы по чеку № N: начислено 50 за Масло 5W-30 4л, Фильтр W712. Теперь у вас …» (до трёх строк, дальше «и ещё N»).
- Клиент: `web/src/components/PointsRuleField.tsx`, `web/src/lib/points.ts` (тест `points.test.ts`), `TelegramSettings.tsx`; сервер: `loyalty.rs`, `domain/points.rs`, `catalog.rs`, миграция `0076_loyalty_rules.sql`, тесты `server/tests/points_units.rs`, e2e `web/e2e/points-units.spec.ts`.
