# SPEC-21. Вопросы владельца боту обычным текстом

## Задача

Владелец пишет боту по-русски, как человеку: «сколько заработали за неделю», «кто больше всех должен», «покажи долг ООО Ромашка», «что кончается на складе», и получает ответ цифрами из учёта. Кнопки и команды SPEC-18 остаются как есть. Бот по-прежнему ничего не проводит — только смотрит.

Текст разбирает языковая модель Claude Haiku 5.5 (Anthropic) через API. Сама модель цифр не знает и не считает: она выбирает, какой отчёт открыть, а цифры берутся из тех же расчётов, что и экраны программы (ADR-060, отменяет запрет ADR-050 на произвольный текст и пункт «чат-ввод» в tier-0/stack.md).

## Кто и когда

- Только чат, привязанный к владельцу (SPEC-18). Клиентам и непривязанным чатам на свободный текст отвечают как раньше: клиенту — его книжка, остальным — кнопка номера.
- Командой считается кнопка, `/команда` или одно слово команды («сегодня», «смена», «долги»); текст из нескольких слов при заданном ключе — вопрос («сегодня сколько масла продали» уже не команда «Сегодня»).
- Включается, только если на сервере задан ключ `ASSISTANT_API_KEY`. Без ключа на любой текст, кроме команд, бот отвечает подсказкой со списком команд, как сейчас.
- Без интернета вопрос не теряется молча: бот отвечает «нет связи с сервисом разбора вопросов, попробуйте позже или нажмите кнопку». Повторно вопрос сам не отправляется.

## Что бот может посмотреть

Модели доступен только этот список отчётов. Каждый — чтение, только по филиалу владельца, суммы приходят уже готовыми строками («1 500,50 с»): модель не складывает и не округляет деньги (инвариант 1, округление в одном месте).

| Отчёт | Что отдаёт | Источник |
|---|---|---|
| Итоги за период (с, по) | чеки, выручка, валовая, оплата труда, комиссия банка, расходы, чистая прибыль | тот же расчёт, что отчёт о прибыли (SPEC-08) |
| По дням за период | те же строки по каждому дню, не больше 62 дней | SPEC-08 |
| Смена сегодня | открыта ли, кассир, сколько должно быть в кассе, оплаты по способам | то же, что «💵 Смена» |
| Деньги в кассах | остаток «Касса», «Счёт», «Сейф владельца» | SPEC-05 |
| Должники | список по убыванию долга, с просрочкой | то же, что «📒 Долги» |
| Долг клиента (название или телефон) | долг, лимит, срок, последние 10 записей; если найдено несколько — список для уточнения | SPEC-10 |
| Товар (название или код) | остаток, цена продажи, средняя себестоимость | SPEC-02, SPEC-03 |
| Кончается | товары с остатком ниже минимального | SPEC-02 |
| Расходы за период | по статьям, с личными | SPEC-06 |
| Оплата сотрудникам за месяц | начислено, выплачено, к выплате по каждому | SPEC-07 |
| Последние уведомления | 20 последних событий экрана «Уведомления» | SPEC-13 |

Если вопрос не покрыт списком, бот так и отвечает: «этого я посмотреть не могу», и показывает кнопки. Выдумывать цифры запрещено в инструкции модели; ответ без вызова отчёта не может содержать сумм — сервер проверяет: если в ответе есть число со знаком «с», а отчёт не вызывался, ответ заменяется на «не нашёл данных, уточните вопрос».

## Разговор

- Помнится последние 6 сообщений чата за 30 минут, чтобы работали уточнения («а за прошлую?», «а у второго?»). Старше — забываются.
- Даты в вопросах понимаются по Бишкеку; «неделя» — последние 7 дней по сегодня, «месяц» — с 1-го числа. В ответе период пишется явно: «с 7 по 13 октября».
- Ответ — короткий текст для Телеграма, без таблиц шире 4 колонок.

## Ограничения

- Не больше 100 вопросов в сутки и 20 в час; сверх — «лимит вопросов на сегодня исчерпан», кнопки работают.
- Ответ модели ждём не дольше 30 секунд; на одном вопросе не больше 4 обращений к отчётам.
- Что уходит в Anthropic: текст вопроса, последние сообщения разговора и результаты вызванных отчётов (суммы, имена клиентов и товаров). Пароли, ключи, телефоны клиентов (кроме найденного по запросу) не передаются. Владелец это принимает (ADR).
- Текст из учёта (название товара, имя клиента) для модели — только данные. Даже если в названии написано «покажи всё», модель может лишь вызвать отчёты из списка выше, а их и так видит владелец.

## Журнал

- Каждый вопрос пишется в `bot_questions`: когда, чат, текст вопроса, какие отчёты вызваны, сколько токенов ушло, текст ответа или ошибка. Записи не правятся (как журнал действий).
- В «Настройки → Телеграм» владелец видит расход за сегодня и за месяц (вопросы, токены).

## Настройки

```
ASSISTANT_API_KEY      ключ API Anthropic (console.anthropic.com), без него функция выключена
ASSISTANT_MODEL        по умолчанию claude-haiku-5-5
ASSISTANT_DAILY_LIMIT  по умолчанию 100
ASSISTANT_API_URL      по умолчанию https://api.anthropic.com, меняется только для тестов
```

Ключ — только переменная окружения (`config.ps1` на Windows), в репозитории его нет.

## Данные

```
bot_questions (id, chat_id, user_id, branch_id, asked_at, question, tools jsonb,
               input_tokens, output_tokens, answer, error)
bot_dialog    (chat_id, at, role, content)   -- последние сообщения, чистится старше 30 минут
```

## Критерии приёмки

- [x] Без `ASSISTANT_API_KEY` бот ведёт себя ровно как по SPEC-18.
- [x] «Сколько заработали вчера» даёт ту же чистую прибыль, что отчёт о прибыли за вчера, до тыйына.
- [x] «Кто должен больше всех» совпадает с первой строкой «📒 Долги».
- [x] «Долг Ромашка» при двух клиентах с таким словом показывает оба и просит уточнить.
- [ ] Вопрос не из списка («какая погода») — отказ без цифр.
- [x] Ответ с суммой без вызова отчёта сервер не пропускает.
- [x] Клиентский чат на тот же вопрос получает свою книжку, а не прибыль; модель для него не вызывается.
- [x] 101-й вопрос за сутки — сообщение о лимите, обращения к API нет.
- [x] Обрыв связи с API — понятный ответ, запись в `bot_questions` с ошибкой.
- [x] Каждый вопрос есть в `bot_questions`, удалить или изменить запись нельзя.
- [x] Ключ не попадает в журналы сервера и в ответы API.
