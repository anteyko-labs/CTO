# SPEC-21. Вопросы владельца боту обычным текстом

## Задача

Владелец нажимает «💬 Спросить» и пишет боту по-русски, как человеку: «сколько заработали за неделю», «кто больше всех должен», «покажи долг ООО Ромашка», «что кончается на складе», и получает ответ цифрами из учёта. Кнопки и команды SPEC-18 остаются как есть. Сам бот ничего не проводит: операции владельца в этом же режиме он только готовит черновиком, а проводит владелец кнопкой «✅ Провести» — SPEC-24 (ADR-068).

Текст разбирает языковая модель Claude Haiku 5.5 (Anthropic) через API. Сама модель цифр не знает и не считает: она выбирает, какой отчёт открыть, а цифры берутся из тех же расчётов, что и экраны программы (ADR-060, отменяет запрет ADR-050 на произвольный текст и пункт «чат-ввод» в tier-0/stack.md).

## Кто и когда

- Только личный чат, привязанный к владельцу (SPEC-18): из групп и каналов бот вопросов не принимает и молчит (ADR-070). Клиентам, работникам и непривязанным чатам на свободный текст отвечают как раньше: клиенту — его книжка, работнику — его кнопки, остальным — кнопка номера. Кнопки «💬 Спросить» у них нет, и её текст режим вопросов не включает.
- Вопросы — только в режиме «💬 Спросить» (ADR-067, решение заказчика 2026-10-15). У владельца внизу чата кнопка «💬 Спросить»; нажатие включает режим для этого чата и отвечает «Задайте вопрос о делах точки. Закончить — «✖ Закончить»», внизу — «✖ Закончить» и обычные кнопки владельца.
- Режим хранится на сервере (`bot_question_mode`, с филиалом и владельцем) и закрывается кнопкой «✖ Закончить» или через 10 минут без сообщений владельца; каждое сообщение в режиме (вопрос, кнопка внизу или нажатие кнопки под сообщением) продлевает его ещё на 10 минут. Включение и закрытие пишутся в журнал действий (`telegram.ask_on`, `telegram.ask_off`; закрытие по времени — с причиной «время»); при закрытии память разговора чата очищается, открытый черновик операции снимается (SPEC-24). Повторное «💬 Спросить» в открытом режиме только продлевает его — второй записи `telegram.ask_on` нет; после истечения оно сначала закрывает прежний режим (`telegram.ask_off`, «время»), потом открывает новый (ADR-070). Ответ, пришедший после «✖ Закончить», память разговора не пишет.
- Только пока режим открыт, свободный текст владельца уходит в сервис разбора. В режиме командой считается кнопка, `/команда` или одно слово команды («сегодня», «смена», «долги»); остальной текст — вопрос. Шесть цифр в открытом режиме — тоже вопрос, а не код привязки: чат уже привязан (ADR-070). Кнопки команд («📊 Сегодня», «💵 Смена», «📒 Долги») работают и в режиме, и без него и режим не закрывают.
- Вне режима свободный текст — подсказка с кнопками, как без ключа (SPEC-18): сервис не вызывается, первое слово команды по-прежнему работает как команда. Первый свободный текст после закрытия режима по времени получает «Режим вопросов закрыт — нажмите «💬 Спросить»», тоже без обращения к сервису.
- Прежнее правило «одно слово — команда, несколько слов — вопрос» вне режима не действует (отменено ADR-067).
- Включается, только если на сервере задан ключ `ASSISTANT_API_KEY`. Без ключа кнопки «💬 Спросить» нет, режим не включается, на любой текст, кроме команд, бот отвечает подсказкой со списком команд, как сейчас.
- Без интернета вопрос не теряется молча: бот отвечает «нет связи с сервисом разбора вопросов, попробуйте позже или нажмите кнопку». Повторно вопрос сам не отправляется.

## Что бот может посмотреть

Модели доступен только этот список отчётов (с SPEC-24 — ещё сводные отчёты о продажах, деньгах, складе и контрагентах и черновики операций, см. SPEC-24). Каждый — чтение, только по филиалу владельца, суммы приходят уже готовыми строками («1 500,50 с»): модель не складывает и не округляет деньги (инвариант 1, округление в одном месте).

| Отчёт | Что отдаёт | Источник |
|---|---|---|
| Итоги за период (с, по) | чеки, выручка, валовая, оплата труда, комиссия банка, расходы, чистая прибыль | тот же расчёт, что отчёт о прибыли (SPEC-08) |
| По дням за период | те же строки по каждому дню, не больше 62 дней | SPEC-08 |
| Смена сегодня | открыта ли, кассир, сколько должно быть в кассе, оплаты по способам | то же, что «💵 Смена» |
| Деньги в кассах | остаток «Касса», «Счёт», «Сейф владельца» | SPEC-05 |
| Долги | кто должен нам (по убыванию, с просрочкой) и кому должны мы — все контрагенты, как экран «Долги» | то же, что «📒 Долги» |
| Долг клиента (название или телефон) | долг, лимит, срок, последние 10 записей; если найдено несколько — список для уточнения | SPEC-10 |
| Товар (название или код) | остаток, цена продажи, средняя себестоимость | SPEC-02, SPEC-03 |
| Кончается | товары с остатком ниже минимального | SPEC-02 |
| Расходы за период | по статьям, с личными | SPEC-06 |
| Оплата сотрудникам за месяц | начислено, выплачено, к выплате по каждому | SPEC-07 |
| Последние уведомления | 20 последних событий экрана «Уведомления» | SPEC-13 |

Тема — только дела точки: продажи, деньги, склад, долги, оплата сотрудникам, смены, расходы, уведомления. На любой другой вопрос (погода, новости, общие знания, советы, просьба написать текст) инструкция модели требует ответить ровно «Я отвечаю только о делах точки: продажи, деньги, склад, долги, сотрудники.» без вызова отчётов (ADR-067). Отдельного фильтра по словам на сервере нет — тему решает инструкция. Если вопрос о делах точки, но не покрыт списком, бот так и отвечает: «этого я посмотреть не могу», и показывает кнопки. Выдумывать цифры запрещено в инструкции модели; ответ без прочитанного отчёта не может содержать сумм — сервер проверяет: если в ответе есть число со знаком «с», а ни один отчёт не прочитан без ошибки, ответ заменяется на «не нашёл данных, уточните вопрос» (отчёт с ошибкой и черновик операции отчётом не считаются; если за вопрос подготовлен черновик — ответ «Черновик готов — проверьте и нажмите «✅ Провести»», ADR-070).

## Разговор

- Помнится последние 6 сообщений чата за 30 минут, чтобы работали уточнения («а за прошлую?», «а у второго?»). Старше — забываются.
- Даты в вопросах понимаются по Бишкеку; «неделя» — последние 7 дней по сегодня, «месяц» — с 1-го числа. В ответе период пишется явно: «с 7 по 13 октября».
- Ответ — короткий текст для Телеграма, без таблиц шире 4 колонок.

## Ограничения

- Не больше 100 вопросов в сутки и 20 в час; сверх — «лимит вопросов на сегодня исчерпан» или «лимит вопросов на этот час исчерпан», кнопки работают.
- Ответ модели ждём не дольше 30 секунд; на одном вопросе не больше 4 вызовов отчётов (считаются вызовы, а не запросы к модели: два запроса по два вызова — предел).
- Ответ сервиса 400, 401 или 403 — «ключ сервиса разбора вопросов не подходит — проверьте настройки»; в журнал сервера пишется только код ответа (ADR-063).
- В очередь вопросов (по одному за раз) встаёт только свободный текст из чата в режиме «💬 Спросить»; кнопки и команды владельца отвечают сразу, не дожидаясь разбора вопроса. Кнопки клиента из чата владельца — подсказка, не вопрос.
- Что уходит в Anthropic: текст вопроса, последние сообщения разговора и результаты вызванных отчётов (суммы, имена клиентов и товаров). Пароли, ключи, телефоны клиентов (кроме найденного по запросу) не передаются. Владелец это принимает (ADR).
- Текст из учёта (название товара, имя клиента) для модели — только данные. Даже если в названии написано «покажи всё», модель может лишь вызвать отчёты из списка выше, а их и так видит владелец.

## Журнал

- Каждый вопрос пишется в `bot_questions`: когда, чат, текст вопроса, какие отчёты вызваны, сколько токенов ушло, текст ответа или ошибка. Записи не правятся (как журнал действий).
- В «Настройки → Телеграм» владелец видит расход за сегодня и за месяц (вопросы, токены).

## Настройки

```
ASSISTANT_API_KEY      ключ API Anthropic (console.anthropic.com), без него функция выключена
ASSISTANT_MODEL        по умолчанию claude-haiku-5-5
ASSISTANT_DAILY_LIMIT  по умолчанию 100
ASSISTANT_API_URL      по умолчанию https://api.anthropic.com, меняется только для тестов
```

Ключ — только переменная окружения (`config.ps1` на Windows), в репозитории его нет.

## Данные

```
bot_questions (id, chat_id, user_id, branch_id, asked_at, question, tools jsonb,
               input_tokens, output_tokens, answer, error)
bot_dialog    (chat_id, at, role, content)   -- последние сообщения, чистится старше 30 минут
                                             -- и при закрытии режима вопросов
bot_question_mode (chat_id, user_id, branch_id, started_at, last_at)
                                             -- режим «💬 Спросить»: открыт, пока last_at моложе 10 минут
```

## Критерии приёмки

- [x] Без `ASSISTANT_API_KEY` бот ведёт себя ровно как по SPEC-18.
- [x] «Сколько заработали вчера» даёт ту же чистую прибыль, что отчёт о прибыли за вчера, до тыйына.
- [x] «Кто должен больше всех» совпадает с первой строкой «📒 Долги».
- [x] «Долг Ромашка» при двух клиентах с таким словом показывает оба и просит уточнить.
- [ ] Вопрос не о делах точки («какая погода») — ровно «Я отвечаю только о делах точки: продажи, деньги, склад, долги, сотрудники.», без вызова отчётов (инструкция содержит фразу дословно — проверено тестом; поведение настоящей модели проверяется на точке).
- [x] Без «💬 Спросить» свободный текст владельца — подсказка с кнопками, обращения к сервису нет.
- [x] После «💬 Спросить» текст уходит в сервис; после «✖ Закончить» — снова подсказка без обращения.
- [x] 10 минут без сообщений — режим закрыт: следующий текст получает «Режим вопросов закрыт — нажмите «💬 Спросить»», обращения к сервису нет.
- [x] Кнопка команды в режиме отвечает сама и режим не закрывает.
- [x] Без ключа кнопки «💬 Спросить» нет и режим не включается.
- [x] Клиент, работник и непривязанный чат режим не включают, даже написав «💬 Спросить».
- [x] Ответ с суммой без вызова отчёта сервер не пропускает; отчёт с ошибкой — не отчёт (`bot_ask_mode_codes_restart_stop_and_claims`, ADR-070).
- [x] Шесть цифр в режиме — вопрос, неверного кода привязки нет; повторное «💬 Спросить» в режиме не пишет второе включение; после истечения — закрытие с причиной «время» и память очищена; нажатие кнопки под сообщением продлевает режим; ответ после «✖ Закончить» память не пишет (`bot_ask_mode_codes_restart_stop_and_claims`, ADR-070).
- [x] Клиентский чат на тот же вопрос получает свою книжку, а не прибыль; модель для него не вызывается.
- [x] 101-й вопрос за сутки — сообщение о лимите, обращения к API нет.
- [x] Обрыв связи с API — понятный ответ, запись в `bot_questions` с ошибкой.
- [x] Каждый вопрос есть в `bot_questions`, удалить или изменить запись нельзя.
- [x] Ключ не попадает в журналы сервера и в ответы API.
