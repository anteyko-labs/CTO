# SPEC-06. Операционные расходы

## Задача

Расходы по статьям с комментарием; расход из кассы уменьшает наличные; расходы уменьшают прибыль своего дня (BLUEPRINT §3.6, ADR-023).

## Данные

```
expense_articles (id, branch_id, name, owner_only, active)
expenses (id, branch_id, number, article_id, amount_tyiyn, source account | outside,
          account_id?, expense_date, comment, reversal_of,
          user_id, device_id, created_at)                         -- неизменяемая
```

- `amount_tyiyn` > 0 у расхода, < 0 у сторно.
- `source = account` — деньги ушли из кассы системы: наличными из «Кассы» или безналично со «Счёта» (`account_id`, по умолчанию касса смены). `source = outside` — «не из денег точки» — больше не принимается: 422, свои деньги владелец сначала вносит на счёт (SPEC-29 §5, ADR-079); прежние такие расходы остаются в истории и в прибыли своего дня.
- `expense_date` — день, к которому относится расход в отчёте о прибыли. По умолчанию сегодня (Asia/Bishkek).
- `owner_only` — статья видна и доступна только владельцу.

Статьи миграцией: «На развитие», «Хозтовары», «Налоги», «Личные расходы» (`owner_only`), «Прочее». Остальные статьи владелец добавляет сам.

Личные расходы владельца уменьшают и кассу, и прибыль магазина, как любая другая статья: один учёт, отдельного признака у статьи нет (ADR-023).

Статей «Зарплата» и «Проценты работникам» здесь нет: оплата сотрудников проходит начислениями и выплатами (SPEC-07). Иначе одни и те же деньги уменьшили бы прибыль дважды.

## Проведение

`POST /expenses {op_id, article_id, amount_tyiyn, source, account_id?, expense_date?, comment?}`

```
в run_operation:
  статья активна; amount > 0
  если статья «Прочее» — comment обязателен
  если source = account:
     lock cash_accounts; amount ≤ баланс кассы (422)
     для кассы типа register нужна открытая смена (409); для счёта смена не нужна
     cash_movement(expense, −amount, shift_id, doc = expense)
  expense = insert (number = next(expense_seq))
  audit expense.post
```

## Сторно

`POST /expenses/{id}/reverse {op_id, comment}`

- Новая строка `expenses` с `reversal_of`, суммой со знаком минус, той же статьёй и тем же `expense_date`: в отчёте за день расход и сторно взаимно гасятся.
- Для `source = account` — движение `reversal` на +amount в ту же кассу; для кассы смены нужна открытая смена.
- Повторное сторно → 409.

## Чтение

- `GET /expenses?from&to&article_id&source&account_id` → список с итогом по статьям.
- `GET /expense-articles`, `POST /expense-articles {name, owner_only?}`, `PATCH /expense-articles/{id} {name?, owner_only?, active?}` (имя, активность, `owner_only`). Название не длиннее 100 знаков и уникально в филиале (409). Создание (`expense.article_create`) и правка (`expense.article_update`, было/стало) — в журнале в одной транзакции со статьёй. Первая своя статья не отменяет начальные статьи филиала: они заводятся до неё.

## Права

| Действие | Владелец | Администратор |
| --- | --- | --- |
| Расход из кассы смены по обычной статье, за сегодня | да | да |
| Расход со счёта, расход `outside`, задним числом, статьи `owner_only` | да | нет |
| Сторно | любой расход | свой расход из кассы смены, пока она открыта |
| Просмотр | все | только расходы из кассы смены за 7 дней |
| Статьи: создание и правка | да | нет |

Администратор не видит расходов со счёта, расходов `outside` и статей `owner_only` — это сводные расходы магазина (инвариант 13).

## Клиент

- Экран «Расходы»: кнопка «Новый расход» — статья (крупные кнопки частых статей), сумма, откуда платим (касса или счёт — счёт только владельцу; «не из денег точки» убрано, SPEC-29 §5), дата (только владельцу), комментарий.
- Мелкий расход администратор проводит прямо с экрана кассы, не уходя из неё: статья, сумма, комментарий. Деньги уходят из кассы сразу, и это видно в разбивке смены (SPEC-05).
- Список за выбранный день или период с итогами по статьям; строка сторно показывается под исходной.
- Расходы из кассы видны в разбивке смены (SPEC-05).
- «Настройки → Статьи расходов» (владелец; ссылка «Статьи расходов» и на экране «Расходы»): список статей с отметками «только владелец» и «в выборе / скрыта»; «Добавить статью», «Переименовать», «Только владелец» / «Показывать администратору», «Скрыть» / «Вернуть в выбор». Скрытая статья пропадает из выбора, прошлые расходы по ней остаются в отчётах.

## Критерии приёмки

- [ ] Расход из кассы 300 с уменьшает ожидаемую сумму смены на 300 с.
- [ ] Расход из кассы больше баланса → 422, ничего не записано. *Уточнено ADR-077: только у счёта, где минус запрещён отметкой; по умолчанию минус разрешён, владелец получает уведомление.*
- [ ] Расход со счёта уменьшает остаток счёта и не трогает наличные; расход `outside` не меняет ни одну кассу, но попадает в прибыль дня `expense_date`. *С ADR-079 новый расход `outside` не принимается (422); прежние читаются, «Исправить» их — отказ (ADR-088).*
- [ ] Личный расход 5 000 с из кассы: наличных меньше на 5 000 с, чистая прибыль дня меньше на 5 000 с.
- [ ] Администратор: расход со счёта, `outside`, задним числом или по статье `owner_only` → 403.
- [ ] Администратор не получает в списке расходы со счёта, `outside` и статьи `owner_only`.
- [ ] Сторно возвращает наличные в кассу и гасит расход в том же дне отчёта.
- [ ] Повторное сторно → 409; повтор `op_id` не создаёт второй расход.
- [x] Статьи: администратор → 403; повтор названия → 409; «только владелец» скрывает статью от администратора; скрытие и переименование пишутся в журнал (`expense_articles_are_managed_by_owner`).

## Решения для ADR

- ADR-023: состав статей расходов; оплата сотрудников статьёй расхода не проводится; личные расходы владельца уменьшают прибыль наравне с прочими.

## Дополнено задачей 003 (31.10.2026): «Кому» (Н12, ADR-158)

- У расхода — «Кому» (`payee`, до 100 знаков): кому отдали деньги. Поле — в «Расходах», «Мелком расходе» на кассе, в «Исправить» (переносится в черновик) и в боте владельца; в списке «Расходов» — столбец «Кому»; в раскрытии статьи «Прибыли и убытков» (SPEC-08) — дата, сумма, кому, касса, кто провёл.
- Пишется при проведении, не правится (I4); сторно повторяет «Кому» исходного; повтор `op_id` — та же запись (I8).
- Обязательно ли — «Настройки → Отчёт о прибыли»: «необязательно» (по умолчанию), «обязательно» (без «Кому» — 422 «укажите, кому отдали деньги»), «не спрашивать» (поля нет).
- Подсказки — `GET /expenses/payees`: `{mode, names}` — прежние «Кому» филиала по видимым пользователю статьям, работники филиала, поставщики.
- Статья с названием «зарплата», «оклад», «аванс», «доп доход»: при добавлении и переименовании — предупреждение, что оплата работникам уже входит в «Зарплату работникам» (ADR-023), расход по такой статье уменьшит прибыль второй раз. Не запрет.
- Проверка: `server/tests/pnl.rs` (`expense_payee_is_stored_reversed_and_set_up_by_owner`), `web/src/lib/expensePayee.test.ts`, `web/src/lib/moneyFix.test.ts`.

## Дополнено задачей 003 (31.10.2026): все траты, кроме оплаты поставщикам (Н12б, ADR-{f2.1})

- Экран «Расходы» — список «Все траты»: расходы по статьям и выплаты работникам (оклад, аванс, проценты, мастеру, бонус, без вида) одним списком: №, дата (у выплаты — дата выплаты в расчёте `payouts.pay_date`, SPEC-07/ADR-154), что (статья или «Выплата: <вид>»), кому (`payee` расхода или работник), за что (комментарий), касса, сумма, кто провёл. Оплата поставщикам за товар, изъятия и переводы в список не входят.
- Начисленные бонусы (`payroll_accruals`, `kind = bonus`) — отдельной строкой «начислен бонус» («в итог не входит»), пока включена настройка «Отчёт о прибыли» → «Показывать начисленные бонусы» (`expenses_bonus_accruals`, по умолчанию да); выплата бонуса — строкой выплаты.
- Отбор «Всё» (по умолчанию) / «Расходы» / «Выплаты работникам»; период «С/По». Сторно — как в отчёте: пара «документ + сторно» скрыта, «Показать сторно» показывает обе строки с отметкой.
- Итог по статьям: статьи (пары сторно гасятся), «Зарплата работникам» — выданные деньги за период, «в т. ч. бонусы» — выдано бонусом; «Бонусы: начислено, не выдано» (по работнику: начислено бонусом за период − выдано бонусом за период, не меньше нуля) — отдельной строкой, в «Итого» не входит. «Итого» = расходы + выдано работникам: бонус не задваивается. В прибыли зарплата по-прежнему по начислению (ADR-023).
- Кнопки «Выплатить работнику» (право «Выплаты мастерам» и «Расчёт сотрудников») и «Бонус» (владелец) — выбор работника и те же окна, что в «Расчёте». «В Excel» — все строки отбора (лист «Расходы») и лист «Итог по статьям».
- API: `GET /expenses/all?from&to&kind=all|expenses|payouts&reversals=1&limit&offset` — одной выборкой, страницей, `x-total-count`; `GET /expenses/all/summary` (те же параметры) — `{articles, expenses_tyiyn, payouts_tyiyn, purposes, bonus_paid_tyiyn, bonus_accrued_tyiyn?, bonus_unpaid_tyiyn?, total_tyiyn, expenses, payouts}`. Неизвестный отбор — 422.
- Права (I12): расходы — по праву `expenses`, администратору — как прежде (из кассы смены, за 7 дней, без статей владельца); выплаты и бонусы — по праву `view_payroll`, кассиры — только с `payroll_view_all` (как в «Расчёте», ADR-151); счёт владельца администратору не называется. Без обоих прав — 403 «Нет права: Расходы»; отбор «Выплаты работникам» без `view_payroll` — 403 «Нет права: Расчёт сотрудников». Ни себестоимости, ни прибыли в ответе нет (I13).
