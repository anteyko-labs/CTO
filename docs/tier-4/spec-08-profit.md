# SPEC-08. Прибыль и экран владельца

## Задача

Чистая прибыль за день и за период, разрез по категориям товаров и по работам, экран владельца на телефоне (BLUEPRINT §3.6). Только владелец (инвариант 13).

## Учётный день

У каждого чека поле `business_date` (дата по Asia/Bishkek), записывается при проведении:

```
если чек пришёл из офлайн-очереди (SPEC-09) и client_time ∈ [created_at − 2 дня, created_at + 5 мин]:
    business_date = дата(client_time)
иначе:
    business_date = дата(created_at)
```

Окно доверия — два дня: интернет на точке пропадает на час, модем втыкают за пять минут (SPEC-09), поэтому чек старше двух дней означает не перебой связи, а устройство, которое долго не включали. Такой чек попадает в день проведения и виден в предупреждениях.

Возврат получает собственный `business_date` (день возврата), а не день исходного чека. Миграция заполняет поле для существующих чеков по `created_at`. `GET /sales?date=` (SPEC-04) переходит на `business_date`.

Для расходов день — `expense_date` (SPEC-06), для начислений — `business_date` чека или смены, для оклада — последний день месяца (SPEC-07).

## Комиссия банка

Оплата картой и переводом приходит за вычетом комиссии банка, поэтому комиссия уменьшает прибыль (ADR-022).

```
payment_method_fees (id, branch_id, method card | transfer, rate_bp, active_from, active_to?)
sale_payments.fee_tyiyn           -- добавляется в SPEC-04, фиксируется при проведении
```

При проведении чека для каждого безналичного платежа `fee = div_round(amount_tyiyn · rate_bp, 10000)` по ставке, активной на `business_date`. Ставка хранится в базисных пунктах, комиссия — в тыйынах (инвариант 1) и фиксируется в платеже, как себестоимость в строке (инвариант 3): изменение ставки не переписывает прошлые чеки. Возврат пишет платёж с минусом и комиссию с минусом.

Та же сумма уходит движением `bank_fee` со счёта (SPEC-05), поэтому баланс счёта равен тому, что банк фактически перечислил, а в отчёте о прибыли комиссия стоит отдельной строкой. Наличные комиссия не затрагивает.

Миграция ставит 0,5 % (`rate_bp = 50`) и карте, и переводу — ставка банка на сегодня; владелец меняет её в настройках, по каждому способу отдельно.

## Формула

За день или период:

```
выручка_товары  = Σ amount строк piece|container|pour
выручка_работы  = Σ amount строк service
себестоимость   = Σ cost строк piece|container|pour
валовая         = выручка_товары + выручка_работы − себестоимость
оплата труда    = Σ payroll_accruals.amount          (удержания входят с минусом)
комиссия банка  = Σ sale_payments.fee_tyiyn
расходы         = Σ expenses.amount                  (все статьи, включая личные расходы)
чистая прибыль  = валовая − оплата труда − комиссия банка − расходы
```

Возвраты и сторно входят со своими знаками. Выплаты сотрудникам прибыль не уменьшают: её уменьшило начисление (SPEC-07). Перемещения денег между кассами, оплата поставщику и погашение долгов прибыль не затрагивают (SPEC-05, SPEC-10): это движение денег, а не доход и не затрата. Закупка попадает в прибыль себестоимостью проданного. Подарки (этап 3) попадут в себестоимость автоматически как строки с нулевой ценой.

Маржа — в базисных пунктах, целым числом: `margin_bp = div_round(валовая · 10000, выручка)`, при нулевой выручке `null`. Проценты с дробью формирует только показ (инвариант 2).

## Разрезы

- **По категориям товаров:** выручка, себестоимость, валовая, маржа.
- **По работам:** по каждой услуге — количество, выручка, начислено мастерам, валовая за вычетом начислений.
- **По дням** внутри периода: выручка, валовая, оплата труда, комиссия, расходы, чистая.
- **Оплата труда по сотрудникам и видам начислений** (SPEC-07).
- **Расходы по статьям.**
- **Поступления по способам оплаты:** наличные, карта, перевод и комиссия банка — для сверки с терминалом и выпиской.

## Достоверность

Ответ содержит `warnings`:
- `negative_stock` — число товаров с `needs_review`: себестоимость части продаж оценена по последней закупке (ADR-011).
- `late_offline` — число чеков периода, проведённых позже их `business_date`: прибыль прошлого дня изменилась после его просмотра.
- `salary_not_accrued` — месяц периода закончился, а оклад начислен не всем, у кого есть правило `monthly_salary`: прибыль месяца ещё не полная.
- `fee_rate_unset` — есть безналичная выручка, а ставка комиссии не задана.

## API

- `GET /reports/profit?from&to` → итоги, разрезы, предупреждения. Период ≤ 366 дней, иначе 422.
- `GET /owner/dashboard` → на сегодня:
  - выручка, число чеков, средний чек, возвраты;
  - валовая и чистая прибыль на текущий момент;
  - наличные в кассе, остаток счёта и сейфа, всего денег (SPEC-05), открыта ли смена, кем и с каким кассиром, расхождение последнего закрытия;
  - поступило сегодня наличными, картой, переводом и сколько съела комиссия;
  - расходы сегодня, к выплате сотрудникам (сумма положительных балансов, SPEC-07);
  - число товаров ниже минимального остатка и с `needs_review`.
  - «Должны нам / должны мы» появятся с долгами на этапе 3.

Администратор → 403 на оба запроса.

Расчёт — агрегирующими запросами на лету, без хранимых итогов. Индексы: `sales (branch_id, business_date)`, `expenses (branch_id, expense_date)`, `payroll_accruals (branch_id, business_date)`.

## Клиент

- У владельца в нижнем меню первым пунктом «Сводка»; это стартовый экран владельца на телефоне.
- «Сводка за сегодня»: карточки «Продано», «Валовая прибыль», «Чистая прибыль», «Чеков»; «Откуда прибыль» лесенкой (товары, работы → выручка → − закупка проданного → валовая → − зарплата, − комиссия, − расходы, − скидки баллами → чистая); «Кто сколько заработал сегодня» по сотрудникам и видам (% с чеков, замены ×N, оклад, премия, недостача) и «Всего к выплате»; «Деньги сейчас» по кассам, кто кому должен, смена; строка предупреждений склада. Переключатель периода «Сегодня / 7 дней / 30 дней» меняет лесенку, «кто сколько заработал» (начислено, выдано, осталось выдать) и график: за сегодня — выручка и валовая по часам, за 7 и 30 дней — валовая и чистая по дням (убыточный день красным). Та же лесенка и «кто сколько заработал» — в боте по кнопке «Сегодня».
- «Прибыль»: быстрые периоды (сегодня, вчера, 7 дней, месяц, свой), итоговая формула лесенкой (выручка → − себестоимость → − оплата труда → − комиссия банка → − расходы → чистая), таблицы разрезов, на телефоне — карточками.
- Настройка ставок комиссии — на экране настроек филиала, только владельцу.
- Значения показываются через общий модуль форматирования денег.

## Критерии приёмки

- [ ] День: продажа товара за 1000 с с себестоимостью 700 с, замена за 300 с с начислением 30 с, расход 100 с → чистая 470 с.
- [ ] Тот же чек оплачен картой при ставке 0,5 % → комиссия 650 тыйын (`div_round(130000 · 50, 10000)`), чистая 463,50 с, на счёт пришло 1293,50 с.
- [ ] Возврат картой уменьшает выручку и комиссию дня возврата.
- [ ] Ставка комиссии изменена сегодня → вчерашние чеки сохранили прежнюю комиссию.
- [ ] Процент кассира и оклад входят в «оплату труда»; удержание недостачи уменьшает её.
- [ ] Личный расход владельца уменьшает чистую прибыль так же, как «Хозтовары».
- [ ] Возврат на следующий день уменьшает выручку и себестоимость дня возврата, а не дня продажи.
- [ ] Сторно расхода гасит расход в его `expense_date`.
- [ ] Офлайн-чек с `client_time` вчера, проведённый сегодня, попадает во вчера и даёт `late_offline`.
- [ ] `client_time` на 5 дней назад или в будущем → учётный день = день проведения.
- [ ] Маржа 333/1000 → `margin_bp = 3330`; нулевая выручка → `null`.
- [ ] Администратор: `/reports/profit` и `/owner/dashboard` → 403.

## Решения для ADR

- Учётный день чека `business_date` с правилом доверия `client_time` (окно два дня).
- ADR-022: комиссия банка фиксируется в платеже чека и уменьшает чистую прибыль.
