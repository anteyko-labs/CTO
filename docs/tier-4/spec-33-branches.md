# SPEC-33. Несколько филиалов

Решение заказчика 24.10.2026 — ADR-108: «несколько филиалов, товары везде одинаковые, но склады и деньги разные; каждый филиал видит только себя, владелец — все». Ответы заказчика: один общий сервер; цена общая, филиал может поставить свою; клиенты общие; перемещения товара между филиалами нет.

## 1. Филиалы и доступ

- «Настройки → Филиалы» (только владелец): список, «Новый филиал» (название, адрес, телефон), переименование, закрытие (архив; закрытый не продаёт, история остаётся). Новый филиал получает свои кассы и счета по умолчанию («Касса», «Сейф»), свои настройки (по умолчанию — копия настроек главного филиала), свои смены и нумерацию документов.
- Администратор и кассир-пользователь привязаны к одному филиалу и видят и меняют только его — сервер проверяет на каждом запросе, данных другого филиала не отдаёт (404, а не 403 — не выдаём существование чужих документов).
- Владелец видит все филиалы: переключатель «Филиал: …» в шапке (по умолчанию — последний выбранный; выбор помнит устройство) и вариант «Все филиалы» для отчётов. Действия (чек, приход, расход и т. п.) владелец проводит в выбранном филиале; в режиме «Все филиалы» — только просмотр.
- Работники (кассиры, мастера) — у каждого филиала свои; PIN кассира — в его филиале.

## 2. Что у филиала своё и что общее

- **Своё:** остатки и себестоимость, приходы, ревизии, брак, переливы, возвраты поставщику, кассы и счета, смены, расходы, начисления и выплаты, чеки и их номера, настройки (комиссии, оплата труда, напоминания, Optima — точка и касса), очередь касс без сети, долги поставщикам.
- **Общее:** каталог товаров (карточки, штрихкоды, категории, характеристики, аналоги), поставщики (карточки), услуги (справочник), клиенты, их машины, масляная книжка и баллы, правила подарков, справочник марок.
- **Цена продажи:** общая цена задаётся владельцем один раз на все филиалы; у филиала можно поставить свою («Цена в филиале … — своя», «Вернуть общую»). Наценка и цена в приходе (ADR-075) меняют цену только того филиала, где приход, если там своя цена; иначе — общую (с отметкой в журнале).
- **Долг клиента:** записывается на филиал, где взяли в долг; у клиента виден общий долг и по филиалам; гасить можно в любом филиале — погашение закрывает долги того филиала, где принято, затем самые старые в других (деньги — в кассу принявшего филиала, долг между филиалами учитывается внутренним счётом «Расчёты между филиалами» и виден владельцу).
- Кабинет юрлица и бот клиента — по всем филиалам (покупки с названием филиала).

## 3. Отчёты владельца

- Каждый отчёт (сводка, прибыль, поступления, «Безнал», продаваемые, замены, склад, долги, расчёт) — по выбранному филиалу или «Все филиалы» (сумма и разбивка по филиалам). Себестоимость и прибыль — по-прежнему только владельцу.
- Бот владельца: лента и отчёты с названием филиала; в отчётах — выбор филиала или все.

## 4. Сервер

- Один общий сервер (облако или главная точка) с внешним адресом по HTTPS; филиалы подключаются через интернет, касса без сети работает как сейчас и отправляет чеки при появлении связи. Установка и доступ — ADR-108, раздел установки в `deploy/`.
- Существующая база — один филиал (главный); миграция ничего не теряет.

## Проверка

- [ ] Администратор филиала Б не видит и не меняет ничего филиала А: каждый список и каждый документ по id (чек, приход, смена, счёт, расход, начисление, ревизия, брак, отчёт) — тест обходом всех маршрутов API.
- [ ] Владелец переключает филиал; «Все филиалы» — суммы равны сумме по филиалам; действия в «Все» запрещены.
- [ ] Общая цена меняется во всех филиалах без своей цены; своя цена филиала не меняется; «Вернуть общую».
- [ ] Клиент общий: баллы и книжка из любого филиала; долг по филиалам; погашение в чужом филиале — расчёты между филиалами.
- [ ] Новый филиал: свои кассы, счета, настройки, нумерация; закрытый не продаёт.
- [ ] Миграция существующей базы — один главный филиал, все данные на месте, остатки = сумма движений.
