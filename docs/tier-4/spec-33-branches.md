# SPEC-33. Несколько филиалов

Решение заказчика 24.10.2026 — ADR-108: «несколько филиалов, товары везде одинаковые, но склады и деньги разные; каждый филиал видит только себя, владелец — все». Ответы заказчика: один общий сервер; цена общая, филиал может поставить свою; клиенты общие; перемещения товара между филиалами нет.

## 1. Филиалы и доступ

- «Настройки → Филиалы» (только владелец): список, «Новый филиал» (название, адрес, телефон), переименование, закрытие (архив; закрытый не продаёт, история остаётся). Новый филиал получает свои кассы и счета по умолчанию («Касса», «Сейф»), свои настройки (по умолчанию — копия настроек главного филиала), свои смены и нумерацию документов.
- Администратор и кассир-пользователь привязаны к одному филиалу и видят и меняют только его — сервер проверяет на каждом запросе, данных другого филиала не отдаёт (404, а не 403 — не выдаём существование чужих документов).
- Владелец видит все филиалы: переключатель «Филиал: …» в шапке (по умолчанию — последний выбранный; выбор помнит устройство) и вариант «Все филиалы» для отчётов. Действия (чек, приход, расход и т. п.) владелец проводит в выбранном филиале; в режиме «Все филиалы» — только просмотр.
- Работники (кассиры, мастера) — у каждого филиала свои; PIN кассира — в его филиале.

## 2. Что у филиала своё и что общее

- **Своё:** остатки и себестоимость, приходы, ревизии, брак, переливы, возвраты поставщику, кассы и счета, смены, расходы, начисления и выплаты, чеки и их номера, настройки (комиссии, оплата труда, напоминания, Optima — точка и касса), очередь касс без сети, долги поставщикам.
- **Общее:** каталог товаров (карточки, штрихкоды, категории, характеристики, аналоги), поставщики (карточки), услуги (справочник), клиенты, их машины, масляная книжка и баллы, правила подарков, справочник марок.
- **Цена продажи:** общая цена задаётся владельцем один раз на все филиалы; у филиала можно поставить свою («Цена в филиале … — своя», «Вернуть общую»). Наценка и цена в приходе (ADR-075) меняют цену только того филиала, где приход, если там своя цена; иначе — общую (с отметкой в журнале).
- **Долг клиента:** записывается на филиал, где взяли в долг; у клиента виден общий долг и по филиалам; гасить можно в любом филиале — погашение закрывает долги того филиала, где принято, затем самые старые в других (деньги — в кассу принявшего филиала, долг между филиалами учитывается внутренним счётом «Расчёты между филиалами» и виден владельцу).
- Кабинет юрлица и бот клиента — по всем филиалам (покупки с названием филиала).

## 3. Отчёты владельца

- Каждый отчёт (сводка, прибыль, поступления, «Безнал», продаваемые, замены, склад, долги, расчёт) — по выбранному филиалу или «Все филиалы» (сумма и разбивка по филиалам). Себестоимость и прибыль — по-прежнему только владельцу.
- Бот владельца: лента и отчёты с названием филиала; в отчётах — выбор филиала или все.

## 4. Сервер

- Один общий сервер (облако или главная точка) с внешним адресом по HTTPS; филиалы подключаются через интернет, касса без сети работает как сейчас и отправляет чеки при появлении связи. Установка и доступ — ADR-108, раздел установки в `deploy/`.
- Существующая база — один филиал (главный); миграция ничего не теряет.

## Проверка

- [x] Администратор филиала Б не видит и не меняет ничего филиала А: каждый список и каждый документ по id (чек, приход, смена, счёт, расход, начисление, ревизия, брак, отчёт) — тест обходом всех маршрутов API (`server/tests/branches.rs`: `admin_of_branch_b_sees_and_changes_nothing_of_branch_a` — маршруты берутся из роутеров `src/api/*.rs`, 189 маршрутов, около 6000 запросов: администратор Б, администратор Б с заголовком филиала А и владелец в филиале Б; id всех документов А в каждый параметр пути; ответ на чужой документ — тот же код, что на несуществующий; ни в одном ответе нет id и меток данных А; отпечаток всех строк филиала А после обхода не изменился).
- [x] Владелец переключает филиал; «Все филиалы» — суммы равны сумме по филиалам; действия в «Все» запрещены (`owner_reports_all_branches_as_the_sum_of_branches`; e2e `z-branches.spec.ts`; «Все филиалы» — только параметр GET-отчётов, действия всегда идут в выбранный филиал).
- [x] Общая цена меняется во всех филиалах без своей цены; своя цена филиала не меняется; «Вернуть общую» (`shared_price_and_own_branch_price`).
- [x] Клиент общий: баллы и книжка из любого филиала; долг по филиалам; погашение в чужом филиале — расчёты между филиалами (`client_debt_repaid_in_another_branch_is_settled_between_branches`, `loyalty_lookup_is_shared_and_unambiguous`).
- [x] Новый филиал: свои кассы, счета, настройки, нумерация; закрытый не продаёт (`new_branch_gets_own_accounts_settings_numbers_and_closed_branch_does_not_sell`; e2e `z-branches.spec.ts`).
- [x] Миграция существующей базы — один главный филиал, все данные на месте, остатки = сумма движений (`migration_makes_one_main_branch_and_keeps_everything`; копия рабочей базы заказчика 24.10.2026: расхождений остатков, долгов и цен — 0).
- [x] Бот владельца: лента всех филиалов с названием, отчёты по выбранному филиалу или по всем (`owner_bot_feed_and_reports_name_the_branch`).

## Как сделано (24.10.2026)

- **Миграции 0062–0063.** `branches`: адрес, телефон, `archived`, `is_main` (главный — первый заведённый; он не закрывается, из него новый филиал копирует настройки). `products.sale_price_tyiyn` — общая цена, `branch_products.own_price` — своя цена филиала; в `branch_products.sale_price_tyiyn` по-прежнему лежит действующая цена филиала, поэтому касса, снимок без сети и отчёты читают её как раньше; строка без цены, заведённая лениво (первым движением), берёт общую триггером. `party_balances` — долг контрагента по филиалам, ведётся триггером из `party_ledger` (у каждой записи долга свой филиал), сумма частей всегда равна `parties.balance_tyiyn` и сумме записей. `branch_settlements` — «Расчёты между филиалами» (неизменяемые записи, сторно — встречной). Правило подарка — одно на товар для всех филиалов. Распределение оплат поставщику (ADR-073) — внутри филиала. `telegram_links.all_branches` — «все филиалы» в отчётах бота. Существующая база — один главный филиал, ни одна строка не переносится.
- **Филиал запроса.** Извлекатель `CurrentUser` (`server/src/auth.rs`) кладёт в `branch_id` филиал запроса: администратор — всегда свой (`users.branch_id`), заголовок `X-Branch-Id` у него не читается; владелец — филиал из заголовка `X-Branch-Id` (без заголовка — свой), неизвестный филиал — 422, а не молча другой филиал. Поэтому все существующие запросы «по `user.branch_id`» сразу стали запросами выбранного филиала. Выбор помнит устройство (`web/src/lib/branch.ts`, `localStorage`); переключение перезагружает экраны. В закрытом филиале любые изменения — 409 (кроме `/branches` и входа).
- **Общее.** Клиенты и поставщики (`parties`), их люди и машины, книжка, баллы, услуги, правила подарков, каталог — без отбора по филиалу (столбец `branch_id` у них остался: где завели). Клиент: `balance_tyiyn` — общий долг, `branch_balance_tyiyn` — долг в филиале запроса, `branch_balances` — по филиалам; поставщик: `balance_tyiyn` — долг этого филиала (у владельца в «Все филиалы» — общий с разбивкой). Карточка и акт сверки клиента — по всем филиалам, у чужих записей — название филиала, сторно — только в филиале записи; у поставщика — только этот филиал. Кабинет юрлица и бот клиента — по всем филиалам с названием филиала.
- **Погашение в чужом филиале** (`parties::repayment_parts`): сначала долг филиала, где приняли деньги, затем другие филиалы — сначала тот, где самый старый непогашенный долг, переплата — аванс в этом филиале. Деньги — в кассу принявшего филиала; каждая часть — своя запись долга в своём филиале (с процентом кассира того филиала), часть чужого долга — строка `branch_settlements` «Б должен А». Сторно погашения снимает все части и расчёты. Экран — «Настройки → Филиалы → Расчёты между филиалами», `GET /branches/settlements` (владелец).
- **Цена.** `PATCH /products/{id}/prices`: `own_price: true` — своя цена филиала, `false` — «Вернуть общую», без поля — цена меняется там, где задана (своя — у филиала, иначе общая во всех филиалах без своей). Цена из прихода (ADR-075) — по тому же правилу; в журнале — `price_scope` (`shared` / `branch`). Новый товар заводится строкой остатка в каждом филиале; объединение дублей переносит остатки во всех филиалах.
- **Новый филиал** (`POST /branches`, владелец, `op_id`): кассы и счета, статьи расходов, настройки главного филиала копией (кроме точки и кассы Optima и отметок «просмотрено»), строки остатков всех товаров с общей ценой и минимальным остатком главного. Счётчики документов — по филиалу, с 1. Правка и закрытие — `PATCH /branches/{id}`; `GET /branches` — владельцу все, администратору свой. `/auth/me` отдаёт филиал запроса, свой филиал, список и `several_branches`.
- **«Все филиалы»** — параметр `branch=all` у GET-отчётов: сводка, прибыль, тепловая карта, подарки, продаваемые, замены, поступления, «Безнал», расчёт за месяц, товары (склад), долги. Сервер строит отчёт каждого филиала той же функцией и складывает (`branches::merge_reports`): деньги, количества и счётчики — суммой, цены, доли, ставки и номера — без сложения, маржа и средний чек — пересчётом по сумме, строки списков — по ключу строки (день, товар, способ, название); в ответе — `branches` с отчётом каждого филиала. Администратору `branch=all` — 404. Действий в режиме «Все» нет: это только параметр отчёта, изменения идут в филиал из заголовка.
- **Фоновые задачи** — по всем филиалам: лента бота владельцу — события всех филиалов с названием филиала; сверка Optima — по каждому филиалу с расчётным счётом, от имени владельца; напоминания о замене — по настройкам филиала, где машину записали (у машины один такой филиал, повторов нет); сообщения о закупе — по филиалу чека.
- **Бот владельца.** `/филиал` — список, `/филиал 2` или название — филиал отчётов, черновиков и вопросов; `/филиал все` — отчёты «Сегодня», «Смена», «Долги», «Замены» по каждому филиалу подряд с заголовком «🏬 Филиал». Лента — с названием филиала, когда филиалов больше одного.
- **Касса без сети.** Запись очереди помнит филиал, где её пробили (`OutboxItem.branch_id`), и уходит туда с этим заголовком, даже если владелец переключил филиал; снимок кассы — выбранного филиала, клиенты в снимке — все.
- **Экран.** Переключатель «Филиал: …» в боковом меню и в шапке телефона (`components/BranchSwitch.tsx`), у администратора — название его филиала; «Настройки → Филиалы» (`pages/Branches.tsx`); «Филиал / Все филиалы» и разбивка по филиалам на отчётах (`components/BranchScope.tsx`, `lib/branchReport.ts`); «Своя цена в филиале» в карточке товара; долг клиента по филиалам в карточке, «Долгах», окне оплаты и кабинете; название филиала в печатном чеке (когда филиалов несколько).

## Вопросы заказчику (24.10.2026)

- **Расчёты между филиалами только видны.** Запись «Б должен А» появляется сама; как филиалы рассчитываются (перемещение денег между кассами разных филиалов), в SPEC-33 не сказано. Сейчас — только экран для владельца; закрыть расчёт — отдельной операцией, если нужно.
- **Напоминания о замене** идут по настройкам филиала, где машину записали, а не где её обслужили последний раз.
- **Справочник старой программы** (список «Умага» для сканера) — у каждого филиала свой, как был.
- **Лимит долга клиента** — общий на все филиалы (по общему долгу).
- **«Все филиалы» по складу**: строки одного товара складываются, страницы режет экран (до 2000 товаров у филиала); отборы «ниже минимума», «нет» считаются в каждом филиале отдельно.
