# Реестр решений

Записи только добавляются. Отменённое решение не удаляется, а получает статус «заменено» со ссылкой на новое.

## ADR-001. Avtodom — отдельный продукт на общих принципах FlowCar

- **Дата:** 2026-10-05
- **Решение:** строим систему для одной точки. Из платформенного blueprint берём принципы: целочисленные деньги, сторно вместо правок, журнал действий, привязку к филиалу, офлайн-очередь событий. Остальные блоки платформы не реализуем.
- **Причина:** заказчику нужен работающий учёт точки в обозримый срок.
- **Последствие:** схема данных сразу содержит филиал, чтобы вторая точка не требовала переделки.

## ADR-002. Rust на сервере, React на клиенте

- **Дата:** 2026-10-05
- **Решение:** сервер на Rust (Axum, SQLx), клиент на React + TypeScript в виде PWA.
- **Причина:** совместимость с будущей платформой; одно клиентское приложение на кассу, склад и телефон.
- **Последствие:** скорость разработки ниже, чем на едином языке; компенсируем узкими этапами.

## ADR-003. Без Redis и брокера очередей

- **Дата:** 2026-10-05
- **Решение:** сессии и идемпотентность — в PostgreSQL, фоновые задачи — внутри сервера.
- **Причина:** нагрузка одной точки не оправдывает дополнительных сервисов.
- **Пересмотр:** при появлении второго филиала или тяжёлых фоновых задач.

## ADR-004. Оплата без интеграции

- **Дата:** 2026-10-05
- **Решение:** способ и сумма оплаты вносятся вручную. Оплата хранится отдельной сущностью от чека, чтобы позже подключить терминал и ККМ без изменения модели.
- **Причина:** решение заказчика на первую версию.

## ADR-005. Две роли со входом

- **Дата:** 2026-10-05
- **Решение:** в систему входят только владелец и администратор. Мастера и кассиры — справочник.
- **Причина:** решение заказчика; меньше учётных записей на точке.
- **Последствие:** действие в журнале привязано к вошедшему пользователю, а исполнитель работы указывается в чеке.

## ADR-006. Единый учёт

- **Дата:** 2026-10-05
- **Решение:** от двухконтурного учёта с переключателем отображения отказываемся. Система ведёт один полный учёт операций.
- **Причина:** юридический риск для заказчика и исполнителя.

## ADR-007. Старт с пустой базы

- **Дата:** 2026-10-05
- **Решение:** импорт из прежней программы не делаем, товары заводятся при первом приходе и стартовой ревизии.
- **Причина:** решение заказчика.
