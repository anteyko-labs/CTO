# 042 — Временный разбор остатков из Умага: «Новый товар» или «Уже есть»

Статус: утверждено (21.11.2026, владелец: «временную систему в остатках — загрузили, и справа у каждого товара подтверждение: 1-я кнопка „Новый товар“ — что есть с Умага вставляется, чего нет — заполняет человек; 2-я — „Товар уже есть в Автодом“, предлагает похожие из Автодома»)

## Зачем
Айкос переносит товар и остатки из Умага. Файл Умага уже загружается как список подсказок (SPEC-20, `old_catalog`), но остатки из него не встают, а разбирать по одному сканером долго. Нужен экран, где каждая строка файла за 1–2 клика становится товаром учёта с остатком.

## Что меняется (дополняет SPEC-20, SPEC-15)
1. **Экран «Остатки → Разбор из Умага»** (`/stock/umag-intake`), временный: пункт виден, пока в филиале есть неразобранные строки. Владелец (и администратор с правом «Товары») загружает выгрузку Умага .xlsx с остатками — к полям SPEC-20 добавляется **количество** (колонка «Остаток»/«Количество»). Загрузка идёт в список Умага филиала (`old_catalog` + `qty`), как сейчас.
2. **Таблица**: название, штрихкод/артикул, кол-во, закупка, цена, категория Умага; фильтр «Не разобрано / Новые / Привязаны / Пропущены», поиск. Справа у строки — две кнопки и «Пропустить»:
   - **«Новый товар»** — карточка товара заполнена из строки Умага (название, коды, цена, закупка, единица, категория — по совпадению имени категории, иначе пусто); пустые поля заполняет человек, «Сохранить» → товар заведён, все коды строки — коды товара, строка «Новая».
   - **«Уже есть в Автодом»** — список похожих из общей базы (тот же поиск, что «Похожие в базе» задачи 041 и подсказки SPEC-20: код, артикул, слова названия), сверху — совпавшие по коду. Выбрал «Это он» → коды строки привязываются к товару, строка «Привязана». Нет нужного — «Нет, это новый» открывает «Новый товар».
3. **Остаток.** При «Новый товар» и «Это он» количество строки пишется в черновик ревизии филиала «весь склад» (открытый или новый — как в режиме пересчёта SPEC-20; администратору без черновика — только завести/привязать, кол-во ждёт). Если товар уже посчитан в этом черновике — прибавить (ADR-059). Владелец проводит ревизию — остатки встают, излишек оценивается закупкой из строки.
4. Строку можно вернуть в «Не разобрано» («Отменить»): привязка кодов снимается (`unlink`), кол-во из черновика убирается, заведённый товар остаётся.
5. Повторное нажатие (двойной клик, повтор сети) — тот же результат (`op_id`).

## Данные, маршруты
- Миграция 0122: `old_catalog.qty numeric null`, `old_catalog.intake_status text not null default 'todo'` (`todo|new|linked|skipped`), `intake_product_id`.
- `GET /old-catalog/intake?status=&q=` (постранично), `POST /old-catalog/{id}/intake/new` (тело — карточка товара), `POST /old-catalog/{id}/intake/link {product_id}`, `POST /old-catalog/{id}/intake/skip|undo`, `GET /old-catalog/{id}/similar`. Всё с `op_id`, право «Товары» (`products`), владелец — всегда. Журнал `stock.umag_intake`.

## Проверка
- Сервер: «Новый» — товар, коды, кол-во в черновике ревизии; «Это он» — коды у существующего товара, кол-во прибавлено; повтор `op_id`; «Отменить»; без права — 403; similar находит по коду и словам.
- Веб: юнит чтения колонки количества; e2e — загрузить файл, «Новый товар», «Уже есть» → «Это он», проведение ревизии → остатки.

## Решено без вопроса
- Остатки встают через ревизию (одно проведение владельцем), а не сразу: так не нарушается порядок движения склада (I-инварианты), и всё видно одним документом.
- Экран временный: исчезает из меню, когда неразобранных строк нет.
