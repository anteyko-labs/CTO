# 018. Касса: без создания товаров и без продажи в минус

Статус: сделано (02.11.2026; ответы 1а, 2а; ветка feat-015-till-stock, не слита и не выкачена — выкат по слову владельца)

## Зачем
Заказчик: «запретить на кассе товары создавать новые, можно только пробивать; если остаток 0 — не должен уходить в минус и продаваться».
Сейчас касса открывает карточку нового товара (по имени из поиска и по незнакомому коду, `web/src/pages/Cashier.tsx:2431`, `:3713`), а нехватку только подсвечивает (`:2647`) — чек проводится, остаток уходит в минус.

## Что меняется
1. Касса не создаёт товары: из поиска убрано «Создать», в окне незнакомого кода — кнопка «Новый товар» убрана; остаётся «привязать код к существующему» (право `till_barcode`). Создание — только в разделе «Товары»/приход.
2. Онлайн-чек: сервер отклоняет строку, если её количество больше остатка филиала, — 409 «Не хватает: <товар>, остаток <N>». Проверка в той же транзакции под блокировкой строки остатка (I7), с учётом нескольких строк одного товара в чеке. Услуги (без товара) не проверяются.
3. Касса заранее: товар с остатком 0 в поиске — «нет в наличии»; в чек встаёт красной строкой (чтобы работала подсказка аналога), «Провести чек» закрыт («Не хватает: товара …»).
4. Без сети (I9, I10): касса не даёт пробить сверх остатка по снимку; если снимок устарел и на сервере уже 0 — офлайн-чек всё равно проводится с пометкой владельцу (как сейчас, инвариант I10 не меняем: выданный товар не отменяется).
5. Настройка в панели владельца (I21) «Продажа в минус на кассе»: выкл. по умолчанию (прямая просьба заказчика). Включена — прежнее поведение п.2–3.

## Не входит
- Ревизия, перелив, возвраты, сторно — остаток по ним не ограничивается.
- Создание товаров в разделе «Товары», приходе, приёмке — без изменений.

- `web/src/pages/Cashier.tsx:2431, :2647, :3713-3745` — убрать создание, блок оплаты.

## Проверка
- `server/tests/sales.rs`: чек сверх остатка → 409, остаток не изменился; ровно в остаток → 200, остаток 0; две строки одного товара в сумме сверх → 409; услуга без остатка → 200; офлайн-чек (`offline: true`) сверх → проводится с пометкой; настройка включена → прежнее поведение.
- `web/src/lib/tillStock.test.ts`: нехватка по корзине (шт, мл, г, мм, канистры).
- e2e `web/e2e/till-stock.spec.ts`: нет «Создать» в поиске и «Новый товар» по незнакомому коду; товар с 0 не кладётся; оплата закрыта при нехватке.

## Решено без вопроса
- Офлайн-чек не отклоняется (инвариант I10) — только не даём пробить по снимку.
- Создание запрещено для всех на кассе, включая владельца: на кассе только пробивать.

## Ответы владельца
1. Разлив из бочки — тоже запрещать при остатке 0 (как всё остальное).
2. Запрет для всех, включая владельца.
