# 040 — «Грузовая / Легковая» на кассе и ключ Optima у филиала

Статус: утверждено (20.11.2026; ответы 1а, 2б, 3а, 4 — «просто фильтр, это для масляных книжек; ползунок — чтобы понятно всем»)

## Зачем
Владелец 20.11.2026: «в филиале Айкос по умолчанию ползунок „грузовая машина“, в Автодом — „легковая“; на кассе для каждого чека отдельно; у грузовой разные фильтры, их много — тоже в чеке должно отображаться». И: «ключ API Optima — именно филиала Айкос».

## Что меняется
### A. Грузовая / Легковая (ADR-205)
1. **Ползунок на кассе** «🚚 Грузовая / 🚗 Легковая» — крупный, виден всем, над позициями чека. Для каждого чека отдельно (1а): новый чек начинается со значения филиала. Значение филиала — настройка «Настройки → Касса» `vehicle_kind_default` (`car` | `truck`); Айкос — `truck`, остальные — `car` (миграция ставит Айкосу `truck` по имени филиала, если такой есть; иначе `car`).
2. **Только отметка** (2б): ничего не прячется, цены не меняются. В чеке (`sales.vehicle_kind`) хранится выбранное; без сети — так же, в очереди.
3. **Чек и масляная книжка** (3а): строка «Грузовая» / «Легковая» в печатном чеке (80 и 58 мм) и в книжке (печать и в книжке клиента), на экране чека. В книжке у грузовой — все фильтры, что поставили, построчно: каждый своим названием товара и со «Следующей заменой» по своему интервалу (как сейчас по категориям; у грузовой фильтров одной категории может быть несколько — каждый отдельной строкой, не сливаются).
4. Отдельной пометки «для грузовых» у товара нет (4): фильтр — просто фильтр.

### B. Ключ Optima у филиала (ADR-206)
5. Ключ филиала — в переменной сервера `OPTIMA_BRANCH_KEYS` (`<id филиала>=<ключ>[,…]`), секрет только в `/etc/avtodom/env`, не в базе. У филиала со своим ключом QR, опрос статуса и сверка с выпиской идут его ключом; у остальных — общим `OPTIMA_API_KEY` (если задан). Ни одного — QR в филиале выключен, как сейчас.
6. «Настройки → Optima» показывает «ключ филиала задан / общий ключ / нет ключа»; ключ на экране не показывается.

## Данные, маршруты
- Миграция 0118: `sales.vehicle_kind text not null default 'car' check (in ('car','truck'))`; настройка кассы `vehicle_kind_default`.
- `POST /sales`, офлайн-очередь, чек и книжка — поле `vehicle_kind`. `GET|PUT` настроек кассы — `vehicle_kind_default`.
- `Config.optima_branch_keys`, `AppState.optima` → по филиалу (`optima_for(branch_id)`), фоновый опрос — по своему клиенту на филиал.

## Проверка
- `server/tests/http.rs` (или свой файл): чек с `truck` — сохранён и в ответе/книжке; без поля — значение филиала; неверное — 422; настройка филиала.
- `web/src/lib/*.test.ts`: строка «Грузовая» в печати чека и книжки; два фильтра одной категории — две строки.
- Optima: юнит-тест разбора `OPTIMA_BRANCH_KEYS`; тест выбора ключа (филиал со своим — свой, без — общий, ни одного — выключено) на подставном банке.
- e2e: ползунок на кассе, новый чек — значение филиала.

## Решено без вопроса
- Ключ — в переменной сервера, а не в базе: секреты только в `/etc/avtodom/env` (как остальные ключи).
- Значение ползунка после проведения чека возвращается к значению филиала.
