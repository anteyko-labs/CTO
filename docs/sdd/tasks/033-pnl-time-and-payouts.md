# Задача 033. «Прибыль и убытки»: уточнение по времени, зарплата — по выплате

Статус: сделано (04.11.2026; ответы 1в, 2а; в main, не выкачено)

## Зачем
Заказчик: «прибыль и убытки — нужно уточнения по времени добавить, и расход не нужно считать сразу, именно по оплате мастерам и т. д., только после того как нажали выплатить».
Сейчас зарплата уменьшает прибыль при начислении (SPEC-08, ADR-023, ADR-157), а выплата прибыль не меняет.

## Что меняется

### 1. Зарплата в прибыли — по выплате
- «Зарплата работникам» = сумма `payouts` периода по `pay_date`, все виды (`general`, `percent`, `service_fee`, `bonus`, `salary`, `advance`), с источником `account` и `outside`; сторно гасит выплату в её дату (уже так, ADR-154).
- Начисление, пока не нажали «Выплатить», чистую прибыль не меняет. Формула прибыли одна (ADR-120): меняются `totals_for`, `totals_between` и «По дням», поэтому числа следуют на сводке, в боте, у помощника и в отчёте смены.
- Дерево: «Зарплата работникам» → работник → выплаты списком (вид, дата, касса, кто выдал) — складываются в сумму; справочно, вне суммы: «Начислено за период» по видам, «Остаток к выплате на сегодня», «Оклад ожидается».
- «Не входит в прибыль»: строка «выдано работникам» убирается (иначе счёт дважды).
- Отчёт смены: строка «Выплачено сотрудникам (без оклада)» — выплаты, проведённые в окне смены (`created_at`), кроме `purpose = salary`; выплаты при закрытии смены входят.
- Подписи: «Зарплата сотрудникам» на сводке и в боте → «Выплачено сотрудникам»; выгрузка: лист «Зарплата» с итогами «Выплачено» и «Начислено (справочно)».
- Предупреждение `salary_not_accrued` («прибыль месяца ещё не полная») при учёте по выплате не показывается; `salary_expected` остаётся справочно.
- Настройка (I21): «Настройки → Отчёт о прибыли» → «Зарплата в прибыли»: «по выплате» (по умолчанию — прямая просьба заказчика) | «по начислению». Ключ `payroll_basis` (`payout` | `accrual`) в `profit_report`, журнал `settings.profit_report`.

### 2. Уточнение по времени
- «С» и «По» — дата и время (без времени — весь день, как сейчас); подпись «С 4 ноября 09:00 по 4 ноября 14:00». Запрос: `GET /reports/profit?from&to&from_time&to_time`, без времени — прежний ответ.
- Что попадает: чеки, расходы, выплаты, движения — по времени проведения (`created_at`, Бишкек). Начисления и оклад, документы задним числом и офлайн-чеки времени в своём дне не имеют — правило в «Решено без вопроса».
- У строк-документов в раскрытии — дата и время проведения; в выгрузке — так же.

## Не входит
- Заработок работника и расчёт: начисления, «Кто сколько заработал», «К выплате», «Мой заработок» не меняются.
- «По работам»: «начислено мастерам» и «валовая за вычетом начислений» остаются по начислению — это разбор услуги, а не прибыль.
- Экран «Расходы» (выплаты и строка «начислен бонус», настройка `expenses_bonus_accruals`) не меняется.
- Переход на учёт по оплате для прочего (поставщики, комиссия, долги).

## Решено без вопроса
- «Оплата мастерам и т. д.» — все виды выплат, включая аванс и оклад: расход появляется при нажатии «Выплатить» / «Выдать аванс».
- День выплаты — `pay_date` (дата, выбранная при выплате, ADR-154), как «Выдано» в итогах.
- Удержания (ADR-065): отдельным плюсом не считаются. Недостача — минус в день смены, а прибыль возвращается, когда выплата выйдет меньше на удержание. Прощение — выплата больше.
- Период с часами: границы по времени проведения; документ задним числом (расход, выплата) — по своей дате и попадает, только если период покрывает этот день целиком; начисления — справочно по дню. Офлайн-чек — по `client_time`, если он в окне доверия.
- Следствие: день выплаты оклада может уйти в минус, а месяц без выплат выглядит прибыльнее; это и есть учёт по выплате, переключается настройкой.

## Вопросы
1. Что значит «уточнение по времени»? а) в периоде можно указать часы; б) только показывать время у каждой строки; в) и то и другое. Рекомендация: в; «б» намного проще, и его хватит, если отбор по часам не нужен.
2. Прошлые месяцы: а) новый учёт для всей истории (числа прошлых месяцев изменятся); б) только с даты включения, раньше — по начислению. Рекомендация: а, данные пока демонстрационные.
