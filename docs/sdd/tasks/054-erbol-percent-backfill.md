# 054 — Процент Эрболу с долговых чеков — задним числом с открытия Айкоса

Статус: утверждено (25.11.2026)

## Зачем
Владелец 25.11.2026: «зп Эрболу без долгов от валовой посчитай уже, беря процент даже от валовой сразу, начиная с того числа, как внедрили систему».
Задача 050 (ADR-214) включила «процент с долга — сразу» только для новых чеков, ждущие оставила (ответ 1б). Теперь владелец меняет ответ: ждущие тоже начислить. По 050 в Айкосе ждали 10 долговых чеков — около 7 949 с (Маметтурдиев Эрбол, 15,5 % и 17,5 %).

## Противоречия
I4: начисление не правится — делаем новые записи начисления, ожидания (`payroll_pending`) закрываем отметкой, ничего не удаляем. Новый ADR-217 уточняет ADR-214 (ответ 1б → 1а для Айкоса).

## Что меняется
1. Разовая операция владельца: «Сотрудники → Эрбол → Оплата → Начислить процент по ждущим долгам» (или кнопка в «Настройки → Касса» Айкоса). Показывает список чеков с открытия филиала: дата, клиент, валовая, ставка, процент — и итог; «Начислить» — одной транзакцией.
2. По каждому ждущему долговому чеку — начисление `revenue_percent` с валовой его долговой части по ставке, что действовала в день чека (15,5 % или 17,5 %), минус баллы как обычно (ADR-065). Ожидание закрывается — погашение долга процент больше не добавит (как в 050).
3. Уже погашенные чеки не трогаются — процент по ним уже начислен; сторнированные и возвращённые — не начисляются.
4. Повтор (`op_id`) — тот же ответ, дубля нет; второй запуск — «нечего начислять».
5. Журнал `payroll.debt_backfill` (кто, сколько чеков, сумма), уведомление владельцу.

## Данные, права
Миграции нет (отметка закрытия ожидания — по полю в `payroll_pending`, если его нет — небольшая миграция). Только владелец, только при связи (I11).

## Не входит
Пересчёт уже сделанных выплат; другие филиалы.

## Затронутые файлы
`server/src/api/payroll.rs:890–1070` (`paid_share`, `insert_debt_pending`), `server/tests/debt_percent_now.rs`, `web/src/pages/` (карточка сотрудника, оплата), `docs/tier-4/spec-07-payroll.md`, ADR-217.

## Проверка
`server/tests/debt_percent_now.rs`:
- [ ] два ждущих чека с разными ставками → начислено по ставке дня чека, ожидания закрыты, погашение потом не добавляет;
- [ ] погашенный и сторнированный чеки не трогаются; баллы вычитаются;
- [ ] повтор `op_id` — без дубля; второй запуск — «нечего»; не владелец — 403; другой филиал не затронут.

## Решено без вопроса
Ставка — та, что была в день чека. Только ждущие (не погашенные) долговые чеки.

## Ответы (25.11.2026)
1б — начисление датой каждого чека: прошлые периоды в отчёте изменятся; уже сделанные выплаты не правятся (I4), разница — к выплате в карточке сотрудника.
2б — всем кассирам Айкоса с ждущими долговыми чеками.
3а — с открытия Айкоса в программе, 14.11.2026.
