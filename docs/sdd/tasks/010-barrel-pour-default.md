# 010 — бочка на кассе: по умолчанию розлив в литрах

Статус: сделано (02.11.2026)

## Зачем
Владелец 02.11.2026: «в кассе масла по дефолту выбирается канистра, а если больше 150 л в канистре — тип бочка, чтоб по дефолту не канистрой измерялось, а литрами»; уточнение: «любой товар с тарой больше 150 л, порог строгий».

## Что меняется
- **Н1 Розлив по умолчанию для бочки.** Касса, добавление товара в чек (поиск, скан, ходовое, аналог): товар в литрах (`unit = 'ml'`) с объёмом тары `container_ml` строго больше порога → строка сразу «Розлив, л», а не «Канистра». Количество пустое, фокус в поле литров (как у продажи на вес), цена — за литр розлива (`listPrice` для `pour`). Тара ≤ порога или объём не задан — как сейчас, «Канистра» × 1.
- Повторный скан того же бочкового товара: если строка розлива уже есть — новая строка не добавляется, фокус в её литры (прибавлять «ещё канистру» к бочке бессмысленно).
- Переключатель «Канистра / Розлив, л» у строки остаётся — можно вручную выбрать тару целиком.
- То же правило — в «Возврат без чека» (`NoReceiptReturn`), где выбор тех же двух видов.
- **Н2 Настройка порога.** «Настройки → Касса»: «Бочка — продавать литрами, если тара больше, л», целое, по умолчанию 150, 0 — правило выключено (всегда канистра). Хранение — `settings` ключ `cashier` (поле `barrel_pour_over_l`), меняет владелец, журнал (I5), op_id (I8); касса без сети берёт из снимка.
- Данные/миграция: нет (поле в JSON настроек, отсутствует → 150). Права, уведомления: без изменений.

## Не входит
- Новые типы тары, пометка «бочка» в карточке товара — определяется только по объёму.
- Приход, ревизия, отчёты — без изменений.
