# 005 — личные входы сотрудников, склад, коды на кассе, смена, бот сотрудника (обратная связь 8)

Статус: утверждено (02.11.2026)

## Зачем
Владелец 02.11.2026: «каждый сотрудник и есть пользователь… у каждого свой логин и пароль; ни один сотрудник кроме владельца не должен видеть стоимость всех товаров в общем — по отдельности может; в кассе если штрих-код не нашёл — … добавить сразу к существующему; чтобы не могли пробивать, если смену не открыли; сотрудники в настройках привязывают ТГ-бот, который выполняет только то, что им в системе доступно». Пункт «владелец правит всё через бот» владелец отложил (02.11).

## Что меняется
- **Н1 Личный вход сотрудника (ADR: отступление от I15, замена ADR-005/066, уточнение ADR-081/152).** Миграция: `users.employee_id` (необязательный, уникальный, тот же филиал). В карточке сотрудника — «Вход в программу»: логин, пароль ≥ 8, вкл/выкл (заводит владелец); вход — роль `admin` со своими правами (`PERMISSIONS`, без новой роли — I13 и бот работают без переделки), набор по умолчанию — как у нового администратора (25 из 33, ответ 2б). Отключили сотрудника — отключён вход, сессии сброшены. «Сменить свой пароль» у каждого (op_id, журнал, сброс прочих сессий). Права кассира смены (ADR-152) урезают только вход без сотрудника (общий `kassa`), личный вход — по своим правам. Кассир, вошедший своим логином, открывает смену на себя без PIN (пароль входа — подтверждение); пробить чек в смене другого кассира нельзя — 409 «Смена открыта на <имя>: закройте её и откройте свою» (владелец и вход без сотрудника — как сейчас). **«Мой заработок»** у каждого входа с сотрудником (мастер, кассир, администратор): сколько заработал, сколько выплачено, сколько ему должны — только своё, без права «Зарплата». В журнале и ленте — «вход (сотрудник)». op_id у `POST/PUT /users`. Проверить блокировку попыток входа по адресу (`*|IP`): ошибки одного кассира не должны закрывать вход остальным на моноблоке.
- **Н2 Общая стоимость склада — только владельцу (ADR: расширение I13, уточнение ADR-125, SPEC-27 §4, SPEC-36 §14).** Сервер не отдаёт не-владельцу `totals.sale_tyiyn` и `category_totals[].sale_tyiyn` (`/products/list`, «Остатки»); экран, печать и «Итого» в Excel — по наличию поля. Количество и число позиций в итогах — всем. Цена и сумма строки товара — как сейчас (ответ 10а). Отчёт «Склад» бота — стоимость только владельцу на уровне функции. В ADR прямо: цены и остатки по товарам видны (и в офлайн-снимке кассы), поэтому сумму можно сложить вручную — скрывается итог, не данные.
- **Н3 Незнакомый код на кассе.** Окно «Код … не найден» уже умеет «Привязать код» (после поиска) — делаем сразу две большие кнопки «Добавить к существующему товару» / «Новый товар», поиск по названию, бренду, артикулу или другому коду; после привязки товар — в чек. 409: код уже у этого товара — успех; у другого — «Этот код уже у «Y»» и Y в чек. op_id и повтор у `POST /products/{id}/barcodes` (I8). Кто привязывает — любой кассир: новое право «Привязывать коды на кассе», группа «Касса»: 33 → 34, по умолчанию включено). Код литра Умага — предупреждение. Без сети — как сейчас (I9). Событие «к товару привязан код» — выключатель в ленте, по умолчанию выключено (I21).
- **Н4 Продажа только при открытой смене (ADR: замена части ADR-021/065).** Онлайн-чек без смены — 409 «Смена не открыта: откройте её на экране «Смена»»; повтор op_id проведённого чека — прежний ответ. Чек без сети без смены проводится, владельцу уведомление «чек без открытой смены» (`sale.offline_bypass`, I9, I10, ADR-062) (ответ 6а). «Исправить» и «Изменить оплату» не ограничиваются; возвраты на карту/QR — как сейчас. Касса: при связи и без смены «Провести чек» → «Открыть смену» (смену перечитать перед блокировкой); плашка «пробить чек нельзя» и в сенсорном режиме. Переключатель «Настройки → Касса», включён (прямая просьба, I21). Запрет и для владельца (ответ 5а).
- **Н6 Бот сотрудника по его правам (доделать H18, затем H17 из worktree `wf_7f12e533-aba-1`, `wf_2c8386f8-a2f-1`).** Любой вход сотрудника: «Мой Телеграм» в профиле — привязать (код/ссылка/QR, 15 мин), отвязать; владельцу уведомление, выключатель «сотрудники привязывают сами» (по умолчанию да). Меню бота — по его правам (ADR-165); вопросы словами — помощник только с инструментами по его правам, без денег владельца, изменения — черновиком с «Провести» (включено у всех со входом, владелец выключает каждому; 50 в день — ответ 9б). Хвосты: при перепривязке чата чистить `bot_dialog` и открытый черновик (I13); проверка настройки после `begin_op` (I8); e2e «Мой Телеграм»; кабинет работника по телефону и вход — один чат: и заработок, и кнопки по правам (ответ 8а); пределы вопросов — по пользователю, не съедают предел владельца. Документация: SPEC-40, SPEC-13 (+1 событие), tier2.
- **Н7 Ревизия несколькими входами (владелец 02.11 03:55: «нас 5 человек, каждый со своим аккаунтом зашёл и провёл ревизию, в конце суммируется: я занёс 6, Алексей 4 — в итоге 10; при ревизии должны товары с Умага предлагать — кто отсканил код, кто название ввёл»).** Ручной ввод в строке ревизии по умолчанию — «+ добавить» (прибавка к общему итогу на сервере), «= итог» — явным выбором; у строки видно, кто сколько добавил. Пять входов одновременно: сканы и ручные прибавки складываются, повтор op_id не удваивает. Поиск по названию/артикулу в ревизии показывает и строки Умага («Из старой базы Умаг» → «Завести» с посчитанным количеством, ADR-114 это допускает), как уже делает скан кода. Проверка: `server/tests/revision_many_logins.rs` (5 входов, 6+4=10, повтор op_id), e2e `revision-many-logins.spec.ts` (два браузера — два входа, ручные прибавки сходятся; название → строка Умага → «Завести»).
- Номера: ADR-167 (Н2, стоимость склада только владельцу), ADR-168 (Н3, привязка кода на кассе, право `till_barcode`), ADR-169 (Н4, продажа только при смене), ADR-170 (Н1, личный вход сотрудника, один чат 8а), ADR-171 (H17, помощник в боте администратора), ADR-172 (H18/Н6, «Мой Телеграм»), ADR-173 (Н7, ревизия несколькими входами); миграции 0092_till_barcode, 0093_employee_logins, 0094_admin_self_telegram; прав 34 (по умолчанию 26), событий 81 (`product.barcode`, `telegram.admin_unlink`); `python3 scripts/registry.py`.

## Не входит
Н5 «владелец правит всё через бот» (отложено 02.11). Бот сотрудника шире пунктов меню и 8 инструментов H17 (приход, цены, клиенты) — следующим этапом. Вход через бот, пароли и PIN через бот — никогда (I19). Смена кассира без сети. Мак 8080 — не выкатывается (рабочий — облако).

## Решено без вопроса
Вход — роль `admin` со своими правами (167 мест различают только «владелец / нет»). Вход заводит и меняет только владелец; общий `kassa` продолжает работать (I21). Скрытие — на сервере (I12). Суммы документов (чек, накладная, приход за период, выручка) — не стоимость склада, остаются. Исключений «видеть сумму склада» нет. Офлайн-очередь не меняется. Через бот сотрудник входа не заводит.
