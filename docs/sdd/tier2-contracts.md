# Tier 2 — контракты (Spec-as-Source)

То, на что опирается любой код и любая задача. Меняется только вместе со спецификацией/ADR.

## Роли и права
- Роли со входом: `owner` (всё, все филиалы), `admin` (только по правам, один филиал). Кассиры и мастера — без входа.
- Права администратора — `PERMISSIONS` в `server/src/auth.rs` и зеркально `web/src/lib/permissions.ts` (ключ, подпись, группа, «по умолчанию» совпадают; тест сверяет). Сейчас 34, по умолчанию 26 (последнее — `till_barcode` «Привязывать коды на кассе», ADR-{n3}); не по умолчанию: `discount`, `oil_transfer`, `payroll_advance`, `old_debts`, `till_pay_fix`, `prices`, `products_archive`, `payroll_view_all`. Группа «Разделы» (`view_*`, `reconciliation`) закрывает и GET отчётов раздела (ADR-151).
- Новое право = миграция (выдача существующим админам, если по умолчанию), запись в оба списка, обход в `server/tests/http.rs`, подписи «N из M» в `web/e2e/admin-permissions.spec.ts`, SPEC-30 §5.
- Отказ: 403 `{"error":{"message":"Нет права: <подпись>"}}`. Право групп «Касса» и «Деньги», снятое у кассира открытой смены, — 403 «Нет права у кассира <имя>: <подпись>» (ADR-152); проверка — `auth::access`.

## HTTP API
- Префикс `/api/v1`, JSON. Ошибки — `{"error":{"message": "..."}}` текстом для человека по-русски.
- Коды: 409 — повтор/конфликт состояния (дубль документа, уже обработано), 422 — неверные данные, 403 — нет права, 401 — нет входа.
- Заголовки: `x-branch-id` (филиал владельца), `x-device-id` (устройство для журнала), `x-total-count` (списки).
- Каждая изменяющая операция несёт `op_id` (UUID v7 с клиента) → идемпотентность (I8).
- Новый маршрут попадает в обход филиалов `server/tests/branches.rs`. Список «Все филиалы» владельца — `?branch=all` (SPEC-33 §3): строки с `branch_id`/`branch_name`, правка — только у строк своего филиала. Задача 003: `POST /debts/old-supplier` — старый долг поставщику (ADR-163; `POST /debts/old` для поставщика — 422); `GET /expenses/all` и `/expenses/all/summary` с `?branch=all` — владельцу все филиалы, строки с `branch_id`/`branch_name`, администратору 404 (ADR-161, ADR-164).

## Данные
- PostgreSQL 16, миграции `server/migrations/NNNN_*.sql` (последняя — 0091). Применённые не правятся; номер — следующий за последним в main.
- Деньги — `*_tyiyn BIGINT`; объёмы — мл; пробег — `mileage_km` + как вписан (`mileage_value`, `mileage_unit`).
- Долги — `party_ledger` (append-only, сторно — `reversal_of`); касса/счета — движения; склад — движения.
- Книжка ТО: `oil_changes` + `oil_change_items` (строка = `slot`, `next_km`/`next_date`); фильтры масляный/воздушный/салонный идут на срок масла (ADR-117); итог чека — только строки этого чека (ADR-111); цель, которую кассир не прислал, ставит сервер — пробег + интервал, `target_auto` (ADR-144).
- Настройки — `settings` (ключ → JSON), меняет только владелец, каждое изменение — в журнал (I5), PUT настроек — с `op_id` (`ops::WithOp`); значение по умолчанию сохраняет прежнее поведение.
- Пересчёт сканом (ревизия и др.) — прибавление на сервере (`mode: add`, `op_id`, миграции 0087–0088), на экране — итог сервера; ручной ввод — итог строки. Клиент не пишет итог своим счётом; очередь сканов общая для вкладок (`navigator.locks`).
- Выгрузка «В Excel» — в браузере без библиотек (`web/src/lib/xlsxWrite.ts`, ADR-159/162): деньги и количества — числами из целых (I1), коды — текстом.
- SQL в Rust — макросы `sqlx::query!`; после правки SQL — `cargo sqlx prepare -- --all-targets` на базе `avtodom_e2e*`, коммит `server/.sqlx`.

## Уведомления владельцу
- `WATCHED` в `server/src/api/notifications.rs` (длина массива = число событий) + текст в `describe`; уходят и в бот владельца. Новое событие — SPEC-13 и выключатель в `server/src/api/bot_feed.rs` (`EVENTS`, тест сверяет); что приходит в бот, каждый владелец выбирает сам, чеки по умолчанию не приходят (ADR-138). Сейчас событий 80; последнее — `product.barcode` «К товару привязан код» (ADR-{n3}), в бот по умолчанию не идёт (`bot_feed::OFF_BY_DEFAULT`: событие, выключенное по умолчанию, добавляется туда и миграцией — в сохранённые настройки).
- Бот администратора (SPEC-40): меню — по его правам (`bot_admin::ITEMS`), лента — только включённое владельцем из `bot_admin::EVENTS` (без денег владельца, свои тексты `bot_admin::event_text`), каждый ответ его чату — через `bot_admin::guard` (I13). Новое событие в ленту администратора — только без прибыли, себестоимости, закупочных сумм и безнала, с текстом в `event_text`.

## Проверки (команда — `scripts/sdd-review.sh`)
- Быстрый набор (каждая задача): сервер — `cargo fmt --check`, `clippy --all-targets -D warnings`, `cargo test`; клиент — `tsc -b`, `oxlint src`, `npm test`, `vite build`.
- Полный e2e (Playwright, ~6 мин, своя база `avtodom_e2e*`, свой порт, env как в `.github/workflows/ci.yml`) — только перед выкатом.
