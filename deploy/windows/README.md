# Установка Avtodom на точке (Windows)

Два устройства: **компьютер-сервер** (i5, Windows) хранит базу и программу, **моноблок кассы** открывает кассу в браузере по сети магазина. Владелец из дома заходит через Tailscale. Решение — ADR-057.

Время на месте: около часа. Нужны: доступ к роутеру магазина, пароль от Google-аккаунта для копий, телефон владельца.

## 0. Подготовка (заранее)

1. Скачать пакет: GitHub → репозиторий → Actions → «Windows package» → последний успешный запуск → архив **avtodom-windows**.
2. Скачать установщики: PostgreSQL 16 для Windows (enterprisedb.com), Google Drive для компьютера, Tailscale для Windows и для телефона.

## 1. Компьютер-сервер

1. **Адрес в сети.** В роутере закрепить за компьютером постоянный адрес (резерв DHCP), например `192.168.1.10`.
2. **Питание.** В «Электропитании» отключить сон и гибернацию. В BIOS — «включаться после пропадания питания» (если есть).
3. **PostgreSQL 16.** Установить с настройками по умолчанию, порт 5432; придуманный пароль пользователя `postgres` записать.
4. **Google Drive.** Установить «Google Диск для компьютера» и войти (папку копий подключим после установки, шаг 9).
5. **Пакет.** Распаковать архив в любую папку, например `C:\Avtodom-установка`.
6. **Настройки.** Скопировать `config.example.ps1` → `config.ps1` и заполнить: пароли (латиницей, цифрами и знаками, без русских букв, пробелов, кавычки `"` и обратной косой `\`, от 10 символов), адрес сервера, ключ Телеграм-бота. Скрипт проверит пароли и остановится с понятной ошибкой.
7. **Установка.** PowerShell **от имени администратора**:
   ```
   cd C:\Avtodom-установка
   powershell -ExecutionPolicy Bypass -File install.ps1
   ```
   Скрипт ставит программу в `C:\Avtodom` (доступ только системе и администраторам — там пароли), создаёт базу, автозапуск сервера и HTTPS, ночную копию базы, правило брандмауэра для сети магазина и кладёт сертификат для моноблока в `C:\Avtodom-сертификат`. Любая ошибка останавливает установку с объяснением.
8. **Проверка.** В браузере на сервере открыть `http://127.0.0.1:8080` — экран входа. Войти логином и паролем владельца из `config.ps1` и **сразу сменить пароль** («Пользователи»).
9. **Копии в облако.** Google Диск → Настройки → «Мой компьютер» → «Добавить папку» → `C:\Avtodom\backups` → «Синхронизировать с Google Диском». Утром после установки проверить, что файл `avtodom-ДАТА.dump` появился в Google Диске («Компьютеры»).

## 2. Моноблок кассы

1. С сервера скопировать папку `C:\Avtodom-сертификат` (там `root.crt` и `install-cert.ps1`) на флешку.
2. На моноблоке из этой папки запустить PowerShell от имени администратора:
   ```
   powershell -ExecutionPolicy Bypass -File install-cert.ps1
   ```
3. Открыть Chrome: `https://192.168.1.10` (адрес сервера) — замка с ошибкой быть не должно.
4. Меню Chrome → «Установить приложение» (Avtodom): касса откроется отдельным окном, ярлык — в автозагрузку.
5. Войти администратором. Подключить сканер (работает как клавиатура) и принтеры: чековый 80 мм и этикеток 30 × 20 мм. Напечатать пробный чек и этикетку (Настройки → Этикетки).
6. **Проверка без интернета:** выдернуть кабель интернета из роутера (сеть магазина остаётся) — касса продаёт. Выключить сервер — касса всё равно продаёт, чеки уйдут, когда сервер вернётся.

## 3. Доступ владельца из дома (Tailscale)

1. На сервере установить Tailscale и войти (один аккаунт владельца). В панели Tailscale (login.tailscale.com → DNS) включить **MagicDNS** и **HTTPS Certificates** — без этого адрес `https://…ts.net` не заработает.
2. PowerShell от имени администратора на сервере:
   ```
   tailscale serve --bg --https=8443 http://127.0.0.1:8080
   tailscale serve status
   ```
   Команда покажет адрес вида `https://avtodom-pc.хвост.ts.net:8443`.
3. На телефоне владельца установить Tailscale, войти тем же аккаунтом, открыть этот адрес и «Добавить на главный экран».

## 4. Телеграм-бот

Ключ уже в `config.ps1`. Владелец: «Настройки → Телеграм и баллы → Получить код», отправить боту `/start КОД`. Клиенты подключаются по QR из масляной книжки.

Вопросы боту обычным текстом («сколько заработали за неделю», «кто больше всех должен») включаются ключом сервиса разбора вопросов: вписать его в `$AssistantApiKey` в `config.ps1` и перезапустить сервер (см. SPEC-21). Пусто — функция выключена, кнопки работают. Расход вопросов виден в «Настройки → Телеграм и баллы». Тот же ключ включает «Заполнить по фото» в «Новом приходе» и приём фото накладных в боте (SPEC-30 §9), даже если бот не настроен.


### Optima Business: QR на сумму и сверка с банком

Ключ API банка создаёт первый подписант в Optima Business (категории: генерация QR, статус QR-платежа, список точек и касс, выписка по POS и QR). Вписать его в `$OptimaApiKey` в `config.ps1` и перезапустить сервер (`OPTIMA_API_KEY`; адрес банка по умолчанию — `https://api.optimabusiness.kg`, другой — `$OptimaApiUrl` → `OPTIMA_API_URL`). Затем владелец: «Настройки → Optima Business» — ID компании, расчётный счёт (16 цифр), «Загрузить точки и кассы», выбрать точку и кассу, «Проверить связь». На кассе при оплате «Карта / QR банка» появится «QR на сумму»; сервер сам спрашивает банк об оплате каждые 2 с, а в 06:00 сверяет выписку за три прошедших дня (SPEC-31). Серверу нужен выход в интернет; без связи или без ключа касса работает как раньше — оплату картой отмечают вручную.

### Сообщения клиентам: WhatsApp Business Platform

Клиентам, подключённым к боту, напоминания о замене масла и сообщения фирмам о закупе уходят в Телеграм; остальным, у кого в карточке есть телефон, — в WhatsApp через официальный WhatsApp Business Platform (Cloud API Meta, ADR-107). Сообщения, которые начинает программа, Meta пропускает только по одобренным шаблонам; оплата за сообщения — по тарифу Meta с карты заказчика.

1. **Аккаунт Meta.** На business.facebook.com — бизнес-портфолио Avtodom (подтвердить компанию документами — иначе лимит 250 сообщений в сутки). На developers.facebook.com — «Создать приложение» → тип «Бизнес» → добавить продукт **WhatsApp**.
2. **Номер.** WhatsApp Manager → «Номера телефонов» → добавить номер точки (он не должен быть в обычном WhatsApp или WhatsApp Business на телефоне — сначала удалить там аккаунт), подтвердить кодом из SMS, задать отображаемое имя «Avtodom». Скопировать **ID номера телефона** (Phone number ID) — это `$WhatsAppPhoneId`.
3. **Постоянный ключ.** Настройки компании → «Пользователи» → «Системные пользователи» → добавить (роль «Администратор»), назначить ему приложение и аккаунт WhatsApp, «Создать токен» без срока с разрешениями `whatsapp_business_messaging` и `whatsapp_business_management` — это `$WhatsAppToken`. Временный ключ со страницы «Начало работы» живёт сутки — для точки не годится.
4. **Оплата.** WhatsApp Manager → «Оплата» — привязать карту.
5. **Шаблоны.** WhatsApp Manager → «Шаблоны сообщений» → «Создать»: категория «Служебные» (Utility), язык «Русский» (`ru`), тип «Переменные: число». Два шаблона — текст и переменные по порядку показаны на экране «Настройки → Сообщения клиентам», там же примеры значений:
   - «замена масла», например `avtodom_oil_change`: `{{1}}` имя клиента, `{{2}}` что менять, `{{3}}` машина (марка, модель, госномер), `{{4}}` пробег и остальное, `{{5}}` ссылка на бот;
   - «закуп юрлица», например `avtodom_purchase`: `{{1}}` имя и фирма, `{{2}}` когда и что («Сегодня был закуп»), `{{3}}` сумма, `{{4}}` водитель, `{{5}}` машина, `{{6}}` общий долг, `{{7}}` ссылка на кабинет или на бот.
   Одобрение обычно занимает от минут до суток.
6. Вписать `$WhatsAppToken`, `$WhatsAppPhoneId` и (если программа доступна из интернета) `$PublicUrl` в `config.ps1`, перезапустить сервер. Другая версия Graph API — `$WhatsAppApiUrl` (по умолчанию `https://graph.facebook.com/v26.0`).
7. Владелец: «Настройки → Сообщения клиентам» — имена одобренных шаблонов и язык, «Сохранить», «Отправить пробное» себе (своя карточка клиента с телефоном). Журнал на том же экране: что ушло, куда, и причина ошибки от Meta.

## 5. Товары и запуск

1. Владелец: «Ревизия и товары» → «Сканер товаров» → «загрузить Excel» — выгрузка «Список товаров» из старой программы.
2. Включить «Пересчёт (ревизия)», сканировать полку подряд: товары заводятся и сразу считаются.
3. Владелец проводит ревизию («Ревизия» → открыть → «Провести») — остатки встали.
4. Счета («Деньги» → «Счета»): завести «Личный счёт владельца» (безналичный, комиссия 0 %) и отметить его «по умолчанию для перевода» — QR владельцу пойдёт туда без комиссии; у «Счёта» поставить ставку банка (карта и официальный QR банка).
5. Завести сотрудников (кассир с PIN, мастера), услуги, проверить ставки оплаты и плитки «ходовое» на кассе.
6. Открыть смену с разменом — работаем.

## 6. Несколько филиалов: общий сервер (SPEC-33, ADR-108)

Все филиалы работают с **одним** сервером и одной базой: товары, клиенты, услуги и поставщики общие, а склад, деньги, смены, сотрудники и документы — у каждого филиала свои. Второй сервер на втором филиале не ставится.

1. **Где стоит сервер.** Либо компьютер главной точки (установка — как в разделах 1–4) с хорошим интернетом и бесперебойным питанием, либо сервер в облаке (тогда установка и копии — отдельным разделом при переезде, ADR-108). Если сервер выключен или у главной точки пропал интернет, филиалы продают без сети и отправят чеки позже (SPEC-09), но отчёты, приход и выплаты в это время недоступны.
2. **Внешний адрес по HTTPS.** Филиалы подключаются к серверу через интернет. Подходит один из вариантов:
   - **Tailscale на каждом моноблоке филиала** (как у владельца, раздел 3): адрес `https://…ts.net:8443`, наружу ничего не открывается. Самый простой и закрытый вариант.
   - **Свой домен** (например `avtodom.kg`): в роутере главной точки пробросить порты 80 и 443 на сервер, в `C:\Avtodom\Caddyfile` добавить блок `avtodom.kg { encode gzip; reverse_proxy 127.0.0.1:8080 }` — Caddy сам получит сертификат Let's Encrypt.
   - **Cloudflare Tunnel** на сервере (без проброса портов): в `config.ps1` — `$TrustCfHeader = $true` (`TRUST_CF_HEADER=1`), чтобы предел попыток входа видел настоящий адрес.
   Внешний адрес вписать в `$PublicUrl` (`PUBLIC_URL`) — им же пользуются ссылки на кабинет юрлица.
3. **Филиал в программе.** Владелец: «Настройки → Филиалы → Новый филиал» (название, адрес, телефон). Филиал сразу получает свои «Кассу», «Счёт» и сейфы, статьи расходов и копию настроек главного филиала; номера чеков — с первого.
4. **Люди филиала.** В шапке выбрать «Филиал: …» нового филиала, затем: «Пользователи» — администратор филиала (он видит только свой филиал), «Сотрудники» — кассиры с PIN и мастера, «Счета» — ставка банка у «Счёта», «Настройки → Optima Business» — точка и касса банка этого филиала.
5. **Моноблок филиала.** Chrome → внешний адрес (шаг 2) → «Установить приложение» → войти администратором филиала. Сканер и принтеры — как в разделе 2.
6. **Владелец.** Переключатель «Филиал: …» в шапке (на телефоне — в меню «Ещё»): действия — в выбранном филиале, в отчётах — «Все филиалы» с суммой и разбивкой. В боте — `/филиал` (выбрать филиал отчётов или «все»). Закрыть филиал — «Настройки → Филиалы»: история остаётся, продажи и документы в нём больше не проводятся.

## Обслуживание

- **Копии:** каждую ночь в 02:30 в `C:\Avtodom\backups` (`avtodom-ДАТА.dump`), в облако их уносит Google Диск (шаг 1.9); если Google Диск не работает, копии всё равно делаются и остаются на компьютере. Копия считается годной, только если `pg_restore --list` читает файл и в нём есть данные таблицы продаж; неудачная попытка не затирает удачную копию того же дня. Хранение: 7 последних годных ночных — за каждый день, затем по одной на неделю (4 недели) и на месяц (3 месяца); копии перед обновлением и восстановлением (`…-before-update-ЧЧММ.dump`, `…-before-restore-ЧЧММ.dump`) — 30 дней, две последние — всегда. В копиях лежат и фото накладных: если все копии вместе больше 10 ГБ, владельцу приходит уведомление «Копии базы занимают много места». Если копия не удалась, старые не удаляются.
- **Ошибка копии:** причина пишется в `C:\Avtodom\logs\backup.log` (строка «ОШИБКА: копия не создана — …») и в журнал действий сервера событием `backup.failed` с причиной — владелец видит его в «Уведомлениях» и в Телеграме (текст для `backup.failed` задаёт сервер). Если не работает сама база, событие записать нельзя — остаётся только `backup.log`. Ручная копия: `powershell -ExecutionPolicy Bypass -File C:\Avtodom\backup.ps1`.
- **Восстановление** (PowerShell от имени администратора):
  ```
  powershell -ExecutionPolicy Bypass -File C:\Avtodom\restore.ps1 -Dump 'C:\Avtodom\backups\avtodom-ДАТА.dump'
  ```
  Скрипт проверит файл, покажет его имя, дату и размер и попросит ввести `ВОССТАНОВИТЬ`. Затем остановит сервер и сделает копию текущей базы `avtodom-ДАТА-before-restore-ЧЧММ.dump` — не получилось, восстановление отменяется, база не тронута. Базу скрипт пересоздаёт и восстанавливает копию в чистую: так встаёт и копия, сделанная прежней версией программы, — новая версия при запуске сама доведёт базу до своей. Если `pg_restore` завершился с ошибкой, сервер **не запускается**, а скрипт печатает команду, которой вернуть базу из этой копии. Копию из облака сначала скачать с Google Диска («Компьютеры») в `C:\Avtodom\backups`.
- **Проверка восстановления раз в месяц** (5 минут, рабочую базу и кассу не трогает). PowerShell от имени администратора, взять последнюю ночную копию:
  ```
  powershell -ExecutionPolicy Bypass -File C:\Avtodom\restore.ps1 -Dump 'C:\Avtodom\backups\avtodom-ДАТА.dump' -Check
  ```
  Скрипт создаёт отдельную базу `avtodom_check` (`createdb`), восстанавливает в неё копию (`pg_restore -d avtodom_check`), показывает число чеков и время последнего, затем удаляет базу (`dropdb`). Должно быть «Проверка пройдена», а последний чек — вечер дня копии. Раз в квартал так же проверить файл, скачанный из Google Диска. «ПРОВЕРКА НЕ ПРОШЛА» — проверить копию на день раньше и сообщить разработчику.
- **Обновление:** скачать и распаковать новый пакет, в его папке от имени администратора: `powershell -ExecutionPolicy Bypass -File update.ps1`. Скрипт проверит права администратора, сделает свою копию базы `avtodom-ДАТА-before-update-ЧЧММ.dump` (ночная копия её не перезапишет, хранится 90 дней), остановит сервер, сохранит прежнюю программу в `C:\Avtodom\previous`, заменит файлы, запустит и подождёт до 5 минут, пока сервер обновит базу и ответит. Касса подхватит новую версию сама: на экране кассы с пустым чеком обновится, на остальных экранах покажет плашку «Обновить».
- **Откат обновления:** `powershell -ExecutionPolicy Bypass -File C:\Avtodom\rollback.ps1`. Скрипт покажет, какая версия и какая копия базы вернутся, попросит ввести `ОТКАТ`, вернёт прежнюю программу из `C:\Avtodom\previous` и восстановит базу из копии перед обновлением (всё, что внесено после обновления, пропадёт; копия текущей базы и новая программа в `C:\Avtodom\previous-new` сохраняются). Прежняя программа на базе новой версии не запускается — поэтому откат всегда вместе с базой.
- **Журналы:** `C:\Avtodom\logs\server.log`, `caddy.log`.
